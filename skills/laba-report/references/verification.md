# 検証（書き終えてから、渡す前に必ず）

## 1. 引用の再照合

台帳の全行について URL を開き直し、書誌（著者・題名・誌名・巻号・頁・年）を本文と参考文献の両方と突き合わせる。「」の中身は原文と文字単位で比較する（判決文は漢数字・読点の字形まで）。頁数の食い違いは `scripts/ledger_check.js`。V1・V2 のまま本文に中身を書いていないか。

## 2. 数値・計算

本文の数値（期間の日数・倍率・割合・金額の差）はコードで再計算する。図の数値と本文の数値をそろえる。専門家の段は根拠の時点（法令の施行日・統計の年・版）と確認日を再確認。

## 3. 別エージェントによる査読（本文を見ていない担当・読むだけ）

完成稿と台帳を渡し、重さの順に場所つきで列挙させる。直さない担当にする。指摘は全部直すか、直さない理由を利用者に伝える。

| 段 | 回数 | 観点 |
|---|---|---|
| 高校生 | 1 | 根拠のない主張・AI らしい言い回し |
| 学部生 | 1 | 根拠のない主張・原文と違う引用・矛盾・最も強い反論・AI らしい言い回し |
| 大学院生 | 2 | 引用検証役（台帳の全行と「」）と反対役（最も強い反論・射程の外・残る問題）を別々に |
| 専門家 | 2 ＋ 数値・日付・法令の時点の再確認 | 同上＋感度 |
| 論文 | 3 | 引用・反対・文体（査読者の目：寄与の明示・限界・投稿規定との照合） |
| 学会 | 3 ＋ スライド全ページを画像にして点検 ＋ 想定問答の確認 | 同上 |

## 4. 文体の機械チェック

`node ${CLAUDE_PLUGIN_ROOT}/skills/laba-report/scripts/prose_check.js --level 〔段〕 本文.txt`（台帳が別なら `--ledger`）。日本語は型（意見文・発表レジュメ・論文）で数値が変わり、英語は段で変わる（`levels.md`）。所見は「直す候補」で、どの文が・何字で・分ける候補はどこか、から始め、書き直しは利用者が選ぶ。error が 0 になるまで。warn は残す理由を書けるなら残す。

図：`python3 ${CLAUDE_PLUGIN_ROOT}/skills/laba-report/scripts/fig_check.py 図.svg --width-mm 156 --caption "図 1 …"`。禁止要素（角丸・影・グラデーション・凡例だけの色分け・色の文字・4 色以上）が 0、文字 8 pt 以上、線 0.35〜1.0 pt、灰と強調の明度差 20 以上。v2.1：記号だけのラベル（F23）・枠の有無の不揃い（F24）・流れを示す図に矢印が無い（F25。`--kind process`）・関係の種類の混在（AR-L5）・図題に読み方の文が無い／断片（AR-N2・N3）。

## 5. 使ってはいけない使い方

機械の点検は、このスキルが**自分の下書きを直すため**のもの。人の書いた文章を「AI が書いた」と判定する道具に使わない（検出器は英語を母語としない書き手を誤判定しやすい。印の多くは人の一流の文にもある。閾値は分布の裾に置いたので 1 つだけで直させない）。指摘の文に「AI らしい」と書かず、「文長が揃っている」「文末に分詞句」のように文の性質を書く。

## 6. 最終チェック

- 未確認の印（【要確認】【未確認】TODO）と作業の注記（本文約○字・記憶に基づく・提出前に確認）が残っていないか。
- **本文に作業の告白が無いか（v2.1）**：検索先（J-STAGE・リポジトリ）・検索語・検索月・「全文を確認できなかった」「参照できなかった」「〜の整理を通じてしか把握しておらず」「書誌のみ確認」は本文と注から外し、台帳と報告に移す（`work-confession`）。限界の節は論の射程だけか。参考文献に V2（書誌だけ見た）の文献が無いか（`references-v2`）。無料で読める一次資料を孫引きしていないか（台帳の「孫引き」の欄を見て、原典が無料なら読んで直す）。
- **要入手の重要文献（v2.1）**：台帳の【要入手】が残っていれば、論文・学会の段では報告の**冒頭**に「要入手の重要文献が残っている（〇件：…）」と警告を出す。本文には書かない。主要な文献の注が引く無料の文献をたどったか（`citation-ledger.md` §3 (b)）。
- 章番号と相互参照（「15(1)参照」）が合っているか。図番号が連番で本文から参照されているか。引用形式が文書の中でそろっているか。図題が完全な文（何を示すか＋読み方＋出典）か（`figure-caption-reading`・`-fragment`）。
- 利用者が手を入れた段落（太字・下線・です・ます）を壊していないか。
- Word は validate を通し、soffice→pdftoppm で全ページを画像化して見る（語の途中の改行・はみ出し・見出しの書式）。スライドも全ページ。
- 渡し方：成果物と台帳（別ファイルかチャット）。報告は短く：（論文・学会の段は冒頭に**要入手の重要文献の警告**）、何を書いたか 1 文、**V1・V2 にとどまった文献と、利用者の資料から写した頁数の一覧**、作業の記録（検索先・検索語・検索月・読めなかった資料・孫引きの有無。本文には書かない）、図書館で確かめるべき資料名、仮置きの日付。修正依頼は言われた箇所だけ直し、版番号を上げ、前版のファイルを残す。
