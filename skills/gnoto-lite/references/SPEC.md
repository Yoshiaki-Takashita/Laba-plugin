# GNOTO Lite 仕様書（調査段階）

作成：2026-11-13。GNOTO（`GLYPH.html`）は読むだけで、書き換えていない。この文書は、`.gnoto` ファイルの形式とブロック・スライドの模型を調べた結果と、法律モードを「Claude の中だけ」で再現する設計をまとめたもの。GNOTO のコードは写していない（保護規則 c）。

根拠の凡例：**［実測］**＝ヘッドレス Chromium で GNOTO を動かして確かめた。**［コード］**＝`GLYPH.html` の関数を読んだ（行番号は変わるので関数名で示す）。**［資料］**＝`HANDOVER.md`・コネクタの `laba-integration.md` と `schemas/tools.v1.json`。**［不明］**＝確かめられていない。

---

## 0. 全体の方針（保護規則の設計への落とし込み）

GNOTO の法律モードは、本体アプリでは有料プランの機能。Lite の法律モードは Claude の中でだけ動き、外に持ち出せる法律モードにはしない。

| 規則 | 設計 |
|---|---|
| (a) スクリプトに法の知識を入れない | `scripts/` は「ノートファイルの読み書き・検証・静的な表示」だけ。条文データ、略称表、判例表、引用の解析は持たない |
| (b) 法律の動作は SKILL.md の手順 | 「条文番号→展開」「判例→要旨」は、Claude がコネクタのツールを呼び、返った原文を普通のブロックと出典で書く手順として書く |
| (c) GNOTO のコードと表を写さない | 読んだのは `.gnoto` の形式とブロック・スライドの模型だけ。本体の法令データ・略称表・判例表は、プラグインへ入れない。この文書にも、その中身・名前・置き場所・仕組みは書かない |
| (d) 表示に法律の対話機能を入れない | HTML プレビューはノートを静的に表示するだけ（候補の出る入力欄・Enter での展開・ホバーの条文ポップアップは作らない） |
| (e) 別ライセンス | `skills/gnoto-lite/LICENSE`（草案）。Claude の中でこのプラグインの一部として使う場合だけ許し、Claude の外でノート・法律モードの機能を提供するための取り出し・移植・再利用を禁じる |

注意（正直な限界）：公開プラグインは中身が読める形で出す必要があるため、**技術的に複製を防ぐことはできない**。防ぐのは「設計（法律の知識をクライアント側に持たない。条文・判例はサーバー側のコネクタが持つ）」と「ライセンス」の二つ。ノートを書く部分（形式の読み書き）は、誰が写しても法律モードにはならない。

## 1. `.gnoto` ファイル形式

### 1.1 入れ物（コンテナ）

［コード］`_gnotoExportObj`・`exportNoteGnoto`・`importGnotoFile`・`openImportedGnoto`。［実測］書き出し→読み込みの往復を実行した。

- 拡張子 `.gnoto`（旧 `.glyph` も読む。コード中のコメントに「.glyph で入出力」とあるのは古い）。**1 ファイル＝1 ノート**。ほかに入れ物の種類はない。
- 中身は **UTF-8 の JSON 1 つ**（アプリの書き出しは `JSON.stringify` のままで、インデントなし）。デスクトップ版は先頭の BOM（U+FEFF）を外して読む。
- ファイル名は `<タイトル>.gnoto`。`\ / : * ? " < > |` は `_` に置き換える。

```text
{
  "glyph": "note",            必須。この値でなければ「対応していないファイルです」で拒否される
  "version": 1,               書き出しは 1。読み込み側は値を見ない
  "exportedAt": 1794551524492,  ミリ秒。読み込み側は使わない
  "app": "GNOTO",             同上
  "card": null,               ノートのカード情報（null か object）。中身は［不明］。Lite は null
  "note": {                   必須（無いと拒否）
    "title": "…",             一覧に出る題（500 字まで）
    "style": "normal",        "normal" または "slide"（Lite の対象）。^[a-z0-9_-]{1,24}$ 以外は "normal" になる
    "n": 1,                   「第 n 回」の数。整数。無ければ 0
    "content": { … },         1.2 節
    "books": [],              教科書の紐付け。{id,name,color,img} の配列。Lite は []
    "pen": []                 手書きの線。Lite は []
  }
}
```

読み込み側（`openImportedGnoto`）の動き［コード・実測］：

1. `glyph !== "note"` か `note` が無ければ拒否（［実測］`{"glyph":"nope","note":{}}` は拒否）。`version`・`app`・`exportedAt` が無くても読める（［実測］`version` 無しで開けた）。
2. `content` を `_sanNoteContent` で**一律に無害化**してから新しいノートにする。`content` が無ければ題だけの空ノート。
3. ノートは必ず「インポート」というジャンルに**新規追加**される（ファイルにジャンル名は入らない。既存ノートの上書きはしない）。同じファイルを 2 回読むと 2 つできる。
4. 教科書（`books`）は名前一致で既存に紐付け、無ければ作る。

### 1.2 `content`（ノートの中身）

［実測］アプリが書いた実物（`tests/fixtures/` の 3 ファイル）から。

| キー | 型 | 内容 |
|---|---|---|
| `title` | string | 題。`note.title` と同じにする |
| `rows` | array | ノートの本文（行の配列）。1.3 節。**normal のとき本体**。slide のときは `[[{"html":""}]]` を入れておく |
| `body` | string | `rows` から作った HTML の写し（互換・書き出し用）。`rows` が無いときだけ、これから `rows` を作り直す。表・画像は欠ける（`<div></div>` や空）。Lite は `rows` を正とし、`body` は簡易な写しを付ける |
| `scroll` | number | 開いていた位置。0 |
| `updated` | number | ミリ秒 |
| `cCue`・`cSum` | string | コーネル式用。空文字でよい |
| `slides`・`cur` | array・int | slide のとき。2 章 |
| `textboxes` | array | 白紙の上に置く自由なテキスト・画像の枠。Lite は書かない（読んだものは変えずに残す） |
| `tags` 等 | | ほかのキーは JSON の複製でそのまま残る。知らないキーは消さない |

### 1.3 行（`rows[]`）とブロックの種類

行（row）は次の 4 形のどれか。［コード］`serializeBlocks`・`serializeRowEl`・`_sanitizeRowsDeep`。

| 行の形 | 例 | 意味 |
|---|---|---|
| ブロックの配列 | `[{"html":"本文"}]` | 普通の行。ほとんどは長さ 1 |
| 2 列 | `{"cols":[[B…],[B…]],"ratio":[1,1]}` | 左右の列。読み込みは 4 列まで通す（画面で作れるのは 2 列）。`ratio` は正の数 2 つ |
| 囲み | `{"callout":true,"tone":"key","rows":[行…]}` | 色つきの箱。入れ子にできる（深さ 64 まで）。`tone` は `key`（青）・`warn`（赤）・`example`（緑）・`review`（紫）・無指定（黄）。［コード］CSS の `data-tone` |
| 折りたたみ | `{"toggle":true,"open":false,"title":"題","rows":[行…]}` | `title` は**読み込み時に文字列として扱われる**（`<` `&` はそのまま見える）ので、記号を含めず素の文字で書く |

ブロック（block）の種類と欄。［実測］は往復で欄が保たれたことを確認したもの。

| ブロック | 欄 | 備考 |
|---|---|---|
| 文章 | `html`（必須）、`htype`（`"1"`〜`"3"` の文字列。見出し）、`list`（`"ul"`・`"ol"`）、`indent`（`"1"`・`"2"`。文字列）、`done`（1。チェック済み）、`callout`（1。囲みの見た目の行）、`md`（1）＋`src`（MD ブロック） | 見出しの大きさ：h1 26px/太字、h2 21px/太字、h3 17px/中太・青（#185FA5）。番号つき（`ol`）の数字は表示のときに自動で振られる（保存はしない）。［実測］ |
| 区切り線 | `{"hr":true}` | |
| 表 | `{"table":{"head":["項目","内容"],"rows":[["甲","ア"]]}}` | セルは HTML。列は 50 まで・行は 2000 まで。行の列数は `head` に合わせて切り詰め・空で埋める |
| コード | `{"code":{"lang":"python","src":"…"}}` | アプリは `out`・`imgs`（実行結果）も書くが、読み込みは `lang`・`src` だけ残す。**Lite は実行しない** |
| 画像 | `{"img":{"src":"…","wPct":40}}` | `src` は `https://` か `data:image/(png|jpeg|gif|webp|bmp);base64,…` だけ通る。`wPct` は 15〜100 |
| 目次 | `{"toc":true}` | |
| 埋め込み | `{"embed":{"url":"https://…","kind":""}}` | https だけ |
| 構造式・物理・漢文 | `struct`・`phys`・`kanbun` | 理系・漢文のスタジオのブロック。Lite は**書かない**。ただし既存ファイルに入っていたら、編集しても**変えずに残す** |
| ノート参照・埋め込み・コレクション | `noteref`・`noteembed`・`collection` | 読み込みで**空の文章に置き換わる**（外から来たノートでは意味を持たない）。Lite は書かない |
| 知らない形 | | 読み込みで `{"html":""}` になる（［実測］`{"weird":true}` は空行になった） |

### 1.4 文章の `html` に入れられるもの（読み込みの無害化）

［コード］`glyphSanitizeHtml`・`_SAN_OK`・`_sanStyle`。［実測］`<script>`・`onclick`・`display:flex`・`letter-spacing` を入れたファイルを読み込み、前の二つと後の二つが落ちたのを確認。

- 使えるタグ：`a abbr b blockquote br caption code col colgroup dd div dl dt em font h1-h6 hr i img li mark ol p pre q s small span strike strong sub sup table tbody td tfoot th thead tr u ul wbr`。`script style iframe form button input(checkbox以外) svg math …` は中身ごと消える。知らないタグは、タグだけ外して中身を残す。
- 属性：`href`（http・https・mailto・tel・`/`・`#` だけ。`rel` と `target` は付け直される）、`src`（img だけ・画像の規則は 1.3）、`style`（下記）、`class`（英数字・空白・`-`・`_`）、`colspan`・`rowspan`、`align valign alt title width height dir lang color face start`。`on*` はすべて消える。`data-*` は `data-ph`・`data-nid`・`data-ct` の 3 つだけ残る。
- `style` で通る性質：`color`・`background-color`・`background`・`text-align`・`font-weight`・`font-style`・`text-decoration`・`font-size`・`font-family`・`line-height`・`margin`・`margin-left`・`margin-right`・`padding`・`padding-left`・`list-style-type`・`white-space`・`vertical-align`・`border`・`border-bottom`・`border-left`・`width`・`max-width`・`opacity`。値に `url(`・`var(`・`expression`・`<` `>` `\` を含むものは落ちる。**`display`・`height`・`justify-content`・`align-items`・`border-radius`・`letter-spacing` は落ちる**。
- 1 つの `html` あたりの要素数に上限（4 万ノード）がある。
- **隠し印は読み込みで欠ける**：GNOTO は条文・判例を引用するとき `<span class="cite-mark" data-ct="law" data-cl="民法" data-ca="709" data-cn="2"></span>` という見えない印を付けるが、読み込みで `data-ct` 以外が落ちる（［実測］`data-ct="law"` だけ残った）。Lite は出典を**見える文字**で書く（3.3 節）。印は使わない。

### 1.5 Lite の書き手が守ること

1. `glyph:"note"`・`version:1`・`app:"GNOTO"`・`note.{title,style,n,content,books,pen}` を必ず書く。UTF-8・BOM なし。
2. `style` は `normal` か `slide` だけ。
3. `rows` は 1 行以上。空なら `[[{"html":""}]]`。
4. `html` は 1.4 の許可に収まるものだけを書く（書いた物が GNOTO で読み込まれても欠けないため。同時に静的プレビューの安全にもなる）。HTML の特殊文字は文字として入れる必要があるとき `&amp; &lt; &gt;` に直す。
5. `indent`・`htype` は**文字列**（`"1"`）。数にしない。
6. 読んで書き直すとき、知らないキーとブロックは**そのまま残す**。
7. `body` は `rows` の簡易な HTML の写しを付ける（無くても読めるが、あるほうが互換が高い）。
8. 画像は利用者が渡したものだけ。ネットから取らない。

［実測の範囲］書いたファイルを GNOTO に読み込ませて、行数・題・スタイル・スライド枚数が合うことを確認する試験（`tests/`）を用意する（実行結果はこのあとの段階で報告）。この段階の実測は、アプリが書いた 3 ノートの書き出し→読み込みと、手で書いた最小ファイル 4 通り（正常 2・`version` 無し・拒否 1）。

## 2. ノーマルとスライド

### 2.1 ノーマル（`style:"normal"`）

［コード・実測］

- 縦に流れる 1 本の文書。上に題（26px）、その下に「第 n 回」・タグ・文字数、本文は**ブロックの縦並び**。本文の左右余白は約 40px、行間 1.5。
- ブロックは `rows` の行を上から順に並べたもの。ブロックの左のキューブでドラッグ移動・メニュー（Lite では不要）。2 列は行の中の左右の列。囲み・折りたたみは箱で、中に行を入れ子にできる。
- 画面の「スタイル」は文章ブロックの `htype`・`list`・`indent` の組み合わせ（見出し 1〜3・箇条書き・番号・引用・コード・コールアウト）。引用・コードの見た目（`blk-quote-style` など）は**保存されず**、再び開くと普通の文章になる［コード：`serializeBlk` は `html` と `list/htype/indent/done/callout` だけを書く］。したがって引用は `blockquote` タグか囲みで書く。
- 描画は HTML の `html` をそのまま使う（編集は contenteditable）。

### 2.2 スライド（`style:"slide"`）

［コード・実測］`ensureSlides`・`slideElsHTML`・`addSlideTpl`・`SLIDE_TEMPLATES`・`_sanNoteContent`。

**模型**

```text
content.slides = [ Slide, … ]   最大 500 枚
content.cur    = 開いている枚数の番号（0 始まり）
Slide = { id, els:[Element…], trans?, note? }
Element（文字）= { id, type:"text", x, y, w, h, z, html, lh?, ls?, anim? }
Element（画像）= { id, type:"image", x, y, w, h, z, src, anim? }
```

- 1 枚は **16:9 の面**。要素の位置と大きさ `x y w h` は**面に対する百分率**（0〜100 が面の中。読み込みで x・y は −100〜200、w・h は 0〜300 に丸められる）。`z` は重なり順。1 枚あたり要素 500 まで。
- 面は `container-type:size` で、文字の大きさは **`cqh`**（面の高さの 1%）で書く。既定の本文は 4.4cqh、題は 6.5〜9cqh、副題は 3.8〜4.4cqh。文字の色の既定は #1a1a1a。要素の中は余白 `0.5cqh 0.7cqw`・はみ出しは隠れる（`overflow:hidden`）ので、**要素の高さに収まる量**に抑える。
- `lh`（行間・数）・`ls`（字間・px）は要素の欄。HTML の `style` に `letter-spacing` を書いても読み込みで落ちる（1.4 節）。
- 中央寄せ・縦中央は、`display:flex` が落ちるため使えない。**水平は `text-align:center`、縦は `y`・`h` で位置を決める**（見本のとおり）。
- `anim`：`{ "t":"none|fade|flyL|flyR|flyU|flyD|zoom|rotate", "d":遅れ秒, "dur":秒 }`。`trans`（スライドの切り替え）：`none|morph|fade|pushL|pushR|up|wipe|zoom|flip`。
- `note`：発表者ノートの文字列（GNOTO の AI の書き出しが付ける。画面で編集する欄があるかは［不明］）。`bg`（背景色）は読み込みの無害化にはあるが、描画で使われるかは［不明］なので Lite は使わない。
- レイアウトの型（GNOTO が持つ）：白紙・タイトル・タイトル＋本文・セクション見出し・2 カラム・箇条書き・比較・引用・画像＋説明・締め。**Lite は型を表として持たず**、同じ考え方で `x y w h` を書く（上の寸法の目安：題 `8,7,84,14`、本文 `8,26,84,66`、2 カラム `8,26,42,66` と `50,26,42,66`）。
- スライドの `rows` は使われない（`[[{"html":""}]]`）。

**表示と書き出し**［コード］：左にサムネイルの一覧、中央に面。スライドショー（全画面・矢印で送る・切り替えとアニメーション）、PDF（297×167mm の横長）、PowerPoint（.pptx）に書き出せる。Lite の HTML プレビューは、面の描画（16:9・`cqh`・要素の `%` 配置）と一覧だけ。アニメーション・切り替えは**表示しない**（保存は保つ）。.pptx・.pdf は Claude 側の別のスキルに任せ、Lite では作らない。

## 3. 法律モード：GNOTO の機能と Lite での再現

GNOTO の法律モードは `studyMode==='law'` のとき働く［コード・資料］。次の表は、機能ごとに「GNOTO の動き」「Lite（Claude とコネクタ）」「データが e-Gov・裁判所から取れるために変わること」を書く。コネクタの入出力は `laba-jp-connector/schemas/tools.v1.json` が正。

### 3.0 前提（コネクタの範囲）［資料］

- 条文：e-Gov 法令 API v2。法令（法律・政令・省令など）。**収録は 2017-04-01 以降の版**。附則・別表は対象外。`asof`（日付）でその日に施行されていた版が取れる。
- 判例：裁判所ウェブサイトの裁判例検索。**最高裁**で、**サイトに載っているものだけ**。大審院・下級審・判例時報などだけに載る裁判例は `not_covered`（存在しないという意味ではない）。
- その他：国会会議録（発言だけ）、NDL サーチの書誌、表記の抜き出し（上流へは問い合わせない）、状態確認。
- 呼び出し：1 回最長 45 秒、上流ごとに間隔（裁判所 2 秒・e-Gov 0.5 秒…）、全体で 1 分 30 回・1 日 1,000 回まで。
- 「全部の条文・全部の判例」と**言ってはいけない**。言えるのは「e-Gov が配信している法令」と「裁判所のサイトが公開している判例」。公開されていない裁判例は存在しても取れない。

### 3.2 コネクタが無いとき

ツール一覧に `law_get_article` と `case_verify_citation` があればコネクタの手順。無ければ Claude のウェブ取得で e-Gov 法令検索・裁判所の裁判例検索のページを読む（`laba` スキルの手順を使う）。確かめられなかったものは**【未確認】**と書く。コネクタの URL・鍵は、プラグインにもノートにも**入れない**（各自が Claude の設定にだけ入れる）。

### 3.3 条文・判例ブロックの書き方（Lite の取り決め）

GNOTO の引用ブロックと同じ「見出し行＋本文の文章ブロック」の形で、出典を**見える文**で足す（隠し印は使わない）。見本は `tests/fixtures/law-blocks-sample.gnoto`。

条文：

1. 見出し（`htype:"3"`）：`{law_title} {article_label}（{caption}）`。`caption` が無ければ括弧を付けない。
2. 項が 2 つ以上なら各項を別ブロックにし、頭に丸数字（①②…）と全角空白。1 項だけなら丸数字なし。号は `indent:"1"` のブロック。
3. 出典行（灰色 `color:#8a929b;font-size:13px` の `span`）：`出典：e-Gov法令API v2／法令ID …／施行日 YYYY-MM-DD／取得 YYYY-MM-DD（law_get_article）`。`asof` を使ったときはその日付も。

判例：

1. 見出し（`htype:"3"`）：`{裁判所}{判決・決定} {年月日}（{事件名}）` と、あれば巻号頁。
2. 本文は「裁判要旨：…」「判示事項：…」「参照法条：…」。要旨は裁判所の文のまま。
3. 出典行：`出典：裁判所ウェブサイト 裁判例検索／case_id …／取得 YYYY-MM-DD（case_get）。裁判要旨は裁判所の編集で、判決の文ではない。`
4. 判旨を「」で引くなら `case_quote_check` が `fulltext` で `exact` のものだけ。

未確認：`<span style="color:#c0392b">【未確認】</span>` を先頭に付け、理由（収録の外・上流の失敗・取得せず）を書く。「存在しない」とは書かない。

## 5. 食い違い・注意・不明

### 5.1 形式についての注意

- 本体の書き出し処理の近くのコメントは「.glyph」と書くが、拡張子は `.gnoto`（旧 `.glyph` も読める）。
- 本体は別の作業で編集が続くため、関数名・挙動は変わりうる。形式が変わったら `tests/app_roundtrip.js` で確かめ直す。
- 本体の内部（法律モードの仕組み・データの置き場所）についての開発用の記録は、このプラグインには置かない（所有者の手元の記録にある）。

### 5.2 注意（挙動の癖）

- 読み込みは**常に新しいノートを「インポート」ジャンルに作る**。更新は上書きにならず、新規になる。Lite の「編集」は、ファイルを書き換えて、利用者が GNOTO で開き直すと別ノートになる。
- 折りたたみの `title` は、アプリの書き出しは HTML（`innerHTML`）、読み込みは文字列として扱う。`&` を含む題は往復で `&amp;` が重なって見える。題に記号を入れない。
- 読み込みで落ちる `style`（1.4 節）と、画面で保存されない引用・コードの見た目（2.1 節）は、Lite の書き方の制約になる。

### 5.3 不明

- `card` の中身（ノートのカード情報）と、`GnotoHub.inherit` が `data` から何を読むか。
- スライドの `note`（発表者ノート）・`bg`（背景）の画面での扱い。
- 数式（`data-tex`）の正確な記法と、読み込みでの扱い。
- Claude のプランごと（無料・Pro・Team など）に、Skills・プラグイン・コネクタ・コードの実行がどこまで使えるか（claude.ai と Claude Code）。確かめていない。
- 各ストア（Claude のプラグイン一覧）の掲載審査の結果。
