# GNOTO Lite

GNOTO（法学生向けのノートアプリ）のノートを、Claude が書く。ファイルは `.gnoto`（1 ファイル＝1 ノート）で、本物の GNOTO にそのまま読み込める（読み込むと「インポート」ジャンルに新しいノートができる。上書きはされない）。

**ライセンス**：このフォルダ（skills/gnoto-lite）は `LICENSE`（別の条件）に従う。Claude の中でこのプラグインの一部として使う場合だけ許される。Claude の外へ取り出して、ノートや法律モードの機能に使うことはできない。

## いつ使うか

- 「GNOTO でノートにして」「ノートを作って」「スライドにして（GNOTO の）」「この .gnoto を直して」「プレビューを見せて」。
- 「民法709条をノートに入れて」「この判例（最判○年○月○日）を入れて」「この判旨の引用が正しいか確かめて入れて」。
- laba で作った内容（講義ノート・判例研究）を GNOTO のノートとして欲しいと言われたとき（下の「laba との使い分け」）。
- 使わない：Word・PowerPoint のファイルだけが欲しいとき（laba・laba-slides）。レポート・論文（別の手順）。

## できること・やらないこと

- ノートの種類は **normal（縦に流れる本文）と slide（16:9 のスライド）だけ**。ほかの種類・スタジオ・手書き・コード実行はしない。
- 法律モード：条文・判例・「」の引用・国会会議録・文献の書誌を、**コネクタ（laba-jp-connector）のツールを呼んで取り、出典つきの普通のブロックとして書く**。スクリプトは法律を知らない。条文のデータ・略称・判例の表はどこにも入っていない。
- 「全部の条文・全部の判例」とは言わない。言えるのは「e-Gov が配信している法令」「裁判所のサイトが公開している最高裁の判例」まで。大審院・下級審・判例誌だけの裁判例は取れない（存在しないという意味ではない）。条文は 2017-04-01 以降の版だけ。

## 道具

`python3 ${CLAUDE_PLUGIN_ROOT}/skills/gnoto-lite/scripts/gnoto.py <命令> FILE.gnoto …`（Python 3 の標準ライブラリだけ。`--help` で全命令）。1 手ごとに「読む→1 か所直す→検査→書く」。誤りがあれば書かない。行・スライドの番号は 1 始まり。

| 目的 | 命令 |
|---|---|
| 作る・題や style を直す | `new`・`set` |
| 中身を見る | `info`（行の一覧）・`text`（素の文）・`check`（誤りと注意）・`search`（複数ノートの文字列検索） |
| ノーマルに足す | `heading`・`add-text`・`add-list`・`add-checks`・`add-table`・`add-quote`・`add-code`・`add-hr`・`add-toc`・`add-figure`・`add-callout`・`add-toggle`・`add-cols`・`add-json`（`--at N` で位置） |
| ノーマルを直す | `delete`・`move`・`replace` |
| スライド | `slide-add`（`--layout` blank・title・title-body・section・two-col）・`slide-move`・`slide-dup`・`slide-del`・`slide-set`（切り替え・発表者ノート）・`el-text`・`el-image`・`el-set`・`el-del` |
| 見る | `render --html out.html`（静的プレビュー。スライドは 1 画面 1 枚・矢印キーで送る・O で一覧）・`render --png out.png --slide N`（ブラウザがあるときだけ） |
| Word に出す | `docx out.docx`（ノーマルだけ。LABA の build_docx.py と python-docx が要る）。.pptx は作らない（スライドの .pptx は laba-slides） |
| 法律 | `law-args`・`law-statute`・`law-case`・`law-quote`・`law-unverified`（下の手順） |

使い方の流れ：新規は `new` → 足す命令を順に → `check` → `render --html`（または `--png`）で**自分の目で見る**。直すときは `info` で行番号を確かめてから。出力のファイルは利用者の作業フォルダに置く。

## 渡し方（プレビューと .gnoto）

1. `render --html 作業フォルダ/ノート名.html` で静的プレビューを作り、**自分で見て**（スライドは `--png` があれば画像も）から渡す。プレビューは表示だけで、入力や法律の補助はない。
2. claude.ai では、そのプレビュー HTML をアーティファクトとして出すか、ファイルとして渡す。Claude Code では作業フォルダのパスを伝える。
3. 本体の渡し物は `.gnoto` ファイル。「GNOTO のノート一覧の読み込みで開くと、『インポート』ジャンルに新しいノートができる（上書きされない）」と一言添える。GNOTO を持たない人には、プレビュー HTML と（ノーマルなら）Word で足りる。

## laba との使い分け

- laba（本体）は Word の講義ノートが標準の出力。利用者が「GNOTO のノートで」と言ったとき、または GNOTO を使っていると分かるときは、**出力先を GNOTO Lite にできる**。Word と GNOTO の両方も可。
- 手順：laba の規則（網羅・文体・引用台帳・独立点検）で内容を作る → 確定した本文を gnoto.py の命令で .gnoto に書く（見出し・文・表・図・引用）。条文・判例は、laba が確かめたものを、下の法律モードの手順で出典つきで入れ直す（確認済みと未確認の区別を落とさない）。GNOTO 化のために内容を作り直したり、点検を省いたりしない。
- スライドは、GNOTO のスライド（.gnoto）が欲しいときだけここ。PowerPoint は laba-slides。

## 書き方の規則（GNOTO が読み込みで欠けさせないため。詳細は references/SPEC.md）

- 文は素の文字で渡す（記号は自動でエスケープされる。`**太字**` だけ太字になる）。HTML を渡す `--html` は、GNOTO が通す範囲（SPEC 1.4）に収まるものだけ。収まらなければ拒否される。
- 画像は利用者が渡したファイルだけ（`add-figure --image`）。ネットから取らない。`--url`（https の画像）は利用者が URL を指定したときだけ使い、プレビューや GNOTO で開くとその画像をブラウザが読み込むと伝える。
- スライドの寸法は面に対する %（x y w h）。文字は `cqh`（面の高さの 1%）。中央寄せは `--align center` と `--y`・`--h` で作る（`display:flex` は読み込みで落ちる）。1 枚に詰め込みすぎない。`check` の「箱に収まらない可能性」は直す。`slide-add --body` は 1 行ごとに「・」の箇条書きになる。条文・判旨のように 1 つの文を折り返して渡すときは `--no-bullets` を付ける。
- 条文・判旨を**短くして載せるとき**（スライドに収めるためなど）は、原文のままと読める書き方をしない。見出しか文末に「（抄）」を付け、省いた所は「……」で示す。出典の行は、元の条（項・号）を指す。原文のまま載せるときだけ「（抄）」を付けない。
- 折りたたみの題に `<` `>` `&` を入れない。
- 引用の見た目（`add-quote`）は blockquote で書く。出典・注記は見える文字で書く（隠し印は使わない）。
- 既存の .gnoto を直すとき、知らない欄・ブロックは残される（消さない）。
- 利用者が GNOTO で開き直すと**別の新しいノート**になる。直した版を渡すときはそう伝える。

## 法律モード（Claude の手順）

利用者が「民法709条を入れて」「最判○年○月○日を入れて」のように頼んだら、次の順に行う。**条文の文言・略称の解釈・判例の要旨を、自分の記憶で補わない**。コネクタか公式サイトから取ったものだけを書く。

### 0. 道具の確認
ツール一覧に `law_get_article`・`case_verify_citation` などがあればコネクタを使う（最初に `health`）。無ければ、Claude のウェブ取得で e-Gov 法令検索と裁判所の裁判例検索の頁を読む（laba スキルの手順）。コネクタの URL・鍵はこのプラグインにもノートにも書かない（各自が自分の Claude の設定にだけ入れる。CONNECTORS.md）。コネクタが無い人も、下の代替で使える。呼び出しは 1 分 30 回・1 日 1,000 回まで。

**コネクタが無いとき（代替）**：ウェブ取得で e-Gov 法令検索の該当条の頁・裁判所の裁判例検索の詳細頁を読み、読めた文だけを `add-quote`・`add-text` で書く。出典（URL・取得日）を見える文字で添え、読めなかったものは `law-unverified` で【未確認】にする。この場合、`law-statute`・`law-case` の整形（コネクタの返答の形）は使えない。判旨の「」引用は、判決全文を読んで一字一句確かめたものだけ。

### 1. 条文を入れる
1. `law_resolve_citation`（`text`、必要なら `default_law`。法令名の無い条は直前の法令を受け継ぐので、複数の条を並べて渡すときは法令名を省かない）。返った JSON をファイルに**そのまま**保存し、`gnoto.py law-args FILE.json` に通す。`ambiguous`・`unresolved` は拒否され候補が出る → 利用者の文に法令名があれば、法令名を明示して `law_resolve_citation` を呼び直す。なければ**利用者に聞く**（勝手に選ばない）。`confidence: search` は法令名と条番号を目で確かめる。
2. `law_get_article`（`law`・`article`・`paragraph`・`item`、事件当時の条文なら `asof`）。返った JSON を保存し、`gnoto.py law-statute NOTE.gnoto --json 返答.json [--asof 日付] [--paragraph N] [--item M] [--at N]`。項・号を指定して取ったときは、**同じ値を `--paragraph`・`--item` に渡す**（見出しに「第N項」と出て、条の一部だと分かる。渡さないと第1項だけが条の全体に見える）。見出し・各項（2 項以上なら①②…）・号・出典の行（法令 ID・版・施行日・取得日）が普通のブロックで入り、出典の記録が `gnotoLite.sources` に残る。
3. `status` が `no_match`・`not_covered`・`upstream_error` なら拒否される。**書かずに**、`law-unverified --reason …` で【未確認】と理由（収録の外・上流の失敗・取得せず）を書く。「存在しない」とは書かない。2017-04-01 より前の版は取れない。
4. 範囲（「7〜19条」）は 1 条ずつ呼ぶ。8 件を超えるときは先に件数と待ち時間を伝えて確認する。取れなかった条は飛ばしたことを報告する。
5. 法令名から探すときは `law_search`。略称一覧を自分の記憶で作らない。

### 2. 判例を入れる
1. 日付が分かるとき `case_search_by_date`（`date`・`court: supreme`・`case_name_contains`）。`multiple` なら事件名で 1 件に絞る（勝手に選ばない）。表記（巻号頁）があるとき `case_verify_citation`。
2. `case_get`（`case_id`）を保存し、`gnoto.py law-case NOTE.gnoto --json case_get.json [--verify verify.json]`。書誌＋判示事項＋裁判要旨＋参照法条＋出典。**要旨は裁判所の編集で判決の文ではない**と明記される。`--verify` を付けると（照合結果の case_id がこの判例と違えば拒否）、書誌の全項目が一致したときだけ「照合済み」と書かれ、`mismatch`・`unknown` は項目名つきで「確認済みとは書かない」になる。
3. `not_covered`（大審院・下級審など）・`no_match` は【未確認】（「このコネクタでは確認できない」）。

### 3. 「」の引用
`case_quote_check`（`case_id`・`quote`、判旨として引くなら `scope: "fulltext"`）→ 保存 → `gnoto.py law-quote NOTE.gnoto --json 返答.json --quote "引用文" --cite "判例の表記"`。一致（exact・normalized）だけ書かれ、normalized は返された原文の表記で引く。`not_found` と、一致が要旨・判示事項にとどまる場合は拒否される（要旨として引くなら `--summary-ok` で「裁判要旨（判決の文ではない）」と明記される）。判決全文は作業用で、ノートに丸ごと貼らない（`case_get_fulltext` の `find` で必要な段落だけ読む）。

### 4. そのほか
- 立法趣旨：`diet_search_speeches`（発言だけ）。文献：`biblio_search`（書誌だけ。本文は読めない）。表記の抜き出し：`citation_parse`（実在は確かめない）。取った結果は、出典（取得日・ツール名・URL）を見える文字で添えて普通のブロックに書く。
- 百選の番号と事件の対応は取れない → 【未確認】。利用者が事件名・日付を言えば 2 の手順。
- 後で改正されても、ノートの条文は自動で変わらない。出典の版・取得日を見る。

## 報告の書き方

- 何を作った・直したか（ファイル名・行数やスライド枚数）、`check` の結果、プレビューを見て確かめたこと。
- 法律モード：呼んだツール、【未確認】にしたもの、取れなかったもの、拒否されたもの。
- 走らせなかった検査（PNG のブラウザが無い、Word の python-docx が無い、など）とその理由。分からないことは「不明」と書く。
