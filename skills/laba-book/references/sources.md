# P3 資料台帳：資料なしの題で、主張の根拠を台帳に持つ（`ledger.tsv`）

資料なしの題（`word`・`field`）では、本文の主張の根拠は**自分で確かめた出典だけ**にする。土台は reportkiller の `citation-ledger.md`（V0〜V3）。教科書は本文に出典を出さないので、**台帳は紙面に出さず、本文の下書きの印と報告にだけ残す**。

## 1. 規則（破ると誤りに直結する）

1. **台帳の ID の無い主張を書かない**。主張＝本の外で確かめられる事実：定義（「〜を〜と呼ぶ」）・数・年・人名・地名・機関・条文・判例・法則や因果の説明・分類の仕方・歴史の出来事。下書き（`work/ch<n>/s<k>.md`）では、主張の文の句点の直前に `[R01]`（2 つなら `[R01,R03]`）を付ける。言い換え・前の文のまとめ・問い・自作の事例（`:::box` の A・B）・要点（`:::point`）には付けない。
2. **V0（記憶のみ）は台帳に載せない**。読んでいない出典は、存在しそうでも書かない。
3. 本文の根拠に使えるのは **V3（原文を読んだ）と V1（二次資料の要約を読んだ・使い方に【二次】）だけ**。V2（書誌だけ見た）は中身の根拠にしない（章立ての【構成】には使ってよい）。
   - **V3 は原文の写しがあるときだけ**：頁を `curl -sL -o work/sources/raw/R03.html "<URL>"` で取り、`source_text.py work/sources/raw/R03.html --out work/sources/R03.txt` で字を取り出した写し（`work/sources/<ID>.txt`）があるもの。**WebFetch は頁を要約して返すことがあるので、WebFetch だけで読んだ出典は V1【二次】**にする。
   - **Wikipedia・Wikibooks・コトバンク・weblio などの事典のまとめは根拠にしない**。使い方を【手がかり】にして台帳に残してよいが、本文と根拠の表では引かない（`ledger`・`claims`・`facts` が誤りにする）。そこに挙がった元の出典（法令・公的機関・学会・論文・大学の講義資料）を開き、その行で書く。
4. **見つからない＝存在しない、ではない**。検索で出ない・開けない・コネクタが `no_match`・`not_covered`・つながっていない、のどれも「無い」とは書かない。台帳の「未確認」の行（下の 2）に、探した先と結果を書き、**その主張は本文に書かない**（書くなら確かめてから）。
5. 「」の引用と頁は V3 だけ（教科書の本文では、原則として「」の引用をしない）。
6. 作業の記録（検索語・探した先・読めなかった理由）は台帳と報告に書き、本文に書かない。

## 2. 台帳の形（`work/ledger.tsv`。1 出典 1 行。`citation-ledger.md` 2 と同じ列）

```
ID | 完全な書誌 | 確認に使った URL | V0〜V3 | 使い方の印
R01 | 〇〇大学「国際経済学」シラバス 2025 年度 | https://... | V3 | 【構成】【ウェブ】
R03 | 〇〇学会『用語集』「機会費用」の項 | https://... | V3 | 【一次】【学会】【ウェブ】
R07 | 民法 第166条（e-Gov 法令検索・2025-04-01 時点） | https://laws.e-gov.go.jp/... | V3 | 【一次】【法令】【コネクタ】
R09 | 〇〇大学「国際経済学」第3回講義資料（PDF） | https://... | V3 | 【二次】【講義】【ウェブ】
R10 | ウィキペディア「比較優位」 | https://ja.wikipedia.org/... | V1 | 【手がかり】【ウェブ】
# 未確認（本文で使わない。V を付けない）
U01 | 民法 第724条の2 | 探した先：コネクタ（つながっていない）・e-Gov（開けない） | 未確認 | 次の手：コネクタのある環境で law_get_article
```
- 出典の種類の印（根拠の「種類の違う出典」を数える。1 行に 1 つ）：【法令】【判例】【公的】（省庁・自治体・独立行政法人・国の図書館・文書館）【統計】【規格】【学会】（学会・業界団体の解説・用語集）【査読】（論文・紀要）【講義】（大学の講義資料・公開講座・シラバスの本文）【教科書】（出版社の公開見本・目次の頁）【事典】（署名つきの項目だけ）。印が無ければ道具が URL から推す（`.go.jp`＝公的・`.ac.jp`＝講義 など）。
- 使い方の印：中身の種類＝【一次】（原典：法令・判決・規格・公的統計・原著論文）・【二次】（V1 のとき必須）・【査読】・【構成】（章立てだけ）／確かめ方＝【コネクタ】（laba-jp-connector で確かめた）・【ウェブ】（自分で開いて読んだ）・【利用者資料】（利用者が渡した）。
- 未確認の行は ID を `U` で始め、4 列目に「未確認」と書く（`ledger_check.js` は V の無い行を数えないので、台帳の要求の計算に入らない）。
- URL は検索結果からたどったものだけ。

## 2b. 根拠の確認：段落の設計の主張ごとに根拠を当てる（P3b・`work/ch<n>/facts.tsv`）

これまでの外れ方［測：段 L2・L4・L5］：1 節に引いた出典が 1 つだけの節・事典のまとめを根拠にした節（L2・L4）。L5 で「節ごとに事実 12 以上を集める」目標を入れると、出典の質は上がったが、集めた事実を本文に詰め込み、盲検の採点で読みやすさ・順序・忠実さが下がった（段落に論点が混ざる・題から外れる・細部が多い）。**事実を集めること自体を目標にしない。構成（`outline.json` の段落の設計 `paras`）を先に決め、その段落が言う主張に根拠を当てる**。

1. **順序**：P2 で節の問い（`question`）と段落の設計（`paras`：1 段落 1 論点・前提 → 定義 → 要件 → 例 → 例外）を先に書く（`outline.md` 3）。この表は、その段落の主張ごとに「どの出典のどの文が支えるか」を確かめる表である。段落の設計に無い事実は、読んで見つけても表に入れない。
2. **目標（節ごと。`targets.json` の `depth`）**：中身の出典 **3 以上**・出典の種類 **2 以上**（例：【公的】＋【講義】＋【学会】）・1 つの出典に寄るのは **5 割まで**。事実の数の目標は無い（主張の数は段落の設計で決まる）。章立ての確認先（【構成】）は数えない。
3. **探し方**：`scope.md` 2 の「中身の確認先」の列から、種類の違う先を選ぶ。定義と要件の主張は、2 つの出典で言い方が合うかを見る（食い違えば、より一次に近い方で書き、他方は使わない）。事典のまとめ（Wikipedia 類）は、元の出典をたどる手がかりにだけ使う。1 つ開けなかったら次の先へ（開けない先は未確認の行）。
4. **読み方**：取った頁は `source_text.py` で写しにし、`--grep <術語>` で該当の所を読む。主張の文の言い方（何を何と呼ぶか・条件・例外）は、**抜き書きの言い方から外れない**ようにする（出典にない言い換え・強め・一般化をしない）。
5. **表の形**（1 主張 1 行。節の欄は `s1` か、段落まで書くなら `s1.p3`＝`paras` の 3 つ目）：
   ```
   ID | 節 | 台帳 | 主張（段落で言うこと。自分の語で短く） | 抜き書き（原文のまま 10〜80 字）
   F01 | s1.p2 | R03 | 換気温度は作物ごとに違う | 換気温度は作物の種類によって異なり
   ```
   抜き書きは写し（`work/sources/<ID>.txt`）にあるとおりに写す（道具が照らす）。WebFetch だけで読んだ V1 の行は、返ってきた文のまま写す（照らせないので注意が出る）。
6. **検査**：`python3 ${CLAUDE_PLUGIN_ROOT}/skills/laba-book/scripts/book_state.py facts work/ch<n>/facts.tsv --ledger work/ledger.tsv`。誤り 0、かつ節ごとに「根拠の目標を満たす」（出典・種類・寄り）になるまで読む。**読みに行くのは最大 2 巡**。2 巡で届かなければ、そのまま書き、報告の冒頭に「根拠不足：出典 n・種類 n」と書く（本文で「資料に無い」と断らない）。根拠の取れない段落は、段落の設計から外す（別の主張で埋めない）。
7. 本文の主張の文は、表の行（の台帳の ID）だけで書く。表に無い事実を本文で足さない。表の行を全部使う義務はない。

## 3. 法学の章（条文・判例）

- **コネクタがあれば先に使う**（`skills/laba/references/connector.md` の使い分け・状態の読み方）。条文は `law_get_article`（法令名を付けて 1 件ずつ・`asof`）、判例は `case_verify_citation` と `case_get`。確かめた行の印は【コネクタ】、URL は返事の `provenance.source_urls`。
- コネクタが無い（ツール一覧に `law_get_article` が無い）ときは、e-Gov 法令検索・裁判所の判例検索を自分で開いて読む（印は【ウェブ】）。それもできない環境では、その条文・判例を**未確認の行**にし、本文では条番号・判例を出さずに書けることだけを書く（書けなければ書かない）。報告の冒頭に「コネクタなし・未確認 n 件」と書く。
- `no_match` は「存在しない」ではない（入力の誤りをまず疑う）。`not_covered` は「このコネクタでは確認できない」。
- 判例の理由を本文に出すときは、laba の担当 `verifier` と `reason_table.py` の理由の出所の規則に従う。

## 4. 検査（本文を渡す前に必ず）

```
python3 ${CLAUDE_PLUGIN_ROOT}/skills/laba-book/scripts/book_state.py ledger work/ledger.tsv
python3 ${CLAUDE_PLUGIN_ROOT}/skills/laba-book/scripts/book_state.py facts work/ch<n>/facts.tsv --ledger work/ledger.tsv
python3 ${CLAUDE_PLUGIN_ROOT}/skills/laba-book/scripts/book_state.py claims work/ch<n>/s<k>.md --ledger work/ledger.tsv
```
- `ledger`：V0 の行・ID の重複・URL の無い行・確かめ方の印の無い行・未確認の行の数・出典の種類の印・事典のまとめを【手がかり】にしているか・V3【ウェブ】の行の原文の写し（`work/sources/` があるとき）。
- `facts`：根拠の表の台帳の ID・抜き書きが写しにあるか・節ごとの根拠（出典・種類・寄り。段落ごとの行の数）。
- `claims` は、本文で引いた出典の数・種類・1 つの出典への寄りも注意で出す（根拠の目標と同じ値）。
- `claims`：台帳に無い ID・未確認（U）や V2 の行を根拠にした文・**ID の無い主張の候補**（数・年・条番号・「」・定義の文〔「〜と呼ぶ」「〜という」〕・人名らしい語のある文で、印の無いもの）。候補は機械の下限の数で、印の無い主張をすべて拾えるわけではない。候補が出たら、出典を確かめて印を付けるか、その主張を消す。
- `gate`（本文の数の検査）は `[R01]` の印を外してから測る。紙面（laba-textbook）へ渡すときは `claims --strip` で印を外した本文を書き出す。
- 段ごとの文献の数の要求を見るときは、reportkiller の `ledger_check.js 本文 --ledger work/ledger.tsv --level ug` も使える（教科書は段の要求の対象外。参考として報告に書く）。
