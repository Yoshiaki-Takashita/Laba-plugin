# 節の執筆の指示（P4。担当 `textbook-writer` と、担当を立てない環境の両方で使う）

1 つの節を、教科書の文で書く。**数の目標を書く前に頭に入れ、書いたら道具で測って直す。**
数の元は reportkiller `references/textbook-prose.md` §1（教科書 5 冊・122 ページの形の測定）。この表はその写しで、機械の検査は `scripts/targets.json`（同じ値。試験が一致を確かめる）。

## 1. 数の目標（段 `ug`・`grad`。`hs` は括弧）

| 項目 | 目標 | よくある外れ方 |
|---|---|---|
| 文の長さ | **中央値 55〜68 字**（hs 45〜55）・p90 125 字以下 | 30〜40 字の文を並べる（これまでの試走の外れ方。中央値 31〜37 字） |
| 長短の混ぜ方 | 40 字以下の文を 15〜30%・81 字以上を 25〜35%。変動係数 0.45 以上 | 長さがそろう |
| 読点 | 1 文に 1.8〜3.5 | 長い文で読点が無い |
| 段落 | 150〜260 字・2〜5 文。1 文だけの段落は節に 1 つまで | 1〜2 文の段落の連続 |
| 段落の頭 | 接続語（また・さらに・しかし…）で始める段落は 4 つに 1 つまで。使うなら逆接を多く | 「また」「さらに」で始め続ける |
| 文末 | 「である。」は 3 割まで。「と呼ぶ・といえる・とされる・ことになる・必要がある」などを混ぜる。です・ますにしない | 全部「である。」 |
| 太字 | 定義する用語の名前だけ。1 段落に 0〜2 語・9 字以下・1,000 字に 3〜6 | 文の一部・強調したい語を太字 |
| 見出し | 節 8 字前後（20 まで）・項 5 字前後（8 まで）・名詞止め | 「〜について」「〜の仕組みとは」 |
| 事例の枠 | 3 文以内・約 120 字・人物は A・B・事実だけ（結論・評価は本文へ） | 枠の中で結論まで書く |
| 補足の枠 | 1〜2 文・75〜120 字・接続語で始めない | 本文の続きを補足に入れる |
| 問い | 20 文に 1 つほど。問いの直後 1〜2 文で答える | 問いの連発・答えない問い |

## 2. 長い文の作り方（中央値を 55〜68 字にする）

短い文を 2 つ並べる代わりに、**関係の語でつなぐ**。内容を足して長くしない。
- 条件と帰結：「〜の場合には、〜となる。」「〜とき、〜ため、〜。」
- 理由を中に入れる：「〜ので、〜する必要がある。」「〜から、〜とされる。」
- 定義の 3 歩：場面か条件を 1〜2 文 →「このような〜を、**〜**と呼ぶ。」→ 名前だけ太字。
- 対比を 1 文に：「Aは〜であるのに対し、Bは〜である。」
- そのうえで、要点を言い切る短い文（20〜40 字）を 4〜5 文に 1 つ置く。

自作の例（数：61 字・59 字・16 字）：「温室の室温が換気温度を超えると、天窓が自動で開いて外の空気を取り入れ、室温を作物に合った範囲まで下げる仕組みになっている。開く幅はいつも同じではなく、室温が換気温度をどれだけ上回ったかに応じて段階的に大きくなるため、急な暑さにも対応できる。この開く幅のことを、**開度**と呼ぶ。」

## 3. 手順

1. 受け取った節（`outline.json` の自分の `id`）の題・項・用語・`facts`・図の候補を読む。資料はその節の分だけ。
2. `outline.md` 4 の形で書く（役割の印つき Markdown）。字数は節の `chars`（目安 1,200〜1,600 字）。**資料にない事実・数・人名・年を足さない**。資料で足りない所は、言い換えと関係の説明で埋め、事実を作らない。分からないことは「不明」と書く。
   資料なしの題では、主張の文（定義・数・年・人名・条文・法則や因果の説明）の句点の直前に台帳の ID `[R01]` を付ける（`sources.md` 1）。台帳に無い主張・未確認（`U`）の行の主張は書かない。`[R01]` の印は `gate` が外して測るので、字数の目標には入らない。
3. 測る：`python3 ${CLAUDE_PLUGIN_ROOT}/skills/laba-book/scripts/book_state.py gate <節>.md --level <段>`。
4. `NG` の項目だけを直す（直す箇所は、道具の指す数に関わる文だけ）。もう一度測る。**直すのは最大 2 回**。2 回で通らない項目は残し、理由を返事に書く。点数を上げるために内容のない文を足したり、資料の事実を削ったりしない。
5. 返す：節のファイルの場所・最後の `gate` の結果（`--json` の要約）・直した回数・残した項目と理由・新しく使った用語（`new_terms`）。

## 4. してはいけないこと

- 「本節では〜を解説する」「〜について見ていこう」などの道案内・作業の記録を本文に書かない。
- 本文を箇条書きにしない。「ポイント」「まとめ」の枠は `:::point` の 1 つだけ。
- 見出しを文にしない。見出しの直後に見出しを置くのは、節 → 項に下がるときだけ。
