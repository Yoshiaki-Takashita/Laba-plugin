# P5 図（本文から図にする・描く・検める）

本文（P4）が書けた節について、構成の図の候補を実際の図にする。**親（この入口）が行う**（節の担当は図を描かない）。
判断は `figure-judgment.md`（12 行）、記述の形と欄は laba-textbook の `references/figure-spec.md`、描き手と検査は laba-textbook の `scripts/figure_svg.py`・`figure_check.py`。

## 1. ループ（節ごと。図は 1 節に 1 つまで）

```
本文の段落 ─S1 図にするか（12 行）─ 当たらない → fig を null に（または dropped に理由）
              │
              S2 型（12 行の決定の順。compare を relation より先に）
              S3 要素（本文の語そのまま・数は本文の数そのまま）→ work/ch<n>/figs.json に {"<id>": 記述}
              S4 描く：figure_svg.py figs.json figs/      （記述の検査 → SVG → 幾何の検査）
              S5 検める：book_state.py figs work/ch<n>   （候補と図と本文の :::fig id= の突き合わせ）
              └ 誤りが残る → 直す（最大 2 回）→ それでも残る → 図をやめ、fig.dropped に理由
```

1. **S1 図にするか**：構成で `fig` を立てた節だけでなく、書いた本文を読み直して当てる。「1 文で言える」「語が本文に無い」「数の出典が無い」「同じ節にもう図がある」は作らない。構成で立てた候補でも、本文を読んで当たらなければやめる（`fig.dropped` に理由を 1 行）。本文を書いて新しく当たった段落があれば、`fig` を足す。
2. **S2 型**：12 行の上から。前後・説の違いで同じ当事者の関係が変わる → `compare`（1 枚の relation に詰めない）／本文に数が 3 点以上 → `chart`／順序だけ → `scale`／分類 → `tree`（束ねるだけ `brace`・要件の組み立て `bracket`）／分岐 2 回以上 → `flow`。`scene`・`venn`・`family`・`ledger` はまだ描けない（`want` に残して `fig.dropped`）。
3. **S3 要素**：ノード・面の見出し・項目・カテゴリは**本文の語そのまま**（4〜8 字。長い語は本文に残し、図は短い語）。chart の `values` は本文に書いた数そのまま（丸めない・計算しない）。資料なしの題では、その数の文に台帳の ID がある数だけ（`sources.md`）。`note` に出典か記号の意味を 1 行。id は英小文字で始まる 16 字以内（`f1`・`f2`…章の中で通し）。
4. **S4 描く**：`python3 ${CLAUDE_PLUGIN_ROOT}/skills/laba-textbook/scripts/figure_svg.py work/ch<n>/figs.json work/ch<n>/figs/`。記述の誤りがあれば描かない。描いた SVG は幾何（文字の重なり・はみ出し・文字に掛かる線）も検める。**誤り 0 まで直す**。警告（縦横比・余白・本文に無い語）は読んで、直せるなら直す。
5. **本文に置く**：参照する段落の直後に、

   ```
   :::fig id=f1 kind=compare
   図が示すこと（1 行。図の中身を繰り返さない）
   :::
   ```
   本文では、図が何を示すかを 1 文で 1 回だけ言う（「図 1 参照」で済ませない）。構成の `fig` に `"id": "f1"` を書く。
6. **S5 検める**：`python3 ${CLAUDE_PLUGIN_ROOT}/skills/laba-book/scripts/book_state.py figs work/ch<n>`。候補が全部「図にした」か「やめた（理由つき）」になり、誤り 0 で通る。数（図にした数／候補の数・記述と SVG の誤りと警告）を報告に書く。
7. 機械が見ないもの（辺の根拠・関係の向き・主題の正しさ）：図を作っていない点検者に見せる（laba の `reviewer-prompts/figure-check.md`）。立てられないときは報告に「図は自己点検」と書く。

## 2. 置き場

| もの | 場所 |
|---|---|
| 図の記述（全図） | `work/ch<n>/figs.json`（`{"f1": {...}, "f2": {...}}`。紙面の `page2.figs` に同じものが入る） |
| 描いた SVG | `work/ch<n>/figs/<id>.svg`（見るため。GNOTO は記述から自分で描く） |
| 構成の図の欄 | `outline.json` の節の `fig`：`{"kind": "compare", "id": "f1", "why": "…"}` か `{"kind": "chart", "dropped": "本文に数が 2 点しかない"}` |

## 3. してはいけないこと

- 図のために本文に無い語・数・関係を足す（図は本文を絵にするだけ）。
- 誤りの出る図を残す（直せなければやめる）。点数のために図を増やす（12 行に当たらない段落を図にしない）。
- 座標・色・線の太さを記述に書く（スキーマが拒む。描くのは描き手と GNOTO）。
- 凡例の箱を作る・色相のある色を使う（灰の濃さだけ）。
