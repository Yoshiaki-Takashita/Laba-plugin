# LABA レポート（reportkiller）

このスキルのフォルダは `${CLAUDE_PLUGIN_ROOT}/skills/reportkiller/`。下の `references/`・`scripts/` はすべてこの下にある。

原則は一つ。**自分で読んでいないものは書かない。読めなかったことは隠さずに報告する。** 読者（教授・査読者）は引用元を知っている前提で書く。判例研究は laba-hanrei（構成・引用の格付け・体裁）、スライドは laba-slides の仕事。判例研究の文章を直すときだけ、このスキルの検証・文体・図の規則を上に載せて使ってよい。

## 0. レベルを決める（1 語で切り替える）

`/reportkiller 〔レベル〕〔分野〕 課題文`。レベルは 高校生 hs／学部生 ug（既定）／大学院生 grad／専門家 pro／論文 paper／学会 conf。何を変えるかは `references/levels.md` §1（文献の数・根拠の格・反論と射程・査読の回数）。**文体の数値は段ではなく「型」で決まる**：高校生＝意見文、学部生＝発表レジュメ（較正用の完成版で較正）、大学院生以上＝論文（人の公開論文の分布）。上の段ほど文を短くそろえる、という設計はしない（それが AI の文の形だと研究で分かった）。

## 1. 手順（どの段も同じ。段は厳しさだけを変える）

| 段階 | すること | 読む参照ファイル |
|---|---|---|
| ① インテーク | 1 回で聞き、返事を待たずに調査を始める。最初の答えの冒頭で一度だけ、提出の規則に従う責任と V1・V2 の原典確認を利用者に示す | `structure.md` §1 |
| ② 主張マップ | 結論←主張←根拠の木。根拠のない主張は書かない。自分の論点（一次資料を細かく読んで見つけた点）を 1 つ | `structure.md` §2 |
| ③ 調査と台帳 | 検索先を回り、1 文献 1 行の台帳（V0〜V3）を作る。V0 は書かない。「」は V3 だけ。頁は V3 だけ | `citation-ledger.md` |
| ④ 構成 | 分野の標準構成。冒頭に構成。序論の型（問い・範囲・主張）、反論と射程、学説・判例の扱い | `structure.md` §3〜7 |
| ⑤ 本文 | 日本語の学部生以下は `prose-ja.md`、大学院生以上の日本語（法律文が手本）は `prose-ja-law.md`、英語は `prose-en.md`。禁止語の一覧ではなく、実測で効いた目印を消す | 言語と段で 1 つ |
| ⑥ 図と表 | 一文で言えるメッセージ→型→白黒で描き切る→色を 1 つ（#943522）→図題に読み方と数字。表は横罫 3 本 | `figures.md` |
| ⑦ 体裁 | Word は黒一色・囲みなし・フッターに頁番号。スライドは図形で描く | `word-format.md`・`slides.md` |
| ⑧ 検証 | 引用の再照合・数値の再計算・本文を見ていない別エージェントの査読（段の回数）・機械の点検（下の scripts）・最終チェック | `verification.md` |
| ⑨ 渡し方 | 成果物と台帳を別に。V1・V2 の一覧と、利用者の資料から写した頁数の一覧を必ず報告。修正は言われた箇所だけ、版番号を上げ、前版を残す | `verification.md` §6 |

## 2. 機械の点検（直す候補を出す。人の文を「AI が書いた」と判定する道具ではない）

```
node ${CLAUDE_PLUGIN_ROOT}/skills/reportkiller/scripts/prose_check.js --level grad 本文.txt            # 文体・構成・台帳の所見（日本語は型・英語は段で数値が変わる）
node ${CLAUDE_PLUGIN_ROOT}/skills/reportkiller/scripts/prose_check.js --level paper --lang en --ledger 台帳.txt draft.txt
node ${CLAUDE_PLUGIN_ROOT}/skills/reportkiller/scripts/ledger_check.js 本文.txt --ledger 台帳.txt       # V0・ID の重複・本文に無い ID・頁数の食い違い・V3 でない行の「」と頁
python3 ${CLAUDE_PLUGIN_ROOT}/skills/reportkiller/scripts/fig_check.py 図.svg --width-mm 156           # 図の 22 項目＋建築の図の 6 項目（PNG は色と dpi だけ）
```

所見は error が 0 になるまで直す。warn は残す理由を書けるなら残す。1 つの印だけで書き直さない。指摘は「どの文が・何字で・どこで分けるか」から始め、書き直しは利用者が選ぶ。

## 3. 全段で守ること（短く）

- 読んでいないものは書かない。未確認の印（【要確認】）と作業の注記（本文約○字・記憶に基づく）を最終版に残さない。
- 読者が著者本人でありうる文献（指導教員の論文）は V3 以外は本文に入れない。
- 箇条書きは本文に使わない（構造が本質のところだけ）。「ポイント」の枠を使わない。
- 数え上げは語の形でなく族で見る：「第一に…第三に」を避けて「一つは／もう一つは」「二つの点で」「実益は二つ」に逃げない（合計 1 万字に 5 まで。要件・理由は ①②③）。章の頭と末の道案内（本章では〜・次章では〜）は毎回置かない。
- 本文に作業の告白を書かない：検索先・検索語・検索月・読めなかった資料・書誌だけの確認は台帳と報告に。限界の節は論の射程だけ。参考文献は中身に依拠した文献（V3・V1 の二次資料）だけで、V2 は載せない。
- 無料で読める一次資料は原典で引く（孫引き禁止）。主要な文献の注が引く文献をたどり、無料のものは読む。有料の重要文献は書かずに【要入手】として報告の冒頭に出す。
- 利用者が手を入れた段落（太字・下線・です・ます）は、以後の版で壊さない（docx は XML を直接編集）。
- 図は角丸・影・グラデーション・丸の中のアイコン・凡例だけの色分け・4 色以上・塗りの見出し行を使わない。文字はゴシック 1 書体・黒。線画は 600 dpi 以上か SVG。ラベルは図だけで意味が取れる語（記号 A〜E で置かない）、流れを示す図は矢印を省かない、一枚に関係の種類を混ぜない、始点・終点も同じ形式の箱、図題は完全な文で「何を示すか＋読み方＋出典」。
- **資料で確かめられない部分は、空白や「未確認」で終わらせず、ライト／ル・コルビュジエの研究の規則に沿って想像・創作で補う。ただし資料・推定・創作の 3 層を、図・本文・データで見分けがつくようにする（`references/arch-creative.md`）。**
- **建築の作品研究・ポートフォリオを作るときは、`references/arch-portfolio.md`（中身の最低ライン：見開きの構成・確かさの扱い・紙面）を先に読み、`references/arch-masters-data/`（ライト／ル・コルビュジエの作品ごとの研究）から材料を取る。**
- **建築の図（平面・断面・立面・展開・アクソメ・配置・ダイアグラム・詳細）を作るときは、手で SVG を書かず、`references/arch-figures.md` の手順で `scripts/archstudio/`（Node の道具）を使う。** 作って、PNG で目で見て、`arch_check.py` で点検し、直してから紙面に組む。
- 建築のレポート・ポートフォリオでライトやル・コルビュジエの規則・寸法・こだわりを使うときは `references/arch-masters.md`（研究の V0〜V3 の読み替え・V0/V1 を事実として書かない・作品→規則の引き方）。
- 英語は Claude の癖（短い文の多用・細かい見出し・rather than・First/Second/Third・問いの無い序論）を直す。GPT 系の禁止語は参考。em dash と文頭の But は使ってよい。

## 4. このスキルの中身と出所

版：**v2.1**（2026-10-23。v2 を伏せた比較で評価し、見つかった癖〔数え上げの逃げ道・本文の作業の告白・無料文献の取りこぼしと孫引き・図のラベルと矢印と図題〕を直した）。
`references/` の数値はすべて根拠つき（`levels.md` §3.1 の JSON が唯一の元。研究：較正用の完成版（判例研究のレジュメ）の実測、日本の法律論文 47 本、判事の個別意見 39 件、英語の公開論文 99 本、学生の図 400 枚、建築の図 450 枚、投稿規定と知覚の研究）。文書中の「研究ノート WRITING-…／FIG-…／EXEMPLAR-…」は、その研究の記録の名前で、このプラグインには入っていない。数値と規則は `references/` に写してあり、読むのに研究ノートは要らない。

## 5. このスキルの道具がすること（すべて手元で動く）

- `scripts/prose_check.js`・`ledger_check.js`・`report_check.js`（Node、依存なし）：渡された本文と台帳のテキストを読んで所見を出す。ファイルは書かず、ネットワークにも接続しない。
- `scripts/fig_check.py`・`scripts/archstudio/arch_check.py`（Python 3 標準ライブラリだけ）：図（SVG。PNG は色と dpi だけ）を読んで所見を出す。
- `scripts/archstudio/cli.js`（Node、依存なし）：建物のデータ（JSON）から建築図の SVG を作り、指定の場所に書く。ネットワークには接続しない。
- 文献の検索（J-STAGE・CiNii・各出版社の書誌ページなど）は、スクリプトではなく Claude が `references/citation-ledger.md` の手順で行う。読むのは公開の頁だけで、利用者の文章や個人の情報は送らない。
