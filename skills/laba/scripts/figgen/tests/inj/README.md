# 注入した誤りの回帰試験

`run_tests.py` の inject の組が使う。本文は図より先に書いたもの。

| 場所 | 中身 |
|---|---|
| `body/` | 本文（n1〜n5：作成側 round3、m1〜m6：独立の採点者の未知 6 題） |
| `good/` | 正しい図の仕様。`trace.py --strict` で所見が出ない（偽陽性なし）こと |
| `bad/` | 独立の採点（第3回）が注入した 23 件。記号_題_種.json。全部で所見が出る（要確認、終了コード 1）こと |
| `fresh/` | 新しい図（round4 の 8 図）と、後から入れた 15 件。`*.miss.json` の 2 件は機械が見ない種類（時点の前後の入替え・段の見出しの意味の取り違え）で、人の点検に回す |

種類：①勝敗・成否の入替え ②矢印の逆向き ③効果の取り違え ④条文番号の誤り（本文にある別の条文を含む） ⑤主体の入替え ⑥限定語の脱落・すり替え ⑦枝の語・手続の順序の入替え ⑧範囲の枠の取り違え。


注意（第5回）：ここにある誤りは、過去の採点で使ったものである。trace.py の規則をこれに合わせて足すと、ここでは全部止まるが、新しい種類の誤りでは約半分しか止まらない（第4回の実測 47%）。この組は「前に止めた誤りを止め続けること」の確認であって、検出率を上げる材料ではない。trace.py は所見を出す補助で、一致の保証ではない（`references/figures/06-traceability.md`）。
