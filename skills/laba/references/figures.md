# 図の選び方と作り方（入口）

図は、文章だけでは分かりにくい点を解消するために描く。飾りの図、本文をなぞるだけの当事者関係図は要らない。資料に図が無いなら、ここが資料を上回る所になる。

図は手で SVG を書かず、**仕様（JSON）を書いて `scripts/figgen/` に作らせる**。色・線・字の大きさ・折り返し・矢印の経路はエンジンが決める。書く人は「どの難所か」「どの型か」「何を入れるか」「どこを強調するか」だけを考える。

## 2　難所を書き出す

作図の前に、「文章だけでは分かりにくい点」を三つ以上、作業ファイルに書く。図はその点にだけ描く。

難所になりやすいもの：

- 二つの観点の組合せで類型が決まる
- 似た二つの場面で帰結が分かれる。分かれ目が一つの事実・一つの証明責任にある
- 判例が多く、「誰が誰に何を求めたか」で結論が分かれる
- 判断や手続が段階を踏み、途中で外れると別の結論に落ちる
- あるものは及び、あるものは及ばない（効力、主張と証拠、承認の効果）
- 時点が決め手になる（設定時・基準時・期間の起算と満了）
- 主張が、請求原因・抗弁・再抗弁と積み上がる
- 一つの価値を複数の者が分け合う（配当、担保価値、相続分）
- 条文の本文とただし書、原則と例外の関係

## 3　型を選ぶ（早見）

詳しい決定表は `algorithms/figure-type.md`。

| 難所の形 | 型 | レンダラ |
|---|---|---|
| 誰が誰に何を求めるか（三人以上） | 当事者関係図・多数当事者 | `parties` |
| 関係が順に増えていく | 時系列の積み上げ図 | `parties`（`pict`・`step`） |
| 権利が人から人へ移る | 権利移転の連鎖 | `chain` |
| 同じ人から二人が権利を得た | 対抗関係の図 | `chain`（`relations`） |
| 審級ごとの結論 | 審級の流れ | `instances` |
| 要件がそろって効果が生じる | 要件効果の木 | `tree`（下向き・矢じりなし） |
| 請求原因・抗弁・再抗弁 | 積み上げ図 | `stack` |
| 相手ごとに証明責任が違う | 主張立証責任の分配の図 | `compare`（`split`） |
| 判例の立場の移り変わり | 判例の変遷の図 | `timeline` |
| 学説がどこで分かれるか | 学説の対立地図 | `compare`（矢印なし） |
| 本文とただし書、各号 | 条文の構造図 | `statute` |
| 期間・金額・順位 | 数直線 | `numberline` |
| 機関と機関の関係 | 組織図 | `tree`（下向き） |
| 誰がどの順に行うか | 手続のスイムレーン | `swimlane` |
| 問いに答えて結論に行き着く | 決定木 | `tree`（右向き） |
| 広い概念と狭い概念 | 包含図 | `nest` |
| 基準時・状態の変化 | 時間軸 | `timeline` |
| 二つの観点の組合せ | 座標図 | `quadrant` |
| 似た二場面の帰結の違い | 比較図 | `compare` |
| 判例が多い | 判例マトリクス | `matrix` |
| 関門を順に通る | 流れ図 | `flow` |
| 及ぶもの・及ばないもの | 動きの図 | `movement` |
| 価値の分け合い | 価値配分の図 | `bar` |
| 成立する場合としない場合 | 複合図 | `panel` |

当事者関係だけの図は、一つのノートに二枚まで。一つの章で図は三つか四つ。難所を解く図（比較・流れ・時間軸・積み上げ・複合）を必ず一つは入れる。

## 4　作る手順

```
export NODE_PATH=<sharp を入れたフォルダ>/node_modules        # PNG にするときだけ
cp scripts/figgen/specs/〇〇.json work/fig3.json               # 近い用例を写す
（message・ラベル・強調を書き直す。語は本文から取る）
node scripts/figgen/cli.js check work/fig3.json                 # 仕様の検証（必須の項目・知らない項目・参照先のない id）
node scripts/figgen/cli.js work/fig3.json work/fig3.svg --png   # 作る。warn を直す
python3 scripts/fig_lint.py work/fig3.svg --spec work/fig3.json # error 0 にする（E01〜E12、W01〜W13）
python3 scripts/figgen/trace.py work/fig3.json --body 本文.md --fig 3 --strict   # 所見の洗い出し（T01〜T08、照合できなかった要素、機械で見ない種類）
```

1. 難所を一つ選び、メッセージを一文で書く。言えなければ描かない。図が示す関係を述べる本文の段落を、先に書く。
2. 型を決める（3節、`algorithms/figure-type.md`、`figures/08-field-gallery.md`）。
3. 近い用例の仕様を写し、中身を入れ替える。条文番号・期間・判例の書誌は原文で確かめてから入れる。
4. 生成する。仕様に誤りがあれば、図は作られず理由が出る。`cli.js` の warn（図題の形、強調なし、文字が版面の外、ラベルの置き場なし、線が箱を貫通する・別の線に重なる、語の途中で折れた、箱の語が四行以上、「ない」状態の帯が実線）を直す。
5. `fig_lint.py` で error 0 にする（線の貫通 E11・重なり E12 を含む）。warn は、理由を言えるものだけ残す。
6. PNG を 150mm 幅で見る。
7. `trace.py` で所見を洗い出す。所見は一つずつ読み、図の誤りは図を、本文の説明不足は本文を直し、偽陽性は図を変えずに退ける表に理由を書く（`--dismiss`）。**所見を消すために要件の語・限定語・条文番号を削らない。**「所見なし（機械で見られる範囲で）」は一致の保証ではない。
7'. 読み上げの表を作る（`reviewer-prompts/figure-check.md` 2。省略できない照合の中心）：矢印・止め線・枠・枝・小枝・時点・条文番号を一つずつ文にし、本文の該当する文と並べる。`trace.py` の「照合できなかった要素」と「機械で見ない種類」を必ず含める。
8. `figures/10-quality-rubric.md` で採点する。六つの観点のどれかが 3 以下なら直す。自分の点は下書きで、成績には点検役の点を使う。
9. 図が三枚以上あるノートは、別の点検役に `reviewer-prompts/figure-check.md` で見てもらう。
10. docx に入れたら PDF にして、図の前後の空白、図とそれを指す文の距離を見る（`figures/07-composition.md`）。

## 5　必ず守ること（短い版）

- 一つの図に一つのメッセージ。図題は「図N　この図で分かること：…。読み方。強調は…。」
- 色は黒 `#1A1A1A`・灰 `#8C9493`・えんじ `#943522` の三つ。字は黒。強調は一点。
- ラベルは語で書く。記号（A、①）だけにしない。語は本文と同じ。限定語を落とさない。
- 矢印は、請求する人・渡す人・先の時点から出す。流れ図で矢印を省かない。
- 実線は確かな関係、破線は争い・仮定、点線は補助と手続上の行為。届かないものは止め線。「ない」状態を太い実線で描かない。
- 線は、つないでいない箱を通さない。別の線と重ねない。人でないものは箱の形（`kind`）で分け、凡例を付ける。
- 条文番号・判例の表記・熟語・短い括弧の途中で折らない（エンジンが守る。warn が出たら語を減らす）。
- 資料にない内容は「（補足）」と書き、図題か注で断る。説明のための数値は例だと断る。
- 角丸・影・グラデーション・アイコン・枠で囲んだ凡例の箱・四色目を使わない（凡例は、記号を使った図にだけ、図の下に一行で）。
- 150mm 幅で作り、縮めて貼らない。図は、それを指す文のすぐ後に置く。

## 6　手で書いた SVG を使うとき

エンジンにない形がどうしても要るときだけ、`scripts/templates/` のひな形（7 型）を写して手で直す。その場合も `fig_lint.py` の error 0 と PNG の目視は同じ。PNG にするのは `node scripts/fig_build.js 図.svg`。新しい型がくり返し要るなら、レンダラを足す（`../scripts/figgen/README.md` の「自分で型を足すとき」）。

## 7　表の規則

- 表は、並べると分かるものだけ（類型の比較、要件と趣旨、判例の一覧、条文の列挙、結論の一覧）。
- 横罫三本（上・見出しの下・下）。縦罫と塗りは使わない。
- セルは短く。文で書くなら一文か二文。セルの中で資料にない内容を書くなら、冒頭に「（補足）」。
- 「同左」「同上」「—」で埋めない。
- 表題は「表N　○○」。表題は表の上、図題は図の下。
- 図と表で同じ内容をくり返さない。
