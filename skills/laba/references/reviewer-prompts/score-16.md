# 指示文：採点（基本4指標＋独自12指標）

```
講義ノートを、資料（お手本）と比べて採点してほしい。ファイルは修正しないこと。作成者の自己検査は独立ではないので、抜き取りで検証する。

対象：〔ノート（docx・全文テキスト・本文テキスト・PDF）〕
資料：〔書き起こしと頁の画像〕
採点の基準：〔references/scoring.md〕。指標ごとの定義・減点の型・9.5 に届く条件は〔references/metrics/ の16本〕
機械の検査の結果：〔checks のフォルダ。score.py・pipeline.py の出力〕（走らせ直して確かめてよい）
作成者の作業ファイル（あれば）：〔判例の理由の出所表 reasons.json と判決全文の保存先／定義の照合表 definition.md／難所の一覧／短答の命題 items.json〕。中身を信用せず、抜き取りで原典と照らす。

付けてほしいもの
A. 網羅率：資料の知識の単位（定義・要件・判例の結論と理由・学説・具体例・例外・相互参照）を一覧にし、ある＝1／不十分＝0.5／ない＝0。％で。落ちている重要な項目を列挙。
B. 誤り：重大・中・軽微の件数と一覧（scoring.md の定義による）。
C. 説明技法：〔references/techniques.md〕の12項目を各0〜2点。根拠としてノートの短い引用。
D. 文体：5段階（資料の3頁以上を読んで）。
E. 独自指標のうち点検者が付けるもの（各0〜10）：①条文の正確さ ③判例理由の忠実度 ⑤定義の精度 ⑫答案転用性。③は、出所表の判例を5件以上抜き取り、「判決が挙げる理由」の欄を判決文と照らす。⑫は、論点カードの規範・書き出しが答案に使えるか、短答の命題の正誤と根拠が正しいか（5問以上を条文・判決文で確かめる）を見る。9.5 以上を付けるときは、各指標の文書の「9.5 に届く条件」を満たしているかを1項目ずつ確かめ、満たしていない項目を書く。⑧難所の可視化率は、作成者の難所の一覧が妥当か、手当てが効いているかを見て、listed／handled を数える。
   ②④は、機械の値に誤検知があれば補正した値を。
F. 総合の判定：資料を 下回る／同等／上回る。理由。上回るなら、具体的な箇所を5つ。
G. 渡す前に必ず直す点：最大5つ。箇所と直し方。
H. 作り方（手順書）をどう直せば次は良くなるか：検査できる規則の形で5項目以内。

出力
- 採点表を〔保存先〕に保存。
- reviewer.json（scoring.md 8 の形）を同じ場所に保存。
- 報告は〔500〕字以内：網羅率、技法点、誤りの数、文体、独自指標の主な値、判定、必ず直す点。
```

## 使うときの注意
- 採点者には、前の回の採点表を渡してよい（形式を揃え、差分で見るため）。ただし、作成者の自己評価は渡さない。
- 最後の版を採点していないなら、報告にそう書く。
