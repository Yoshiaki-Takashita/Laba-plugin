# 説明の技法

本文はこの技法で書く。どれも「検査できる形」で書いてあるので、書き終えたら一つずつ当てて確かめる。採点（`scoring.md` の技法12項目）はこの番号に対応する。

## 目次
1. 整理軸　2. 規範の直後に記号事例　3. 理由は利益で　4. 判例は4段　5. 制度は6段　6. 区別表　7. 反例　8. 確度の語　9. 段落の組み方　10. 二重記載の禁止　11. 相互参照と境界　12. 接続語の用途

例文はすべてこのスキルのために書いたもので、特定の書籍の文ではない。

## 1. 整理軸
章の冒頭で、全体を整理する軸を定義し、全類型をその軸に当てはめた表を置く。各論の冒頭で「軸のどこにあるか」を1文で確かめる。

- 良い例：「物権変動の対抗問題は、①当事者か第三者か、②登記があるかないか、の二つで整理できる。以下の類型は、すべてこの二つの組合せである。」→ 表 → 各節の冒頭「この類型は、第三者にあたり、登記がない場合である。」
- 悪い例：「物権変動には次の類型がある。（1）…（2）…（3）…」と並べるだけで、類型どうしの関係が示されない。
- 検査：章の冒頭に軸の定義と表があるか。各節の冒頭に位置の確認が1文あるか。

## 2. 規範の直後に記号事例
規範・条文を書いたら、直後に記号の事例を1つ置き、帰結を①②③で列挙する。条文の構成要素それぞれに、少なくとも1つの帰結を対応させる。事例は節をまたいで同じものを使い回す。

- 良い例：「共同訴訟人の一人がした訴訟行為は、他の共同訴訟人に影響しない。たとえば、X1とX2がYを訴えた場合、①X1が自白しても、その効力はX2に及ばない、②X1だけが上訴すれば、移審するのはX1の請求だけである。」
- 悪い例：「各共同訴訟人は独立して訴訟を追行する。」で終わる。何が起きるのかが見えない。
- 検査：規範の文の次の2文以内に「たとえば」「という場合」があるか。

## 3. 理由は利益で
すべての規律に「誰の、どんな利益を守るためか」を書く。利益が複数あるなら一つずつ取り上げ、それぞれが別の手段で守られるかを確かめてから結論を書く。

- 良い例：「申出を原告だけに認めるのは、この制度が原告の二重敗訴の危険に対処するためのものだからである。被告の側には、弁論が分離されないことについて独自の利益がない。」
- 悪い例：「趣旨は手続の適正にある。」誰の利益かが分からない。
- 足した層（全体像・ざっくり理解・まとめ・図題）にも理由を書く。足した説明の段落ごとに、理由の文（〜から、〜ので、〜ため）を1つ置く。結論だけを並べた要約は、論証の密度を下げる。目安は、ノート全体の論証密度が資料の−3ポイント以内（`scripts/density.py` が WARN を出す）。9.5 に届く条件は、地の文全体が資料の−1ポイント以内で、足した層に理由のない塊が無いこと（`scripts/argument_check.py`、`metrics/06-argument-density.md`）。理由の標識だけを足さない。
- 検査：理由の文に、主体（原告・債権者・第三者・社会一般）が書かれているか。

## 4. 判例は4段
判例は［事案の型／結論／判例が挙げる理由／批判・射程・緊張関係にある判例］で書く。

- 理由の欄には、資料か判決の原文が判例の理由として書いているものだけを入れる。
- 理由の出所を分ける。判決文にある理由（判示）と、資料がその判例について説明している理由（資料の説明）は別のものである。表なら列を「判決が挙げる理由」と「資料の説明」に分けるか、セルの冒頭に［判示］［資料］の札を付ける。列名を「判例が挙げる理由」と一つにまとめない（`algorithms/case-placement.md`）。
- 「主たる理由」「補強的な理由」の順序づけが判決文に無いなら、その順序づけは資料の説明として書く。
- 自分で補う説明は「（補足）」と明示する。「と説明されることもある」のような、出どころのない帰属は書かない。
- 判決が理由を述べていないとき（「原審の判断は正当である」だけ、など）は、空欄にせず「判決は理由を述べていない」と書く。判決文を確かめていないなら「判決文は確認していない」と書く。
- 一つの判決の判示事項が複数あるとき、都合のよい一つだけを引かない。
- 「判決が挙げる理由」の欄・［判示］の札の文は、判決文の語で書く。資料が①②③と整理していても、番号ごとに判決文で確かめ、判決文の言い方が違う点は判決文の語にする。資料のまとめ方は「資料の説明」に書く。判決の理由の段落は最後まで読み、資料が挙げていない理由（「かつ、…」「また、他面…」）も落とさない。
- 理由の1点ごとに、判決全文の該当箇所（頁、または段落の冒頭の語句）を出所表に控える。控えのない判示は書かない。
- 良い例・悪い例は `examples/good-case-4dan.md` と `examples/bad-patterns.md`。
- 検査：判例ごとに4つの要素があるか。理由の欄に、資料にない語句が入っていないか。`scripts/reason_source_check.py` の所見が0か（`--reasons` で、判示を書いたセルごとに控えがあるか）。判例ごとの理由の出所表（`scripts/reason_table.py`。状態・理由の1点ごとの抜き書きと該当箇所・確かめた先）を作り、判決文と照合する。「欄の文が判決文の語でない」が0か（`metrics/03-reason-fidelity.md`）。

## 5. 制度は6段
新しい制度・特則は［問題（具体例）→従来の対処→その限界→新制度→要件（条文上の要件と、条文には書かれていない解釈上の要件）→各要件の理由］の順で書く。要件を表にするなら「誰のどんな利益を守るか」の列を付ける。

- 悪い例：「要件は①…②…③…である。」から始める。なぜその要件なのかが伝わらない。
- 検査：制度の節が、問題の具体例から始まっているか。要件ごとに理由があるか。

## 6. 区別表
資料が「これに対して」「〜とは異なり」で対比する概念の組には、表を置く。列は［典型例／区別の基準／区別する理由／区別が要る場面・要らない場面／限界］。「同左」「同上」は使わない。

- 検査：資料の対比の箇所の数と、区別表（または対比の段落）の数が合うか。

## 7. 反例
通説・伝統的な説明を書いたら、その説明が届かない場合を直後に1つ置く。資料が挙げていれば、必ずそれを使う。自分が挙げた例の全部に、その理由が当てはまるかを照合する。

- 良い例：「この説明は、認容判決にも棄却判決にも対世効がある場合を念頭に置いている。認容判決にだけ対世効がある場合には、当てはまらない部分がある。」
- 検査：「意義」の節に、説明が当てはまらない場合の段落があるか。

## 8. 確度の語
資料の確度の語を、強めも弱めもしない。

| 資料の語 | 意味 | ノートでの扱い |
|---|---|---|
| 判例である／判例は〜とする | 判例の立場 | そのまま |
| 通説である／多数説 | 学説の大勢 | そのまま |
| 有力である／という見解がある | 一部の学説 | 「通説」に格上げしない |
| 余地がある／と解する余地 | 可能性の指摘 | 「〜である」と言い切らない |
| 不明確である／明らかでない | 未解決 | 結論を作らない |
| 要請されよう／期待される | 運用上の望ましさ | 「禁止される」「できない」にしない |

法的な効果（禁止される、効力を生じない、できない）は、条文か判例が定める場合にだけ使う。運用上の要請と混ぜない。`scripts/certainty_check.py` の「見当たらない」を一件ずつ見る。

確度は、本文を書いた後にもう一度落ちる。論点カードの欄、短答の命題、まとめの文は、本文を短く言い直して作るので、「とされる」「と考えられている」の文末が落ちて断定になりやすい。作ったら `scripts/derived_check.py` で、行ごとに本文の該当箇所と照らす（`added-text-safety.md` 規則13）。接続の語も確度のうちである。資料の「…が、」（逆接）を「…ので、」（理由）に変えない。

## 9. 段落の組み方
1段落1論点。［主題文→理由（〜からである）→例・帰結→限定］で組む。段落は理由・例・帰結のどれかで閉じ、言い直しの文で閉じない。箇条書きは、並列の列挙にだけ使う（教科書型の本文では使わず、文中の①②にする）。

- 悪い例：短い文を5つ並べ、文と文の関係（理由なのか、例なのか、限定なのか）が示されない。

## 10. 二重記載の禁止
判例は、本文か表のどちらか一方にだけ書く。判例が3件以上ある小節は表にまとめ、本文は導入の1文だけにする。1〜2件の小節は本文で4段を書き、表は作らない。「ざっくり理解」と本文で、同じ文を3つ以上重ねない。

まとめは1か所にする。章末のまとめと全体のまとめで、同じ要約を繰り返さない。章ごとの要点は、巻末の論点カード（`ronten-card.md`）に置き換える。言い直しの層（まとめ・全体像）は全体の4%以下、分量は資料の1.15倍以内を目標にする（上限1.3倍）。`scripts/summary_dup_check.py` で見る。

巻末どうしでも二重に書かない。論点カードの「短答で問われる形」が短答の表の問と同じ知識なら、文を書かずに番号で示す。半分を超える行が「—」「規範の欄と同じ」になる列は作らない。1つの論点を2つの表に分けない（`metrics/11-info-efficiency.md` の巻末の測り方）。段落の末尾で、直前の内容を言い直す文（「…のは…の場合であり、…までは…ないことになる」）を足さない。表を置いたなら、表への参照で足りる。

## 11. 相互参照と境界
混同しやすい概念には「〜とは別である（⇨参照先）」と境界を書く。資料の相互参照は全部残す。節をまたぐ対比（「前述の○○とは逆の扱いである」）を足すと、体系のつながりが見える。

## 12. 接続語の用途
用途を固定する。

| 語 | 用途 |
|---|---|
| もっとも | 留保（原則は維持したまま、限定を付ける） |
| しかし | 反対・転回 |
| したがって | 帰結 |
| そこで | 対応策（問題を受けて、制度・解釈が出てくる） |
| なお | 補足（本筋から外れる） |
| ただし | 範囲の限定 |
| これに対して／他方 | 対比 |
| また | 並列だけ |
| たとえば | 例示 |

「また」「さらに」を3回続けない。続くなら、関係を見直して別の語にする。
