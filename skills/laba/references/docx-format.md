# Word の体裁とビルダー

## 目次
1. 体裁の仕様　2. 二層の見分け方　3. 使わないもの　4. ビルダーの使い方　5. ブロックの種別　6. 検証と目視　7. 既存の docx を直すとき

## 1. 体裁の仕様

| 項目 | 仕様 |
|---|---|
| 用紙・余白 | A4 縦。左右 25mm、上下 27mm |
| 本文 | 游明朝 10.5pt、行間 1.4、段落の頭は1字下げ |
| 見出し | 游ゴシック太字。章 14pt（下に細い罫線）、節 11.5pt、小見出し 10.5pt。次の段落と離れないようにする |
| 表紙ブロック | 右上に科目名と回（9.5pt）。中央に題（20pt）と副題（13pt）。「構成」（章の一覧）。「※条文番号は特に断りのない限り○○法による」 |
| 表 | 横罫3本（上・見出し行の下・下）。縦罫なし、塗りなし。セル 9.5pt。表題は表の下、9pt 中央 |
| 図 | 中央、幅 150mm 以内。図題は図の下、9pt 中央 |
| フッター | 右下に「頁／総頁」（フィールド） |
| 色 | 黒だけ |
| 読点 | 資料に合わせる（教科書型で資料が「，」なら `--comma-full`） |

書体が無い環境では、明朝・ゴシックの代わりの書体に置き換わる。利用者の環境で開くと游明朝・游ゴシックになる。

## 2. 二層の見分け方
- 本文：1字下げの段落。
- ざっくり理解：太字の見出し「ざっくり理解：○○」＋左に2字分の字下げ、10pt。段の中は、です・ます。
- 色・枠・網掛けでは分けない。見出しと字下げで十分に見分けられる。頁をまたがないよう、長さは半頁以内にする。

## 3. 使わないもの
- 色つきの見出し・帯・枠、「ポイント」の囲み、網掛け、アイコン。
- 塗りつぶした見出し行、縦罫の多い表。
- 下線の多用、傍点。強調は太字だけ、それも見出しと「結論」「答え」に限る。
- 脚注の多用（注は本文の括弧か「（補足）」で）。

## 4. ビルダーの使い方
```
python3 scripts/build_docx.py blocks.json out.docx --comma-full --body-out body.txt --text-out note.txt
```
- 入力は JSON（`{"meta": {...}, "blocks": [...]}`）か、`META` と `DOC` を定義した Python ファイル。長いノートは Python ファイルのほうが書きやすい（章ごとに変数に分けられる）。
- `--body-out`：本文（P・P2・K）だけのテキスト。文体と一致の検査に使う。
- `--text-out`：全文（表・図題・ざっくり理解を含む）。網羅・書誌・確度の検査に使う。
- `--comma-full`：本文の「、」を「，」に統一する（ざっくり理解には掛けない）。
- 見本：`scripts/sample_blocks.json`。

## 5. ブロックの種別

| 種別 | 意味 | 例 |
|---|---|---|
| H | 章見出し | `["H", "１．制度の趣旨"]` |
| S／SS | 節／小見出し | `["S", "(1) 要件"]` |
| C | 判例の見出し | `["C", "参考判例　最判平成○・○・○民集○巻○号○頁"]` |
| P | 本文の段落 | `["P", "…である。"]`　`**…**` で一部を太字 |
| P2 | 「ラベル：本文」の段 | `["P2", "事案：…"]` |
| K | 結論・答え | `["K", "結論　Xは…請求できる。…"]` |
| ZH／Z／ZB／ZN | ざっくり理解の見出し／段落／箇条書き／番号 | `["ZH", "ざっくり理解：○○"]` |
| B／N | 本文の箇条書き／番号（レジュメ型で使う） | `["N", "1. …"]` |
| T | 表 | `["T", [["見出し1","見出し2"],["セル","セル"]], "表1　○○", [50, 110]]` |
| F | 図 | `["F", "fig1.png", "図1　この図で分かること：…", 150]` |
| PB | 改頁 | `["PB"]` |
| KD | 論点カード表（`card_build.py` が作る） | `["KD", [[論点, 問題の所在, 規範, 理由, 当てはめの要点], …], "表9　論点カード"]` |

## 6. 検証と目視
1. docx の検証（環境に docx の検証スクリプトがあれば、それを通す）。
2. PDF にする（`soffice --headless --convert-to pdf out.docx`）。
3. 全頁を画像にして見る（`pdftoppm -r 60 -png out.pdf page`）。見る所：
   - 表の崩れ、セルのはみ出し
   - 図の前後の大きな空白（図が次頁に送られて、前の頁の下半分が空く）
   - ざっくり理解が頁をまたいでいないか
   - 見出しが頁の最下行に取り残されていないか
   - 図番号・表番号の順
   - 読点の混在
4. 直したら、もう一度見る。

## 7. 既存の docx を直すとき
- 利用者が手を入れた docx（太字、下線、書き換え）は、作り直さない。XML を直接直すか、該当の段落だけを差し替える。利用者の書式を消さない。
- 自分で作った docx の小さな修正は、ブロックのファイルを直して作り直す。
