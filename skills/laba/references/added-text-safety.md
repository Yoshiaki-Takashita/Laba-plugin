# 足した説明が誤りを生まないために

分かりやすくするために足した文（言い換え、具体例、ざっくり理解、まとめ、表のセル、図のラベル）は、誤りの入口になる。採点を重ねた結果、資料がある場合の誤りの大半は、資料を写した部分ではなく、足した部分から出た。足すことをやめるのではなく、足した部分を重点的に点検する。

## 1. 規則

1. **言い換えは言い換えだけ**　言い換えの文は、資料の文の意味を変えない。新しい理由・評価・結論・射程の判断を足さない。足すなら「（補足）」を付ける。
2. **帰属を照合する**　「資料は〜とする」「判例は〜とする」「通説は〜」「〜という理由である」と書いた文は、資料の該当箇所（頁と文）を作業ファイルに書き、理由の項目が一対一で対応するかを確かめる。
3. **限定語を落とさない**　「数人による」「一般には」「原則として」「〜に限り」「少なくとも」。複数を指す語（「前掲の判例ら」）を1件に狭めない。まとめ・表・図で「だけ」「すべて」「唯一」「認められない」を使うときは、資料に同じ限定があることを確かめる。
4. **確度を変えない**　資料の「余地がある」「要請されよう」「不明確である」を、「である」「禁止される」にしない（`techniques.md` 8）。
5. **法的効果と運用を分ける**　条文・判例が定める効果と、運用上の望ましさを同じものとして書かない。
6. **論理の要を落とさない**　「これを認めないと」「〜の場合に限り」「〜でない限り」のような、文の向きを決める句を、短くするときに落とさない。落とすと理由が逆になる。
7. **表・図・ざっくり理解にも同じ規則**　本文で守っても、表のセルや図の注記で破られることが多い。
8. **有益な文を引き継ぐ**　改訂で体や構成を変えるとき、前の版で点検者が「有益」とした加筆の一覧を作り、全件が残っていることを確かめる。
9. **判例の理由の出所を分ける**　判決文にある理由と、資料の説明を、別の欄・別の札で書く。判決が理由を述べていないなら、そう書く（`algorithms/case-placement.md`）。
10. **条文の要約で、限定の語を落とさない**　「同一の」「〜に限り」「〜の時までに」。資料の要約が落としていたら、条文で補い、報告に書く（`statute-verification.md`）。
11. **足した層にも理由を書く**　全体像・ざっくり理解・まとめの段落ごとに、理由の文を1つ。
12. **自己申告を成果にしない**　一致の数、照合の件数、書き手の判定は、機械の再実行か、別の点検者の結果を書く。自分で数えた値・自分で付けた点は、成果として書かない。
13. **派生物は本文と照らす**　論点カードの各欄、短答の命題と根拠、まとめ・全体像の文、索引の行は、本文から作り直した行（派生物）である。行ごとに、根拠にした本文の節を控え、次の2つを本文の該当箇所と照らす（`derived_check.py`）。
    - 確度の語：本文の「とされる」「と考えられている」「余地がある」「不明確」が、行でも同じ強さで書かれている。欄を短くするために文末を落とさない。
    - 条文番号：行に書いた条文が、本文の該当箇所でその結論の根拠として書かれている。本文が「○条は働かない」と書いた条文を、根拠として挙げない。
    資料→本文の検査（確度、条文）は、派生物を見ない。本文が正しくても、派生物は別に誤る。
14. **判示の欄は判決文の語で書き、該当箇所を控える**　「判決が挙げる理由」の欄・［判示］の札の文は、判決文の語で書く。理由の1点ごとに、原文の抜き書きと、判決全文の該当箇所（頁、または段落の冒頭の語句）を出所表に控える。資料の言い方（要約、「主たる理由」という順序づけ、資料が足した構成）は、「資料の説明」の欄・［資料］の札に書く。判決の理由の段落は最後まで読み、資料が挙げていない理由も落とさない。資料の表記と判決文が食い違うとき（事案の説明の語など）は、本文は資料の表記のまま、「（補足）判決の事案は…」と書く。
15. **報告の数値は機械で数えた値だけ**　字数、分量比、頁数、判例・条文・表・図の数、論点・短答・索引の数は、`report_numbers.py` の出力を写す。数え方を併記する。前の版と比べる値は、同じ道具で数え直す。

## 2. 実際に起きた失敗の型

| 型 | 何が起きたか | 防ぎ方 |
|---|---|---|
| 理由のすり替え | 判例が挙げた理由（基準が不明確で訴訟を混乱させる）を、もっともらしい別の理由に差し替えた | 理由の欄は資料・原文にある語句だけ。帰属の照合 |
| 判旨を逆に書く | 確認できなかった下級審判決の結論を、一般論から推測して逆に書いた | 確認できない判例の判旨は書かない（`case-verification.md`） |
| 部分引用 | 判決の一部の判示だけを引き、全体の結論と逆の印象を与えた | 同じ判決の他の判示事項を落とさない |
| 当事者の取り違え | 判旨の「甲・乙」と設例の「甲社・乙社」を混同し、親会社と子会社が逆になった | 判旨の記号と設例の記号の対応を注記する |
| 一般化しすぎ | 「判決の効力が衝突する」という説明を、当てはまらない類型にも広げた | 挙げた例の全部に理由が当てはまるか照合。反例の段落 |
| 矢印の位置ずれ | 図で、判例の矢印を隣の枠から出し、射程が本文と逆に読めた | 図の照合表 |
| 限定語の脱落 | 図・表の例示で「数人による」を落とし、別の類型の例に見えた | 図表の例示は本文と同じ限定語 |
| 論理の要の脱落 | 「これを認めないと」が抜け、理由が逆に読めた | 文を縮めるとき、条件・否定の句を確かめる |
| 資料の説明を判例の理由にした | 資料が解説として書いた理由を、表の「判例が挙げる理由」の列に入れた。判決文には無かった | 列を分ける。判決文で確かめたものだけを［判示］にする |
| 条文の限定の脱落 | 資料の要約どおりに書き、条文の「同一の控訴裁判所に」を落とした | 条文を引く文は、現行の条文と照らす |
| 否認と抗弁の混同 | 請求原因を争うことを「抗弁」と書いた | `yoken-jijitsu.md` 2 |
| 名宛人の取り違え | 子会社に向けた禁止規定を、そのまま親会社の取締役の法令違反と断定した | 条文の名宛人を確かめ、根拠を別に立てる |
| 自己申告の過少 | 丸写しの数を、甘い数え方で実測の半分に報告した | 生の値と除外後の値の両方を機械で出す |
| 置き換えによる浮き | 「つまり」を「すなわち」に替えただけの文が並んだ | `style-imitation.md` 5 |
| 有益な文の消失 | 体を変える書き直しで、分かりやすい決め文句が消えた | 規則8 |
| 範囲外の膨張 | 資料の範囲外の論点を詳しく書き、分量が1.6倍になった | 範囲外補足は1段落 |
| 派生物での断定 | 本文は「…とされる」「…と考えられている」。論点カードの当てはめの欄は「…に当たる。…にとどまる」 | 規則13。`derived_check.py` |
| 派生物での条文のずれ | 短答の根拠の欄に、本文が「働かない」と書いた側の条文を挙げた（正誤は正しい） | 規則13。結論を導く条文を書く |
| 判示の欄に資料の言い方 | 抜き書きは原文なのに、欄の文は資料の要約（判決「…を有し」→ 欄「…を行使すべきである」）。判決が続けて挙げた理由が落ちた | 規則14。`reason_table.py check --fulltext --source` |
| 帰結の文に補足の札がない | 資料の2つの立場を紹介した後、「したがって、…はいずれの立場によっても…にならない」とノートが結論を足した | 規則1。資料にない帰結は「（補足）」。`algorithms/hosoku-tag.md` |
| 接続の語を変えて理由にした | 資料「議論は錯綜しているが、本書では判例を中心に」→ ノート「錯綜しているので、判例を中心に」（逆接を理由に変えた） | 規則6。接続の語（が／ので／から）は資料のまま |
| 数値の申告のずれ | 索引の語数を、途中の版の値で報告した。字数の数え方を書かなかった | 規則15 |

## 3. 照合の作業ファイル
足した文ごとに、次の表を書く（`work/added.md`）。数が多いときは、難所の周り・判例の理由・まとめ・表・図を優先する。

| ノートの文（冒頭15字） | 種別（言い換え／例／まとめ／表／図／補足） | 資料の対応箇所（頁・冒頭の語） | 意味は同じか | 限定語・確度 |
|---|---|---|---|---|

この表は、独立点検（`verification.md` の点検B）にそのまま渡す。失敗の型の全体は `failure-catalog.md`、補足の札を付けるかの判断は `algorithms/hosoku-tag.md`。

## 4. 資料が無いとき
照合する相手が無いので、誤りは「記憶で書いた判例の理由・書誌」と「一般化」から出る。

- 判例の理由は、判決の原文か、信頼できる解説で確かめた範囲だけを書く。
- 判例ごとに「対になる判例」（同じ論点で結論が分かれる判例）を探し、両方の理由を並べてから関係を書く。
- 効力の範囲は例ごとに書く。
- 確かめられなかった事項は「未確認」として報告に回し、本文では断定しない。
