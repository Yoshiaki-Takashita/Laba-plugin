# 指標⑬　網羅率（基本指標・20点）

資料の「知識の単位」（定義、要件、判例の結論と理由、学説、具体例、例外、相互参照）が、ノートにあること。

## 1. 定義と測り方

- 点を付けるのは点検者。資料の知識の単位を一覧にし、各単位を「ある＝1／不十分＝0.5／ない＝0」で数える。
- 機械は上限の目安を出す。`inventory.py` が資料の見出し・判例・条文・相互参照・問いを一覧にし、`coverage_check.py` がノートと照合する。機械が見るのは、この5種の欠落だけである（定義・理由・例が落ちていても分からない）。
- 機械の誤検知（章の柱、本文の文が見出しと誤認されたもの）は、`--ignore ignore.json` で、理由を書いて除く。理由のない項目は除かれない。
- 換算：20 ×（網羅率 − 50）÷ 50。合格線95%。「資料を上回る」の判定には95%以上が要る。

## 2. 減点された実例の型

| 型 | 例 | 原因 |
|---|---|---|
| コラム・囲みが抜ける | 「すこし詳しく」「発展」の囲みが全部無い | 本文だけを読んだ |
| 判例が数件抜ける | 資料の脚注・括弧の中の判例 | 一覧を作らずに書いた |
| 理由が抜ける | 結論はあるが、資料が挙げた理由の2つ目が無い | 縮めた（機械では分からない） |
| 例外が抜ける | 原則は書いたが、「もっとも」以下が無い | 段落の後半を落とした |
| 学説が抜ける | 資料が紹介した反対説が無い | 判例・通説だけにした |
| 図表の中身が抜ける | 資料の表の行が、ノートの表に無い | 表を作り直した |
| 範囲の取り違え | 資料の複数の節のうち、一部だけを扱った | 題名だけを見た |
| 誤検知を黙って除く | 機械の欠落を、理由を書かずに無視した | 記録しなかった |

## 3. 9.5 に届く条件（網羅率99%以上に当たる）

1. `coverage_check.py` の欠落が0。除いた項目は、全部に理由がある（`coverage.json` の `ignored` に残る）。
2. 資料の知識の単位の一覧（作成者が作る。`inventory.md` に、定義・理由・例・例外・学説を手で足したもの）があり、各単位にノートの箇所（節番号）が書かれている。
3. コラム・囲み・脚注の内容が、「発展」などの形でノートにある。扱わないものは、理由を報告に書く。
4. 資料の表・図の中身（行・要素）が、ノートの表・図・本文のどこかにある。
5. 点検者の網羅率が99%以上。

## 4. 手順

1. 取り込みの直後に `inventory.py` を走らせ、`inventory.md` を目で見て補正する（見出しの拾い漏れ、コラム）。
2. 一覧に、定義・理由・例・例外・学説を手で足す。1単位1行。
3. 本文を書きながら、一覧の各行にノートの節番号を書く。書けない行が欠落である。
4. `coverage_check.py` を走らせ、欠落を1件ずつ見る。誤検知なら `ignore.json` に `{"item": "…", "reason": "…"}` を足す。
5. 分量を削った後（指標⑪）は、必ず走らせ直す。

## 5. 検査

```
python3 scripts/inventory.py SOURCE.txt --out checks/inventory.json --md checks/inventory.md
python3 scripts/coverage_check.py checks/inventory.json NOTE.txt --ignore ignore.json --out checks/coverage.json
```
`pipeline.py --coverage-ignore ignore.json` で回る。見る所：欠落の種類と件数、「誤検知として除いた項目」の数と理由。

## 6. 良い例・悪い例

- 良い例（ignore.json）：`{"item": "第12章　多数当事者訴訟", "reason": "資料の各頁の柱（章名の繰り返し）で、見出しではない"}`
- 悪い例：欠落2件を「誤検知」とだけ報告し、何をなぜ除いたかが残っていない。
- 良い例（一覧の1行）：「理由｜12-3-3：申出を原告に限る理由（二重敗訴の危険は原告だけが負う）｜ノート 12-3-3 第2段落」
- 悪い例：見出しと判例が全部あるので「網羅率100%」と報告する。→ 機械の値は「機械照合の網羅率」と書き、点検者の網羅率とは分ける。
