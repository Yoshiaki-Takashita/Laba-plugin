# 指標③　判例理由の忠実度

ノートが「判決の理由」として書いたものが、判決文にあること。資料（教科書等）がその判例に付けた説明や、ノートが足した説明と、区別されていること。理由を述べていない判決は、そう書かれていること。

## 1. 定義と測り方

- 点を付けるのは点検者。判例ごとに、ノートの理由の欄を判決文と照らす。
- 機械は出所を整理する。
  - `reason_table.py`：判例ごとの「理由の出所表」（`reasons.json`）を作り、検査する。判決文の全文（`case_lookup.py --save`）があれば、次の3つを照合する。
    - 抜き書きが全文の中に実在するか。
    - 該当箇所の控え（頁・段落の冒頭）が、抜き書きの実際の位置と合うか。控えのない点は所見。
    - 欄の文（出所表の各点の `text`、ノートの表の「判決が挙げる理由」の欄・［判示］の札の文）に出る術語が、その判決の全文にあるか。全文に無い術語が2語以上ある文、資料の言い回しと一致する語が1語でもある文は所見（「欄の文が判決文の語でない」）。
  - `reason_source_check.py`：ノートの表の列名・札（［判示］［資料］（補足））と、「理由を述べていない」判決の直後の理由文を見る。`--reasons` を渡すと、判示を書いたセルごとに、出所表に該当箇所の控えがあるかを見る（控えのないセルは所見）。
- 換算（点検者の目安）：全判例で一致し出所が分かれている＝10。判例の1割で資料の説明が判決の理由に混ざる＝7。2割＝5。判決の結論や主文を取り違えた判例が1件でもあれば、誤り（指標⑮）にも数える。合格線8。

## 2. 減点された実例の型

| 型 | 例 | 原因 |
|---|---|---|
| 資料の説明を判決の理由として書く | 資料が「…ということである」と解説した部分を、「判例は…を理由とする」と書く | 資料の地の文と判示を区別しなかった |
| 理由を述べていない判決に理由文を付ける | 「原審の判断は正当として是認できる」だけの判決に、「…からである」と続ける | 資料の説明をそのまま受けた |
| 記憶・一般論の理由 | 判決文にない、もっともらしい理由 | 判決文を見ていない |
| 列が1つ | 表の列名が「判例が挙げる理由」だけで、判示と資料の説明が同じ欄にある | 表の形を先に決めた |
| 一部の判示だけを引く | 複数の判示事項のうち、結論に合う1つだけ | 要旨だけを見た |
| 順序づけの持ち込み | 判決文にない「主たる理由は」「補強として」 | 資料の整理を判示と混ぜた |
| 抜き書きが原文と違う | 照合用の抜き書きを、要約や現代の表記で書いた | 原文から写していない |
| 当たれない判決に「判示」 | 大審院判決など、判決文を見ていないのに［判示］の札を付けた | 出所の状態を記録していない |
| 抜き書きは原文、欄の文は資料の言い方 | 判決「全員が共同して訴訟追行権を有し」→ 欄「全員が共同して訴訟追行権を行使すべきである」（資料の言い方）。抜き書きは実在するので、旧い検査を通った | 抜き書きを控えた後、欄の文は資料の要約から書いた。欄の文と抜き書きを照らしていない |
| 判決の理由の一部が落ちる | 判決が「かつ、…訴訟制度のたてまえからするも」と続けた理由を、資料が挙げていないので載せなかった | 資料が挙げた点だけを判決文で確かめた。判決文の理由の段落を最後まで読んでいない |
| ［判示］の札の中に資料の要約 | 資料が①②③と整理した理由を、そのまま［判示］①②③と書いた（②は判決文では別の言い方） | 札を付ける前に、点ごとに判決文の語を確かめていない |

## 3. 9.5 に届く条件

1. 理由の出所表（`reasons.json`）があり、ノートに出る全判例が載っている。
2. 各判例の状態が、次の4つのどれかに決まっている。「判決文未確認」が0。
   - 判示を確認：判決文で理由を確かめた。理由の1点ごとに、短い抜き書き（125字以内、原文の表記のまま）と、判決全文の該当箇所の控え（頁、または段落の冒頭の語句）がある。確かめた先がある。
   - 判決は理由を述べていない：判決文を見て、理由が書かれていないことを確かめた。結論だけを述べた箇所の抜き書きと該当箇所の控えがある。
   - 判決文に当たれない：公開の判決文が無い（大審院、未登載など）。理由は資料の説明として書く。
   - （判決文未確認：まだ見ていない。これが残っているうちは9.5に届かない。）
3. 抜き書きが、保存した全文の中に実在する（`reason_table.py check --fulltext` の「抜き書きの不一致」0）。該当箇所の控えのない点が0で、頁・語句の不一致が0。
3-2. 欄の文が判決文の語で書かれている（「欄の文が判決文の語でない」0）。①②③と番号を振った理由は、番号ごとに抜き書きがある。判決が挙げた理由を、資料が挙げていないという理由で落としていない。資料の言い方（要約、順序づけ、「主たる理由」）は「資料の説明」の欄に書く。
4. ノートが「判決が挙げる理由」「［判示］」として書いた理由は、状態が「判示を確認」の判例に限られている。
5. 「判決は理由を述べていない」「判決文に当たれない」判例の理由は、「資料の説明」または「（補足）」として書かれている。
6. 出所表を、巻末の表（判例／判決が挙げる理由／資料の説明／確かめた先）としてノートに載せている。本文の理由と表の理由が食い違わない。
7. 点検者が、判決文と照らして9.5以上を付けている。

## 4. 手順

1. `reason_table.py init NOTE --out reasons.json` で雛形を作る。ノート中の判例と、その近くにある理由の文が入る。
2. 判例ごとに、`case_lookup.py 昭和43・3・15 --save work/fulltext` のように年月日で引き、全文を取る（1件ずつ、間隔を空ける。`--grep 語` で理由の箇所を探せる）。取れた全文は作業用であり、ノートやスキルに貼らない。
3. 全文を読み、理由の部分を探す。理由の段落は最後まで読む（「かつ」「のみならず」「また、他面」で続く理由を落とさない）。見つかったら、理由の1点ごとに `points` に `text`（ノートの欄に書く文。判決文の語で書く）と `excerpt`（原文の抜き書き）を書き、`holding`（表に載せる文）と `checked_against` を埋め、状態を「判示を確認」にする。
3-2. `reason_table.py locate reasons.json --fulltext work/fulltext --write` で、抜き書きごとの該当箇所（頁・段落の冒頭）を `where` に書き込む。抜き書きが全文に無い点には書き込まれないので、抜き書きを原文から写し直す。
4. 理由が書かれていなければ「判決は理由を述べていない」。資料が付けている説明は `source_explanation` に書く。
5. 全文が取れなければ「判決文に当たれない」。ノートの本文で、その判例の理由を［判示］として書いていないかを見直す。
6. `reason_table.py check reasons.json --note blocks.json --fulltext work/fulltext --source SOURCE.txt` で所見0にする。「欄の文が判決文の語でない」が出たら、その文を判決文の語で書き直す（除外の一覧は置かない）。資料の言い方を残したいときは、「資料の説明」の欄に移す。
7. `reason_table.py block reasons.json` で巻末の表を作り、ノートに足す。本文で理由を書いている箇所は、表と同じ出所の書き分けにそろえる。

## 5. 検査

```
python3 scripts/reason_table.py locate reasons.json --fulltext work/fulltext --write
python3 scripts/reason_table.py check reasons.json --note blocks.json --fulltext work/fulltext --source SOURCE.txt --out checks/reason_table.json
python3 scripts/reason_source_check.py NOTE.txt --blocks blocks.json --reasons reasons.json --out checks/reason.json
```
見る所：状態ごとの数、出所が確定した割合、該当箇所の控え（点の数・控えなし・不一致）、抜き書きの実在・不一致、「欄の文が判決文の語でない」、判示を書いたセルの数と控えのあるセルの数、所見。`pipeline.py --reasons reasons.json --fulltext DIR` でまとめて回る。

機械が見ないこと：欄の文の意味が判決文と同じか（術語がそろっていても、主語や限定が違うことがある）。原審の判断を是認しただけの判決で、理由が原審にあるときの扱い（「判決は理由を述べていない（原審の判断を正当とするにとどまる）」と書き、原審の理由を判決の理由として書かない）。点検者が判決文で読む。

してはいけない上げ方：判決文を見ずに状態を「判示を確認」にする。抜き書きを裁判要旨から取る（要旨は裁判所の編集であり、判決の理由そのものではない）。抜き書きだけ原文から取り、欄の文は資料の要約のままにする。

## 6. 良い例・悪い例

- 良い例（表）：

| 判例 | 判決が挙げる理由 | 資料の説明 |
|---|---|---|
| 最判昭和○・○・○ | ［判示］共同相続人の義務は不可分債務であり、各自が全部について義務を負う。 | 全員を被告にしなければならないとすると、原告の負担が重いという考慮もある、とされる。 |
| 最判平成○・○・○ | 判決自体は理由を述べていない。 | 判決の矛盾を避ける必要が大きい場面だから、と説明される。 |

- 悪い例：列が「判例の理由」1つで、「全員を被告にしなければならないとすると原告の負担が重いからである」と書く。判決文にあるのか、資料の説明なのかが分からない。
- 悪い例：「判例は、手続保障の観点から、…とした。」判決文に「手続保障」の語が無いのに、判例の理由として書いている。
