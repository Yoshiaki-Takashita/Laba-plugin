# 指標⑩　独自性（非転写）

地の文が、資料の丸写しではなく、自分の言葉で書かれていること。ただし、術語・条文・判例の書誌・定義は、資料のまま書く。

## 1. 定義と測り方

- 機械だけで測る。
  - `match_check.py`：資料とノートの連続一致を2つの値で出す。raw（正規化した全文の、20字以上の一致）と、filtered（書誌・条文・定義文を除き、術語を1字に畳んでから数えた値）。点に使うのは filtered。raw は必ず併記する。
  - `word_swap_check.py`：語を置き換えただけの文、資料に出ない語、解説書に出にくい言い回しを、文単位で拾う（独自性の裏面。一致を下げようとして文体が浮いていないか）。
- 換算：10 − max(0,（1万字あたりの20字一致の数 − 5）÷ 5）−（最長の一致が50字超なら5、30字超なら2）− max(0,（12字一致率 − 10）÷ 2）。合格線7。

## 2. 減点された実例の型

| 型 | 例 | 原因 |
|---|---|---|
| 段落ごと写す | 資料の段落を、文末だけ変えて写す（最長一致が100字を超える） | 文体を合わせるために資料を下敷きにした |
| 理由文を写す | 判例の理由の説明を、資料の文のまま | 理由は変えてはいけないと考えた（変えてよいのは言い回し、変えてはいけないのは中身） |
| 術語を言い換える | 一致率を下げるために「合一確定」を「統一的な確定」に | 検査を通そうとした |
| 語の置き換えだけ | 「すなわち」を「つまり」に、「したがって」を「そこで」に替えただけ | 文の構造が資料のまま |
| 順序まで同じ | 文は違うが、段落の中の文の順・例の順が資料と全部同じ | 1文ずつ書き換えた |
| 報告で raw を隠す | filtered の値だけを報告する | 都合のよい値を選んだ |

## 3. 9.5 に届く条件

1. filtered で、20字一致が1万字あたり5か所以下（約7.5か所までは9.5点に収まる）、最長30字以下、12字一致率10%以下。
2. raw の値を、報告に併記している。raw の最長一致が定義・条文・書誌以外で50字を超える箇所は、1件ずつ読んで書き直している。
3. `word_swap_check.py` の「置き換えの型」が0。
4. 術語・条文の文言・定義は、資料のままである（言い換えていない）。
5. 段落の組み立て（主題文→理由→例→限定）が、ノートの方針で組まれている。資料の段落を1文ずつ書き換えたものではない。

## 4. 手順

1. 資料を読み、節ごとに、要点を自分のメモ（箇条書き）にする。本文は、資料ではなくメモを見て書く。
2. 術語、条文、定義、書誌は、資料から写す。
3. 書き終えたら `match_check.py -v` で、filtered の一致を長い順に見る。30字を超えるものから、文の組み立てを変える（主語を替える、理由と結論の順を替える、2文を1文にする）。
4. 文体の数値（指標⑯）が崩れないかを、直すたびに確かめる。文体を資料に合わせる作業と、一致を下げる作業は、逆向きに働く。両方を同時に見る。
5. `word_swap_check.py` で、置き換えで済ませた文を拾う。

## 5. 検査

```
python3 scripts/match_check.py SOURCE.txt BODY.txt --out checks/match.json -v
python3 scripts/word_swap_check.py BODY.txt --source SOURCE.txt --out checks/swap.json -v
```
見る所：raw と filtered の両方（20字一致の数、最長、12字一致率）、分量比。置き換えの型。

してはいけない上げ方：術語を言い換える。語順を不自然に入れ替える。定義を自分の言葉に直す（指標⑤が下がる）。

## 6. 良い例・悪い例

- 資料の文（例）：「この場合、原告は、いずれの被告に対する請求についても敗訴するおそれがある。」
- 良い例：「原告は、両方の請求で敗訴することがあり得る。」（術語は保ち、組み立てを変えている）
- 悪い例：「この場合には、原告は、いずれの被告に対する請求についても敗訴するおそれがあるといえる。」（文末を足しただけ）
- 悪い例：「このケースでは、訴えた側は、どちらの相手方に対する求めについても負ける危険がある。」（術語まで言い換えている）
