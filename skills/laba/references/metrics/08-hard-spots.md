# 指標⑧　難所の可視化率

読者がつまずく箇所（難所）を先に書き出し、その全部に、図・表・ざっくり理解のどれかで手当てをしていること。手当てが効いていること。

## 1. 定義と測り方

- 作成者が「難所の一覧」を作り、点検者が確かめる。機械は測れない。
- 一覧の形：［№／難所（どこで、何がつまずきになるか）／難所の型／手当て（図N・表N・ざっくり理解の位置）／効いているか（点検者が記入）］。
- 換算：10 ×（手当て済みで効いている数）÷（書き出した数）。点検者は、一覧に無い難所を見つけたら分母に足す。合格線7。「資料を上回る」の判定には7以上が要る。
- 図の作り方・型の選び方は `../figures.md` と `../algorithms/figure-type.md`、ざっくり理解は `../zakkuri.md`。この文書は、指標としての数え方だけを扱う。

## 2. 減点された実例の型

| 型 | 例 | 原因 |
|---|---|---|
| 描きやすい図だけ描く | 当事者関係図が並び、規律の分かれ目が図になっていない | 難所を書き出さずに作図した |
| 難所の選び方が甘い | 「定義が長い」を難所にし、「2つの規律の適用の順」を挙げない | 資料の見出しから機械的に拾った |
| 手当てが難所に当たっていない | 難所は「誰に効力が及ぶか」なのに、図は時系列 | 型の選び方を誤った |
| 図が本文と逆に読める | 矢印の向き、勝ち負けのラベルが本文と逆 | 図を本文と照らしていない（これは誤りにも数える） |
| ざっくり理解が言い直し | 本文と同じ語で繰り返すだけで、噛み砕いていない | 本文を縮めて作った |
| 一覧が後付け | 図を描いた後に、図に合わせて難所を書いた | 順序が逆 |
| 手当ての偏り | 前半の節に図が集まり、後半の難所に何もない | 息切れ |

## 3. 9.5 に届く条件

1. 難所の一覧が、作図の前に作られている（一覧の日時・版が、図より前）。数は、資料20頁でおよそ6〜10。
2. 難所は、次のどれかの型で特定されている：分岐（場合分けが3つ以上）／対比（似た制度の違い）／時間（順序・期限）／主体（誰に効力が及ぶか）／抽象語（定義だけでは像が浮かばない）／原則と例外の入れ子／判例の射程。
3. 全部の難所に手当てがあり、手当ての型が難所の型に合っている（分岐→流れ図か表、対比→比較図か区別表、時間→時間軸、主体→動きの図、抽象語→ざっくり理解と記号事例）。
4. 図・表のすべてについて、本文との照合表（要素／本文の根拠／限定の語）がある。逆に読める図が0。
5. 点検者が、一覧の選び方を妥当とし、全部の手当てを「効いている」と判定している。

## 4. 手順

1. 資料を読み終えた段階で、自分が読み直した箇所、資料が「もっとも」「ただし」を重ねている箇所、場合分けが多い箇所を書き出す。
2. それぞれに型を付ける。型が付かないものは、難所として弱い。
3. 型から手当てを選ぶ。1つの難所に、図とざっくり理解の両方が要ることもある。
4. 手当てを作ったら、一覧の「手当て」の欄に位置を書く。
5. 点検者に、一覧とノートを渡す（`../reviewer-prompts/score-16.md` のE）。点検者は listed／handled を数える。

## 5. 検査

機械の検査は無い。`fig_lint.py` は図の形（重なり・はみ出し）だけを見る。`reviewer.json` の `indicators.hard_spots` に `{"listed": 8, "handled": 8}` の形で書かれた値を、`score.py` が点にする。一覧が無ければ「難所の一覧が未提出」として未採点になる。

## 6. 良い例・悪い例

- 良い例（一覧の1行）：「№3／12-4-3：1人が上訴したとき、上訴しなかった人がどういう地位になるか。原則と、判例が例外とした類型が入れ子になっている／型：原則と例外の入れ子＋主体／手当て：表5（類型ごとの扱い）、ざっくり理解（12-4-3 の末尾）」
- 悪い例：「№3／必要的共同訴訟は難しい／手当て：図2」→ どこで何がつまずきになるのかが特定されていない。
- 悪い例：難所を5つ書き出し、手当ては3つ。残りの2つを一覧から消して「5分の5」にする。→ 一覧は消さず、手当てを足すか、未手当てのまま報告する。
