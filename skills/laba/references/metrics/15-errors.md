# 指標⑮　誤り（基本指標・15点）

結論・要件・判例の結論と理由・条文・論理に、誤りがないこと。

## 1. 定義と測り方

- 点を付けるのは点検者だけである。機械の検査は形しか見ないので、全部通っても、誤りが無いことにはならない。
- 重大度と減点：

| 重大度 | 定義 | 減点 |
|---|---|---|
| 重大 | 結論・要件・判例の結論を誤る。読者が誤った知識を持つ | 6 |
| 中 | 理由のすり替え、論理の逆転、名宛人・段階の取り違え、図が本文と逆に読める | 3 |
| 軽微 | 表記、補足表示の漏れ、体裁、限定語の軽い脱落 | 1 |

- 15点から引く。合格線：重大0、中1以下。「資料を上回る」には、重大0・中1以下が要る。
- 点検は3種（`../verification.md`）：A＝法的正確さ（条文・判決文と照らす）、B＝足した文の意味照合（資料と照らす）、C＝書き手の判定。

## 2. 減点された実例の型

`../failure-catalog.md` の50の型が、実際に起きた誤りの一覧である。件数の多かったものを挙げる。

| 型 | 重大度 | どこで起きるか |
|---|---|---|
| 判例の理由が判決の理由と違う | 中〜重大 | 判例の4段の「理由」。表の理由の欄 |
| 確認できない判決の結論を推測で書いた | 重大 | 下級審、古い判決 |
| 条文の限定の語が落ちた | 軽微〜中 | 条文の要約、図のラベル、カードの規範 |
| 運用上の要請を法的な禁止として書いた | 中 | 確度の語を強めた箇所 |
| 条件の句が抜け、理由が逆に読めた | 中 | 文を縮めた箇所 |
| 図が本文と逆に読める | 中 | 矢印の向き、勝ち負けのラベル |
| 足した例の帰結が誤り | 重大 | 「（補足）」の例、ざっくり理解の例 |
| 短答の命題の正誤が誤り | 重大 | 巻末の短答の表 |

誤りは、資料を写した部分ではなく、足した部分（言い換え、補足、例、図、ざっくり理解、巻末の表）で起きる。

## 3. 9.5 に届く条件（15点中14点以上＝軽微1件まで）

1. 独立点検A・Bを、本文を書いていない点検者が、最後の版に対して行っている。
2. 重大0・中0・軽微1以下。
3. 足した文（「（補足）」、ざっくり理解、図題、足した例、巻末の表）の全部について、根拠（資料の箇所、条文、判決文）との照合表がある（`../added-text-safety.md` 3）。
4. 判例の理由は出所表で確かめ（指標③）、条文は現行の条文と照らし（指標①）、短答の命題の正誤は条文・判決文で確かめている。
5. 点検者の指摘のうち、記憶に基づくものは、原典で確かめてから直している（点検者も誤る）。
6. 直した後の版が、もう一度点検を受けている。受けていなければ、報告に「最後の版は点検を受けていない」と書く。

## 4. 手順

1. 書くとき：資料にあることは資料の語で、足すことは「（補足）」を付けて根拠とともに書く。確かめていないことは書かない。
2. 機械の検査を全部通す（形の誤りを先に除く）。
3. 点検者に、点検A・Bを頼む（`../reviewer-prompts/legal-accuracy.md`、`added-text.md`）。作成者の自己検査の結果は、根拠として渡さない。
4. 指摘を、重大・中から直す。直した箇所の前後を読み直し、図・表・カード・短答の同じ内容の箇所も直す。
5. 機械の検査を走らせ直し、大きく直したなら点検をもう一度頼む。

## 5. 検査

機械の検査は、誤りの候補を出すだけである：`statute_check`（同じ条文に向きの違う説明）、`reason_table`（抜き書きの不一致）、`certainty_check`（留保が消えた文）、`tf_items`（確度の注意）、`fig_lint`（図の形）。誤りの件数は、`reviewer.json` の `errors` に点検者が書く。

点検者を立てられないとき：誤りの指標は「未採点」とし、判定を出さない。作成者が自分で読み直した結果を、点検として報告しない（`../verification.md` 6）。

## 6. 良い例・悪い例

- 良い例（報告）：「独立点検A・Bを、版3に対して実施。指摘は重大0・中1・軽微3。中1件（12-4-3 の理由文で条件の句が抜けていた）を直し、版4とした。版4は点検を受けていない。」
- 悪い例（報告）：「機械の検査がすべて通ったので、誤りはない。」
- 悪い例（報告）：「自己点検の結果、誤り0件。」
