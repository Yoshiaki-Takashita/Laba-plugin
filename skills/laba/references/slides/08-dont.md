# しないこと

機械で確かめられるものには、`deck_lint.py` の検査名を付けた。

## 見た目

| しないこと | 理由 | 検査 |
|---|---|---|
| 影つきの角丸カード | 既定の見た目。内容より飾りが目に入る | decoration |
| 丸の中に入れたアイコン、ピル型のタグ | 同上 | 目視 |
| グラデーション、斜めの帯、色の縦バー | 同上 | decoration |
| 部の扉スライド | 枚数だけ増える。右上の大項目名で足りる | 目視 |
| 決めた色以外の色 | 色に意味がなくなる | off-palette |
| 文全体を強調の色にする | どこが要点か分からない | accent-heavy（1枚の4割超）。目安は2割まで |
| 正誤・賛否を色で分ける（○を緑・青、×を赤） | 白黒で刷ると区別できない。色の見分けにくい人に伝わらない | 目視（tf_check は形で区別する） |
| 書体を2種類以上使う | 揃わない | 目視 |
| 箇条書きの機能（bullet） | 字下げと記号が環境で変わる | decoration |
| 絵文字 | 書体で形が変わる | 目視 |

## 中身

| しないこと | 理由 |
|---|---|
| 金額・数字だけを大きく見せる | 数字より、だれが何を負ったかが大事。法的地位の表にする |
| 「前の審級から何が変わったか」の差分表を審級ごとに作る | 1行の要点（→）で足りる |
| 各審級がどの説かの位置づけ表 | 学説の枚と重複する |
| 人名（学者・裁判官）を大きく出す | 読んでいない文献の著者名は出さない。出すときも小さく |
| 条文・判例を並べるだけの枚 | 「本件では」がない枚は、聞き手に残らない |
| 判旨の全文を1枚に載せる | 読めない。構造の表にして、全文は読み上げる |
| 1枚に2つの問い | 分ける |
| 本文（レジュメ・ノート）にない内容を足す | 発表で突かれる。スライドは本文の要約である（`scripts/hanrei/sync_check.py` の content-not-in-resume） |
| 限定・確度の言い方を言い切りに変える（「及ぶとは読めない」→「及ばない」） | 結論が言い過ぎになる（同 hedge-dropped） |
| レジュメの小見出しを飛ばす（(1) の次が (3)、「(3) 本件の争点」の枚がない） | 聞き手がレジュメの場所を見失う（同 sub-missing、sub-jump） |
| 読んでいない文献を参考文献に載せる | `../hanrei/02-citation-grade.md` |

## 図

| しないこと | 理由 | 検査 |
|---|---|---|
| 図を画像で貼る（単色の小さいピクト画像は除く）。相関図・表を縮めた小さな画像、同じ画像を並べたもの、横長の画像も同じ | 直せない、積めない、文字が小さい | picture |
| 配色の中の濃い色（基調・強調・灰）で枠を塗り、白抜きの字にする | 決まりは白地＋枠線。塗りが多いと強調が効かない | fill-dark |
| 相関図を、当事者・時系列の後に置く。相関図なしで段を追う | 全体の地図がないまま、細部を聞くことになる | 目視（`04-step-reveal.md`） |
| 向きのない関係（親子・夫婦・所有）に矢印を使う | 何かが動いたように見える | 目視（`arrow: false`） |
| 線が、ほかの当事者の上を通る | 関係が読めない | 作成時に止まる |
| 図を左に片寄せる（最初の段の当事者を左の列にだけ置く） | 右半分が空く | 作成時の知らせ |
| 矢印を交差させる | 関係が読めない | 目視 |
| ラベルを矢印や人物に重ねる、枠と枠を重ねる | 読めない | overlap |
| 1枚の図に当事者7人以上、関係8本以上 | 追えない | 目視 |
| 段ごとに当事者の位置を動かす | 積み上げが分からなくなる | 目視（ビルダーは動かさない） |
| 全部の関係を強調の色にする | 新しい関係が分からない | 目視 |
| ラベルに日付・金額を詰め込む | 長くて置けない。帯に書く | 作成時の警告 |

## 文字

| しないこと | 理由 | 検査 |
|---|---|---|
| 語・条文番号・判例の表記の途中で改行する（「41条1項・2／項」「…3号／551頁」「特段の／事情」） | 読みにくい。番号を読み違える | bad-break、render-break（作成時にも止まる） |
| 1〜2字だけの行を作る（「Y2に／は／抗弁」） | 同上 | short-line、render-short |
| 文字を小さくして押し込む（本文・条文 14.5pt 未満、表 13pt 未満、図の中の注 10pt 未満） | 後ろから読めない | font-small、font-floor（作成時にも止まる） |
| 枠からはみ出す | — | render-outside、below-body、out-of-slide（描画できないときは text-overflow） |
| 枠を本文の領域いっぱいに広げて、中を空ける | 内容がないのに大きく見せている | frame-empty |
| 下半分が空いた枚 | 内容が足りない（1枚 150〜230 字が目安） | sparse、作成時の知らせ |
| 見出しを2行にする | 番号が追いにくい | 作成時の警告 |

## 進め方

| しないこと | 理由 |
|---|---|
| レジュメより先にスライドを作る | 見出しが揃わない。レジュメが固まってから作る |
| 表紙の氏名・日付・所属を推測で埋める | 仮の文字にして、渡すときに伝える |
| 画像にして見ずに渡す | 重なりと改行は、見ないと分からない |
| 下書きの印（`_todo`）や仮の文字（「（役割）」「（…を書く）」「（書誌は…確認して書く）」）、作る人への指示文（「ここに設例の結論を入れる」「※ 登載誌は…確かめてから書く」「要確認」）を残して渡す | 作業の跡が発表で映る（placeholder。作成時にも止まる） |
| `--draft`・`--allow-warn` を付けて作ったものを渡す | 検査を外しただけで、直っていない |
| スキルの中の文書や道具の名前（ファイルの場所）をスライドに書く | 聞き手に関係がない |
| 参考にした資料の色・図形を写す | 構成と文字の使い方だけ参考にする |
| 利用者が PowerPoint で直した版を、作り直しで上書きする | 直した所が消える（`../hanrei/09-revision.md`） |
