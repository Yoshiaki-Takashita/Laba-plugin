## 採点の手順

1. `deck_lint.py 発表.pptx --json lint.json` を走らせる。項目 1・3・5・6・7・8 の機械で測れる部分は、この結果から付ける。
2. error 0 でも、全枚を画像にする（下の「error 0 は『崩れがない』ことの証明ではない」の表の種類を必ず見る。`soffice --headless --convert-to pdf` → `pdftoppm -r 70 -png`）。12枚ずつの一覧にして、まず全体の調子（余白のむら、字の大きさのむら）を見る。次に1枚ずつ、等倍で読む。
3. 1枚ごとに「この枚は何を言う枚か」を1文で言ってみる。言えない枚に印を付ける（項目2）。
4. 本文（レジュメ・ノート）と並べて、番号・判例の表記・結論の言い方を照らす（項目 8・10）。
5. 点と、弱い項目・その枚の番号・直し方を記録する。

## error 0 は「崩れがない」ことの証明ではない

`deck_lint.py` と `build_deck.js` が error 0 でも、それは「機械で見られる種類の崩れが見つからなかった」というだけである。新しい種類の崩れの検出は約4割にとどまる（独立採点 第4回）。**全枚を画像にして、1枚ずつ目で見る工程は省かない。** 次の種類は機械では見ていない（または見落としが多い）ので、目視の項目として必ず見る。

| 種類 | 見ること |
|---|---|
| 図形の重なり | 枠・箱・ピクト・矢印どうしが重なっていないか（文字が重ならなくても）。区切りの線が箱を貫いていないか |
| 帯の下端・枚の下端で切れる行 | 下部の帯や枠の下で、行が半分で切れていないか |
| 白字・灰色 | 白地の白字、本文全体が灰色、など読めない色になっていないか |
| 書体と飾り | Yu Gothic 以外の書体（明朝など）、斜体・下線・破線・文字の輪郭線、自動縮小（fontScale）が入っていないか |
| 判例研究の決まり | 条文の枠に条文番号があるか。審級・判旨の枚に出典の行（判例集の巻号頁）があるか。相関図が時系列の前にあるか。強調の色が、その枚の要点（1〜3語、新しい関係）に付いているか |
| 意味 | 1枚に2つのメッセージがないか。ピクトの取り違え・結論の逆転がないか |

非表示の枚は、描画後の検査をしない（`hidden-slide` の warn）。発表で出す枚なら表示に戻して検査し直す。

## 検査の較正（完成版が error 0 で通るように）

検査の閾値は、完成版として認められた発表資料（48枚）が通るように決めてある。完成版が error になる規則は、規則のほうが誤りである。最初の版の検査を完成版に掛けると **error 78、warn 32** が出た。規則を次のように直し、**error 0、warn 6** になった。

| 検査 | 前の規則 | 完成版での件数 | 直した規則 | 後 |
|---|---|---|---|---|
| picture | 画像はすべて error | 58 | 1.3 インチを超える画像だけ error。小さい単色のピクト画像は許す（完成版のピクトは 0.6〜1.1 インチの画像） | 0 |
| off-palette | 配色の表にない色は error | 9（#000000） | 黒（#000000）は許す（表の既定の罫線） | 0 |

| overlap | 箱の大きさの見積りで比べる | 4（役割と矢印のラベル） | 描画された行の位置で比べる | 0 |
| font-small | 12pt 未満の文字が1つでもあれば warn | 21 | 12pt 未満の黒い文章（25字以上の箱）が、その枚の 25% を超えたら warn | 1（相関図） |

## 判例研究の発表に加える確認（点には入れない）

- 相関図が、当事者・時系列の前にある。関係の種類で左右に分かれ、争いの中心の関係だけが強調の色になっている。
- 時系列が1段ずつ積まれ、最後にまとめの表がある。
- 争点の枚（レジュメの「本件の争点」）と、考察の小見出しの数だけの枚がある（`sync_check.py` の sub-missing が 0）。
- 三審の流れが、1枚で分かる。
- 考察の枚が、事実から問いへの筋道になっている。
- 発表時間に対して、進行表の合計が ±10% に収まる。
