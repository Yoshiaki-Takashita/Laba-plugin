# スライドの型（33種）

構成の JSON では、1枚ごとに `type` と中身を書く。座標は書かない。型が配置を決め、文字は枠に収まる最大のサイズになる。型は `scripts/slides/lib/layouts.js` にある。

どの型にも共通の項目：`heading`（左上の見出し。レジュメの番号と同じに）、`notes`（発表原稿。ノート欄に入り、時間の見積りに使う）、`time`（秒。原稿がないときの目安）、`note`（枚の下の隅に置く注。専門用語の説明など。9pt・灰・太字にしない。1〜2行）、`key`（下の1行。「→」で始まる結び。縦に積む型で使える）。見出しが「5. 110条…」のように番号の直後が数字で始まるときは、作るときに空きを広げる（「5.110条」と読めないように）。`{"type":"section","name":"１．前提知識"}` はスライドを作らず、右上の大項目名を切り替える。

文字の中では `{r:…}`（強調）`{b:…}`（基調）`{g:…}`（灰）`{n:…}`（太字にしない）が使える。行頭の「◎」は型が付ける（自分で「→」「・」を書いた行はそのまま）。

## 型の選び方

| 伝えたいこと | 型 |
|---|---|
| 条文と、その読み方 | statute |
| 用語の定義 | definition |
| 当事者の全体の地図（親族と取引など、関係の種類が2つある） | sokan（時系列の前に置く） |
| だれとだれが、どういう関係か | relation、parties |
| 出来事の順序（だれが何をしたか） | timeline（段ごとに1枚）、timeline_table |
| 期間の長さ（いつからいつまで） | time_axis |
| ある審級が何を判断したか | instance |
| 判旨がどう組み立てられているか | holding_structure |
| 手続・審級の流れ | instance_flow |
| 2〜4個のものの違い | compare_table、doctrine_lr、axis |
| 要件を順に当てはめて結論が分かれる | branch |
| 争点がどこに絞られるか | issues |
| 判決の意義 | significance |
| 解説の要点 | commentary |
| 反対の立場と、その評価 | opposition |
| 事実から問いへの筋道 | reasoning_chain |
| 言い切る結論 | conclusion |
| 難所の手ほどき | zakkuri |
| 設例の主張の組み立て | yoken |
| 答案に使う形の整理 | ronten_card |
| 判例の一覧 | case_matrix、case_ref |
| 質問への備え | qa |
| 知識の確認（短答式の正誤） | tf_check |
| どれにも当たらない | points、blocks |

## 型の使い分けと密度（完成版の水準に合わせる）

完成版（48枚）は、1枚平均 189 字で、図の型が広い（相関図、時系列の段、当事者の関係、流れ、表、判旨の構造、場合分け）。文字だけの枚が続くと、発表で何を見ればよいかが分からなくなる。次を目安にする。

- 1枚の文字数は 150〜230 字。120 字未満の枚は、前後とまとめるか、「本件では」の枠・→ の1行を足す（作成時に、75 字未満の枚と平均 150 字未満の資料を知らせる）。330 字を超えたら分ける。
- 大項目（section）ごとに、図の型（sokan、relation、parties、timeline、time_axis、instance_flow、holding_structure、branch、compare_table、doctrine_lr、axis）を1枚以上入れる。
- 同じ型を3枚続けない（timeline の段は1つと数える）。points・conclusion・opposition など文字だけの型は、全体の 4 割まで。
- 二つの立場を見比べる内容は doctrine_lr、三つ以上の観点で比べる内容は compare_table にする（ノートの図題に「見比べ」「左右」「対比」があれば note_to_deck.py も compare_table の雛形を出す）。
- 判例研究では、調査官解説（判決の理由と解説の補いを分ける）と、学説の対立軸ごとに1枚を置く。レジュメの節と1対1に対応させる（sync_check.py）。
- 長い条文（statute が4行を超える）は、本件にかかわる項・号だけを載せ、残りは原稿（notes）で触れる。文字を小さくして全文を載せない（本文・条文の下限は 14.5pt）。
- 同じ2人の間に関係を2本以上引いてよい（relation・timeline の図は、線を平行にずらして描く）。3本を超えるなら、段（timeline）を分ける。
- timeline の各段の label に丸数字を書かない（段の番号から「①」が付く。書いても外して知らせる）。

## 各型の項目

### 1 cover（表紙）
`kind`（「判例研究」「復習スライド」など）、`theme`（「〜テーマ〜」）、`info`（判決情報などの行）、`affiliation`・`presenter`・`date`（省略時は config から。空なら仮の文字）。
配置：左上に所属（18pt）、中央に kind（40pt）、theme（26pt）、info（16pt）、報告者（22pt）、右下に日付。飾りは置かない。

### 2 toc（目次）
`items`：[{`title`, `sub`:[…]}]。左に基調の色の縦帯（幅1.6）、右に章立て。行が10行以上なら2列（章の見出しの直前で分ける）。
上限：全体で18行。超えるなら節を省き、章だけにする。

### 3 statute（条文）
`statutes`：[{`name`, `text`:[…]}]（1〜2個）、`points`：[…]（◎の要点。2〜3行）、`here`：[…]（強調の枠。2行）、`hereLabel`（既定「本件では」。ノートでは「設例では」）。
配置：上から、条文の枠（条文名は基調の色・太字、本文は太字にしない）→ 要点 → 強調の枠。
上限：条文は合計4行、要点3行、強調の枠2行。悪い例：条文を3つ並べて要点がない。

### 4 definition（定義）
`term`、`definition`：[…]、`points`、`example`、`exampleLabel`（既定「たとえば」）。
配置：強調の枠に用語と定義 → 要点 → 例の枠。

### 5 relation（関係図）
`diagram`：{`actors`, `relations`, `notes`}（書き方は `03-diagram-on-slide.md`）、`side`：{`title`, `lines`, `accent`}（右の解説の枠。省くと図が全幅。枠の高さは中身に合わせる）、`key`（下の1行）、`box`（true で当事者を箱で描く）。
配置：左 5.3 に図、右 3.7 に枠。上限：当事者6人、関係7本、右の枠6行。物（土地・建物）も当事者と同じように置く（「土地だけ描いて建物がない」は、法定地上権のような話では図にならない）。

### 6 parties（当事者）
`parties`：[{`kind`（ピクトの絵柄）, `symbol`（記号）, `role`（立場。基調の色で1行。「原告・被控訴人・上告人」）, `lines`:[…]（説明。黒で1〜2行）, `accent`（記号を強調の色に。争いの中心の当事者だけ）}]、`cols`（列の数。省くと4人まで2列、5〜6人は3列）。
各人：ピクト＋記号＋立場＋説明1〜2行（争点に効く属性）。上限：6人。相関図（sokan）の次、時系列の前に置く。

### 7 timeline（時系列。段ごとに1枚）
`actors`、`relations`（それぞれ `step` で、どの段から出るかを書く）、`notes`、`steps`：[{`label`, `items`:[…], `notes`（その段の発表原稿）, `mark`, `side`:{`title`, `lines`, `accent`}（図の右に置く解説の枠。使うなら全部の段に置く。図の幅が 6 インチになるので、当事者は2列まで）}]、`past`（"ink" か "gray"）。図の中の注記 `notes`（当事者の `notes` と同じ名前だが、置き場所が違う）は構成の直下に書き、段ごとの発表原稿は `steps[].notes` に書く。
steps の数だけスライドができ、見出しに ①②③ が付く。その段で新しく出た関係だけ強調の色。書き方は `04-step-reveal.md`。
上限：1段の帯は見出し＋3行、新しい関係は1段に2本まで（多くても4本）、全体で8段。帯の高さは、いちばん行の多い段に合わせて全段でそろう（段を送っても当事者の位置が動かない）。

### 8 timeline_table（時系列のまとめ表）
`head`（既定 ["時期","出来事"]）、`rows`、`colW`、`key`。上限：8行。

### 9 instance（審級）
`court`（灰の1行）、`claim`：{`title`, `lines`}（基調の枠）、`judgment`：{`title`, `lines`}（強調の枠）、`key`（→ の1行）。
見出しに結論を入れる（「6. 控訴審【原判決取消し・請求棄却】」）。上限：主張3行、判断4行、要点1行。

### 10 holding_structure（判旨の構造）
`head`（既定 ["段階","内容"]）、`rows`、`key`。判決の文を短く切って並べる。上限：5行。

### 11 instance_flow（審級の流れ）
`items`：[{`head`, `lines`, `accent`}]（横に並ぶ箱。2〜5個）、`frame`：{`lines`, `accent`}（下の解説）、`key`。
箱の中は3行まで（裁判所・結論・一言）。本判決の箱だけ強調の枠。

### 12 compare_table（比較表）
`lead`（表の上の1行）、`rows`（1行目が見出し行）、`colW`、`here`、`key`。上限：6行×4列。
短い語だけの列は中央、文の列は左に揃う（自動）。

### 13 issues（争点）
`items`：[{`head`（箱の題。条文・制度の名。基調の色）, `lines`:[…]（その箱の問い。黒。2行まで）, `answer`:[…]（その箱の答え。題と同じ色。1〜2行）, `accent`（最後に残る争点の箱だけ true）}]（3〜4個）、`conclusion`:[…]（争点が1つに絞られる文。1〜2行）、`here`（強調の枠。省いてよい）、`flowH`（箱の高さ。省くと行数から決まる）。
条文の順に箱を並べ、答えの出る箱には答えを書き、最後の箱（答えが分かれる所）を強調の枠にする。レジュメの「(3) 本件の争点」の表と同じ順にする。

### 14 significance（意義）
`points`：[{`lines`:[…], `n`, `accent`}]（①②③ が付く枠。2〜3個）、`key`（射程など）。

### 15 commentary（解説の要点）
`source`（出典の1行。灰）、`items`：[{`title`, `lines`, `accent`}]、`key`。1枚に要点は2つまで。要点が5つなら3枚に分ける。

### 16 doctrine_lr（学説の左右対比）
`lead`、`left`・`right`：{`title`, `lines`, `accent`}、`here`:[…]（「本件では」の強調の枠。本件に当てはめるとどうなるか）、`hereLabel`、`key`（違いがどこに現れるか）。本判決の側を強調の枠に。上限：各5行。左右の枠の高さは、行の多いほうの中身に合わせる（本文の領域いっぱいに広げない）。文字は上下中央。学説を並べて終わらせず、`here` か `key` で本件につなぐ。

### 17 opposition（反対する立場）
`lead`、`position`：{`title`, `lines`}、`evaluation`：{`title`, `lines`}（強調の枠）。

### 18 reasoning_chain（考察の矢印）
`rows`：[{`label`, `lines`, `accent`}]（左にラベル、右に内容。下向きの矢印でつなぐ。3〜4段）、`labelW`、`key`。
既定では最後の段が強調の枠（`accentLast: false` で外す）。使い方：判決の事実→読み取れること→判決の評価→疑問。

### 19 conclusion（結論）
`label`（既定「結論」）、`lines`（言い切り。1〜3行、大きめの字）、`reasons`（◎の理由）、`caveat`（「ただし」の枠）。

### 20 references（参考文献）
`items`：文字列か {`group`（小見出し。「判例」「条文」「文献」）, `items`:[…]} の列（太字にしない、11〜16pt。件数が少なければ大きい字になる）。読んだものだけ。スキルの中の道具や文書の名前（ファイルの場所など）は書かない。領域の半分も埋まらないときは、作成時に知らせる。

### 21 zakkuri（ざっくり理解）
`scene`（場面の1〜2行）、`trouble`（何が困るのか。「・」の箇条3行まで）、`so`（そこで。制度と条文）、`oneLine`（ひとことで。強調の枠）、`troubleLabel`・`soLabel`。
講義ノートの「ざっくり理解」をそのまま1枚にする型。上限：全体で9行。超えるなら trouble を2行に。

### 22 yoken（請求→抗弁→再抗弁）
`stages`：[{`tag`（請求・抗弁・再抗弁…）, `who`（だれがだれに）, `lines`, `result`}]（右にずらしながら積む。3〜4段）、`conclusion`（強調の枠）。
各段は2行まで。請求原因を争うだけの主張（否認）を、抗弁の段に置かない（`../yoken-jijitsu.md`）。

### 23 ronten_card（論点カード）
`issue`、`problem`、`norm`、`reason`、`application`。1枚に1論点。

### 24 case_matrix（判例マトリクス）
`lead`、`rows`（だれがだれに×何を求めるか、など）、`colW`、`key`。上限：6行×4列。1セルは判例の日付と結論だけ。

### 25 qa（想定問答）
`q`、`a`：[…]（1行目が答え）、`basis`（根拠の箇条）。本編の後ろに予備として置く。

### 26 points（要点）
`lead`、`points`、`framed`（false で枠なし）、`accent`（強調の枠）、`key`。

### 27 case_ref（参考判例）
`name`（判例名。〈 〉は型が付ける）、`tag`、`facts`、`holding`、`relation`（→ 本件との関係。強調）。`cases`：[…] で2件並べられる。`here`。

### 28 blocks（汎用）
`blocks`：[{`kind`: text／frame／accent／statute／table／flow／spacer, …}] を上から積む。ほかの型で足りないときだけ使う。

### 29 axis（整理軸。2×2）
`xLabel`・`xValues`:[2]、`yLabel`・`yValues`:[2]、`cells`：[[左上, 右上],[左下, 右下]]（各 {`title`, `lines`, `accent`} か {`none`:"この組合せはない"}）、`key`。
2つの観点の有無で類型を置く。講義ノートの座標図に対応する。

### 30 tf_check（正誤の確認）
`items`：[{`statement`（命題）, `answer`（"○" か "×"）, `basis`（根拠の1〜2行。条文番号・ノートの節・誤りの箇所）, `no`}]、`lead`、`key`、`answers`（false にすると印が「？」になり、根拠を出さない。問いの枚と答えの枚に分けるときに使う）。
配置：1問が1段。左に幅 0.95 の印の箱（○も×も黒の 28pt。枠は基調の色）、右に命題（太字）と根拠（太字にしない、「→」で始める）。正誤は形（○・×）で区別し、色では区別しない（`10-accessibility-print.md`）。段の高さは 1.25 まで、段の間 0.14。
上限：1枚3問（4問なら根拠を1行に）。命題は2行（全角60字）、根拠は2行。悪い例：ノートの命題の文を削らずに入れて 13pt でも収まらない。誤りの箇所を書かずに「×」だけを示す。
講義ノートの正誤の表（短答式の命題）から起こす。命題と根拠は、ノートで確かめたものだけを写す。`note_to_deck.py` は、見出し行に「命題」「正誤」のある表と `--tf` の JSON を、3問ずつこの型にする。

### 31 time_axis（時間軸）
`events`：[{`id`, `when`（軸の上の小さい字。「起算点（客観）」「5年」など）, `label`（出来事）, `sub`:[…]（太字にしない補足）, `accent`}]、`spans`：[{`from`, `to`（出来事の id）, `label`, `row`（1が軸に近い行。長い期間を上の行に）, `accent`, `dash`}]、`lead`、`key`。
配置：軸は左 0.6 から右 9.45 までの右向きの矢印。出来事は等間隔（`events` の数で幅を割る）で、軸の上に目盛り、その上に `when`（13pt、灰）、軸の下に出来事の文字（16→13pt、中央揃え）。期間は軸の上の行（1行 0.6）に両矢印とラベル（14pt）で描き、端から軸へ点線を下ろす。強調の期間は強調の色・3pt。
上限：出来事5個、期間3本（行は2つまで）、出来事の文字は2行、期間のラベルは両端の間に収まる長さ（収まらないと作成時に警告が出る）。悪い例：期間のない出来事の列に使う（それは timeline_table）。出来事を実際の日数に比例させて並べようとする（等間隔でよい。長さは期間のラベルで言う）。
時効・除斥期間、上訴期間、催告後の猶予のように「いつからいつまで」を見せる1枚に使う。だれが何をしたかを段ごとに積むのは timeline。

### 32 branch（場合分け）
`questions`：[{`q`（問い。「〜か」）, `tag`（既定「問①」）, `lines`, `yes`：{`title`, `lines`, `accent`}（右の結論）, `yesLabel`・`noLabel`}]。最後の問いにだけ `no`：{`title`, `lines`, `accent`}（下の結論）を書く。`questionW`（問いの箱の幅。既定 4.3）、`yesLabel`・`noLabel`（既定「はい」「いいえ」）、`key`。
配置：問いの箱を左に上から並べる（幅 4.3、高さ 1.2 まで、段の間 0.3）。「はい」は右向きの矢印（幅 0.95）で右の結論の箱（幅 3.95）へ、「いいえ」は下向きの矢印で次の問いへ。最後の「いいえ」の結論は、問いの列の一番下に置く。
上限：問い3つ（結論を入れて4段）、各箱2行。悪い例：問いが「はい／いいえ」で答えられない（「どの類型か」）。4つ以上の問いを1枚に入れる（2枚に分け、2枚目の最初に「問③から」と書く）。結論を全部強調の枠にする（設例が当たる結論だけ）。
要件を順に確かめる流れ（訴訟共同の必要があるか→合一確定の必要があるか、など）に使う。2つの観点の組合せを一覧するなら axis、主張の応酬なら yoken。

### 33 sokan（相関図）
`groups`：[{`title`（「親族関係」「取引関係」など）, `cols`（その組が使う列の数）}]（左右2組。省くと区切りなし）、`diagram`：{`cols`（列の総数）, `actors`:[{`id`, `symbol`（箱の中の大きい字。記号か「本件土地」のような名）, `sub`:[…]（小さい灰色の説明。1〜2行）, `col`, `row`（小数で書ける）, `color`（"accent"＝争いの中心、"base"＝基調の色の枠）, `fill`（true で帯の色の地）}], `relations`:[{`from`, `to`, `label`, `arrow`（false で矢じりのない線。親子・夫婦・所有）, `dash`（true で点線。世話・事実上の関係）, `emphasis`（true で強調の色の太い矢印。争いの中心の関係だけ）, `small`（true でラベルを 10.5pt に）}], `notes`}、`caption`:[…]（図の右下に置く注。帯の色の地。争いの中心を1行で）、`key`。
配置：題の行（高さ 0.3）、その下に図、右下に注、いちばん下に1行。当事者は箱で描く（ピクトは使わない）。図は図形で描く（画像にしない）。
順序：前提知識の後、**当事者（parties）と時系列（timeline）の前**に置く。全体の地図を先に見せてから、段を追う。強調の色は、争いの中心になる関係1本と、その当事者の箱だけに使う。日付・金額は、判決の確定した事実だけを書く。
上限：当事者7人、線8本。線が当事者の箱の上を通る配置、ラベルを置けない配置は、作成時に止まる（位置を変える）。

## 型ごとの早見表

座標はインチ（スライドは 10×5.625）。本文の領域は x 0.4〜9.6、y 0.95〜5.15（幅 9.2、高さ 4.2）。「積む」とあるのは、ブロックを上から順に置き、枠の間を 0.2 空け、収まる最大の文字サイズを選ぶ配置（`kit.stack()`）。字数は全角で、1枚の合計は 190 字前後を目安に、330 字で警告、420 字で誤りになる。

## 悪い例（どの型でも）

- 1枚に型を2つ詰める（条文と比較表を同じ枚に）。
- 枠の中に枠を入れる。
- 要点が5行を超える。
- 見出しが2行になる（全角で22字以内を目安に。25字分を超えると `deck_lint.py` の heading-long）。
- 「→」の要点を2つ以上置く（1枚の結びは1つ）。
- 強調の色の文字が、その枚の3分の1を超える（accent-heavy）。
- 太い矢印（新しい関係）が1枚に3本以上ある（5本以上で `deck_lint.py` の new-arrows。完成版でも3〜4本の枚がある）。
- 枠を本文の領域いっぱいに広げて、中が空く（枠の高さは中身＋余裕。frame-empty）。
- 下書きの印（`_todo`）や仮の文字（「（役割）」「（…を書く）」）を残す。`build_deck.js` と `deck_lint.py` が止める（下書きを見るだけなら `--draft`）。
