# 時系列を1段ずつ積む

事案の説明は、まず相関図（当事者の全体の地図）を1枚見せ、次に当事者を紹介し、そのあとで出来事の順に関係を1つずつ足していく。相関図で「だれがいるか」を先に渡しておくと、段を追うときに聞き手は新しく出た関係だけを追えばよい。相関図だけで事実の説明を済ませない（順序が伝わらない）。段だけで済ませない（全体が見えないまま進む）。

順序：相関図（sokan）→ 当事者（parties）→ 時系列①②③…（timeline）→ 時系列のまとめ（timeline_table）→ 争点（issues）。相関図は図形で描き、関係の種類で左右に分け、争いの中心になる関係だけを強調の色にする（`03-diagram-on-slide.md` の 4-2）。

## 1. 仕組み

`timeline` の型は、`steps` の数だけスライドを作る。

- 当事者と関係に、`step`（何段目から出るか）を書く。
- n 段目のスライドには、step が n 以下の当事者と関係が描かれる。
- step が n のもの（その段で新しく出たもの）は、強調の色・太い線・大きいラベルになる。
- step が n より小さいもの（前からあるもの）は、黒・細めの線・小さいラベルで残る。
- 当事者の位置は、どの段でも変わらない（格子は全段の当事者から決まる。下部の帯の高さも、いちばん行の多い段に合わせて全段でそろう）。
- 所有・親子のような背景の関係は、その段で出ても黒のままにできる（`"emphasis": false`）。矢じりのない線にするなら `"arrow": false`。
- 下部の帯に、その段の出来事を書く。見出しに丸数字が付く（「④ 昭和58年11月11日　最初の借入れ」）。

```json
{ "type": "timeline", "heading": "4. 時系列",
  "actors": [ { "id": "Z", "kind": "company", "symbol": "Z", "role": "Yが設立した会社", "col": 2, "row": 0, "step": 2 } ],
  "relations": [ { "from": "Y", "to": "Z", "label": "設立・店を移す", "step": 2 } ],
  "steps": [
    { "label": "賃貸借の開始", "items": ["…", "…"], "notes": "（この段の発表原稿）" },
    { "label": "会社の設立", "items": ["…"] } ] }
```

## 2. 段の切り方

- **1段に、新しい関係は1〜2本。** 3本以上出るなら、段を分ける（「④-1」「④-2」。`mark` で指定）。
- 段の切れ目は、法的な意味が変わる所に置く（契約の成立、担保の設定、借入れ、相手方が知った時、解除、提訴）。
- 関係が生まれない段（死亡、成年に達した、など）は、図を変えずに帯だけで語るか、当事者の役割の書き換えで示す。
- 全体で8段まで。超えるなら、まとめられる段をまとめる。
- 最後に、まとめの表（`timeline_table`）を1枚置く。丸数字は、レジュメの時系列の小見出しと同じにする。

## 3. 前の段の関係の色

| 設定 | 見え方 | 使う場面 |
|---|---|---|
| `"past": "ink"`（既定） | 前の段の関係は黒のまま残る | 関係が7本まで。積み上がりを見せたいとき |
| `"past": "gray"` | 前の段の関係は灰に落ちる | 関係が多く、新しい関係が埋もれるとき |
| 指定なし | 7本までは黒、8本以上は自動で灰 | — |

認められた発表資料は、黒のまま残す方式だった。まずこの方式で作り、最後の段を画像で見て、新しい関係が埋もれていたら灰にする。

## 4. 帯の書き方

- 見出し：丸数字＋日付＋出来事の名前（17pt 太字）。
- 箇条：「・」で2〜3行（15pt 太字）。だれが、だれに、何をしたか。金額と日付はここに書く。
- 帯の高さは、いちばん行の多い段の行数で決まり、全段で同じになる。図の領域は、その分だけ狭くなる。
- 図の右に解説の枠を置ける（`steps[].side`：{`title`, `lines`, `accent`}）。置くなら全部の段に置く（段によって図の幅が変わると、当事者の位置が動く）。枠を置くと図は 6 インチになるので、当事者は2列までにする。

## 5. 図の中の注記

相手方の認識など、矢印で描けない事実は、図の中の短い注記にする（構成の直下の `notes`：[{`text`, `col`, `row`, `step`, `dx`, `dy`}]。`steps[].notes` は発表原稿で、別のもの）。置く場所は、当事者のいない格子のます。当事者・線・ラベルに重なると作成時に止まるので、`col`・`row` を小数でずらすか、`dx`・`dy` で動かす。その段で出た注記は強調の色。1段に1つまで、全角10字まで。それより長い事実は、帯の箇条に書いて語を強調の色にする（`{r:Yは売却を知らなかった}`）。

## 6. 発表での使い方

- 1段ごとに、帯の内容を読み、強調の色の矢印を指す。
- 原稿（`steps[].notes`）は、1段 50〜100字（10〜20秒）。
- 最後の段で、争点になる関係を言い、まとめの表に進む。

## 7. 確認

- どの段でも、強調の色が「その段で新しく出たもの」だけに付いているか。
- 段を送ったとき、当事者の位置が動かないか（全枚を画像にして続けて見る）。
- 最後の段の図が、レジュメの相関図と同じ関係を含むか。

## 8. 悪い例と直し方

| 悪い例 | 起きること | 直し方 |
|---|---|---|
| 相関図を見せずに、いきなり段を追う | 聞き手が、だれが出てくるのか分からないまま1段目を聞く | 段の前に、相関図と当事者の枚を置く |
| 相関図に日付・金額・経過を全部書き込む | 1枚で全部を説明しようとして、読めない | 相関図は関係だけ。経過は段と帯で見せる |
| 相関図の線を全部強調の色にする | どれが争いの中心か分からない | 強調の色は、争いの中心の関係1本だけ |
| 1段に関係を3本以上足す | どれがその段の話か分からない。`deck_lint.py` が new-arrows を出す | 段を分ける（`mark` で「④-1」「④-2」） |
| 段ごとに `col`・`row` を変える | 送るたびに当事者が動き、目が追えない | 位置は全段の当事者を並べて一度に決める。途中から出る当事者の場所を最初から空けておく |
| 帯に評価を書く（「Yは悪意であった」） | 事実と評価が混ざる | 帯は出来事だけ。評価は審級・考察の枚で言う |
| 日付と金額を矢印のラベルに書く | ラベルが長くなり、置けない（作成時に警告が出る） | ラベルは関係の名前（全角8字まで）。日付と金額は帯に |
| 8段を超える | 事案の説明だけで時間を使い切る | 争点に関わらない出来事をまとめる。まとめの表で補う |
| 最後のまとめの表がない | 全体をもう一度見渡せない | `timeline_table` を1枚置く。丸数字を段と同じにする |

## 9. 段の数と時間の目安

| 事案 | 段 | 時間（1段 10〜20秒） |
|---|---|---|
| 当事者2〜3人、契約と不履行 | 3〜4 | 1分前後 |
| 当事者4〜5人、担保・転貸・譲渡が絡む | 5〜7 | 1分半〜2分 |
| 当事者6人、複数の取引 | 8（上限） | 2分半。関係の種類で図を2組に分けることも考える |

発表全体に占める事案の説明は、4分の1までにする。超えるなら段を減らす。
