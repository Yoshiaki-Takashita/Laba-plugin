# 改行と文字サイズ

スライドの文字で起きる失敗は三つある。語の途中で折れる。枠からはみ出す。枠の中が空きすぎる。どれも、作る前の見積りで防ぐ。道具は `scripts/slides/lib/textfit.js`、検査は `deck_lint.py`。

## 1. 改行は、切ってよい位置にだけ入れる

行の折り返しを表示側に任せると、書体の違いで折れる位置が変わり、語の途中で折れる。そこで、作るときに改行を全部入れておき、表示側には折り返させない。

**切らない所**（`lib/textfit.js` の breakPrio が 0 を返す所。`deck_lint.py` の break_prio も同じ決まり）

| 切らない所 | 例（／で切ってはいけない） |
|---|---|
| 漢字の語・カタカナの語・英数字の並びの途中 | 請求／原因、Y／2、代理／権 |
| 漢字＋送り仮名＋漢字の複合語 | 建て／替え、取り／消し、引き／渡し |
| ひらがなの続き | みたして／いる、及ぶ／とは |
| 漢字・英数字と、その後ろの助詞の間 | Y2に／は、相手方／が |
| 条文番号 | 41条1項・2／項、612条／2項、民法／612条 |
| 判例の表記 | 昭和43・3／・8、民集22巻3号／551頁（年月日と登載誌の間「…3・8／民集…」は切ってよい） |
| 数と単位 | 3000／万円、30／年 |
| 短い括弧の中（8字まで） | （承諾／なし）、「特段の／事情」 |
| 決まった言い回し | 特段の／事情、善意の／第三者、権利の／濫用（一覧は `lib/textfit.js` の KEEP_BASE。構成の `meta.keep` で足せる） |
| 行頭に来てはいけない字の前、開き括弧の後 | 、。）」ー っ ゃ など |

**切ってよい所と優先順位**（大きいほどよい切れ目。行がよく埋まり、優先順位の高い位置を選ぶ）

| 優先 | 位置 |
|---|---|
| 4 | 句点（。）の後 |
| 3 | 読点（、）・閉じ括弧の後、「→」の前、空白の後 |
| 2 | 格助詞など（は・が・を・に・へ・で・と・も・や）の後に、漢字・カタカナ・英数字・開き括弧が続く所 |
| 1 | そのほかのひらがな（の・て・る・た・な など）の後に、漢字・カタカナ・英数字が続く所 |

- 行の幅の 35% に満たない位置は、ほかに切れ目がないときだけ使う。
- **1〜2字だけの行を作らない。** できたら、行の幅を少しずつ狭めて切り直す（行数は増やさない）。
- 行頭記号（◎・→・①・（1））で始まる行の続きは、記号とその後ろの空きの幅だけ字下げする（「①　」なら全角2字、「→ 」なら全角1字と半角1字）。
- どのサイズでも切ってよい位置がなく、語の途中で切るしかないときは、作成を止めて知らせる。**文を短くするか、言い回しを変える。**

**幅の見積り**

- 全角1字＝文字サイズ pt ÷ 72 インチ。半角の数字は 0.56 字、英大文字 0.66 字、英小文字 0.54 字。
- **和文と英数字の境には、0.25 字分の空きを足す。** LibreOffice は和文と英数字の間を自動で空けるので、見込まないと「Y1には請求原因、Y2には…」のような行が見積りより長くなり、表示側でもう一度折れて「は」だけの行ができる（独立の採点で実際に起きた）。
- 1行の字数から、全角 0.6 字分の余裕を引く（書体の置き換わりの分）。

## 2. 文字サイズは「収まる最大」

枠ごとに、大きい順の候補（18 → 17 → 16 → 15）を試し、高さに収まり、語の途中で切らずに済む最初のサイズを使う。

- 1枚に枠が複数あるときは、全部の枠を同じ段（同じ大きさの組）で測り、本文の領域（高さ4.2）に収まる最大の段を選ぶ。枠ごとに大きさがばらばらにならない。
- 同じ文字サイズなら、ふつうの間隔（0.2）、詰めた間隔（0.12）の順に試してから、1段小さくする（間隔より先に文字を縮めない）。
- 内容が少なく、いちばん大きい段（18pt）でも領域の6割に届かない枚は、1段大きい組（本文20pt、表17pt、条文16pt）を試し、収まればそれを使う。見出し（20pt）は超えない。
- 余った高さは、次の順に配る。完成版は、本文の領域を下まで使い、段落の間を広めにとっている（実測：段落の後ろの空きは 3〜12pt、枠の下端はほとんどの枚で 4.9〜5.15）。
  1. 枠・要点の段落の間を広げる（6pt → 最大 12pt）。
  2. 枠を広げる（枠は最大 35%・0.6 インチまで、表 35%、流れの箱 30%、条文 15%）。枠を広げすぎると、中が空いて見える。
  3. 枠と枠の間を広げる（最大 ＋0.2）。
  4. それでも領域の 30% を超えて余るなら、内容が少ない枚として知らせる。文字を大きくしても埋まらない。**内容（「本件では」の枠、→ の1行）を足すか、前後の枚とまとめる。**
- 行頭記号（◎・）の直後が半角の字（「◎612条」）なら、詰まって見えないよう空きを入れる（自動）。
- 最小の段（本文 15pt、条文 14.5pt）でも収まらなければ、間隔を詰めて試し、それでも収まらなければ作成を止めて知らせる。候補に 14.5pt より小さいサイズを書いても、textfit はそこまで縮めない（`small` の注と参考文献を除く。`01-tokens.md` の下限の表）。**文字を小さくして押し込まない。文字を削るか、2枚に分ける。**
- 表が 15pt を下回りそうなときは、縮める前に列の幅を中身の長さに合わせて配り直して試す（作成時に「確かめる所」に出す）。
- 本文が 15pt を下回る枚、ラベルが全角8字を超える線、1枚 75 字未満の枚は、作成時に知らせる（止めない）。

高さの見積り：行数 × 文字サイズ × 1.32 ＋ 段落の間 ×（段落数−1）＋ 枠の内側の余白。行送りは固定値で指定してあるので、環境が違っても行の高さは同じになる。

## 3. 枠の中の文字は上下中央

囲みの中の文字は、上下中央に置く。上に寄せると、下が空いて見える。左右は左揃え（流れの箱・当事者・表の短い列だけ中央）。

## 4. 描画した後の検査（deck_lint.py）

見積りは見積りでしかない。`deck_lint.py` は、資料を PDF にして文字の位置を読み（LibreOffice と poppler の pdftotext）、実際の行を、構成で指定した行と照らす。

| 検査 | 見つけるもの |
|---|---|
| bad-break、short-line | 指定した改行そのものが、語・番号の途中にある。1〜2字だけの行を指定している |
| render-break | 指定していない改行が、語・条文番号・判例の表記の途中に入った（表示側がもう一度折った） |
| render-short | 指定していない改行で、1〜2字だけの行ができた |
| render-wrap | 指定していない改行がある（文節の切れ目）。warn |
| render-outside | 文字が、囲みの枠の外に出ている |
| below-body | 枠・文字が、本文の領域の下（頁番号の所）まで出ている |
| overlap | 文字どうしが重なっている（描画された行の箱で比べる） |

- 改行を1つも指定していない資料（ほかの道具で作った資料）でも、render-break と render-short は error にする。例外は、条文の引用（「民法824条［…］」で始まる 60 字以上の箱、または statute）の中の折り返しで、keep 語・条文番号・判例の表記に触れないものだけ（warn）。条文は長い地の文で、和文の組版では字の間で折り返すのが普通だからである。完成版の 7・8・15 枚目の 5 件がこれに当たり、画像で確かめると、枠の幅いっぱいの地の文の折り返しだった（完成版の不備ではない）。
- 書体が置き換わっているとき（Yu Gothic が無く、Noto Sans CJK になる、など）は、その旨を出す。実機とは改行の位置が違うことがある。
- LibreOffice か pdftotext が無いと、この検査はできない（その旨を出し、見積りの検査 text-overflow に切り替える）。そのときは、画像にして目で確かめる。
- 回帰試験：`scripts/slides/tests/textfit_test.js`（改行の決まり）、`tests/lint_regress.py`（検査が見つけること）、`tests/bad_cases.py`（独立の採点で使った悪い例 34 件。9 割以上の検出を求める。現在 34 件すべてを検出し、うち 33 件が error）。

## 5. 余白が多すぎる枚（deck_lint.py の sparse、frame-empty）

- sparse：本文の領域（y 0.95〜5.15）の下 35% に、文字も枠も図形もない（warn）。45% を超えたら error。完成版 48 枚では、最大でも下 29% だった。
- frame-empty：幅 4 インチ以上・高さ 1.3 インチ超の枠で、描画した文字の実際の高さ（1行目の上から最終行の下まで）が、枠の高さの 45% に満たない（warn）。35% に満たなければ error。完成版では 47 枚目の1件（文字 44%）が warn になる。

直し方は三つ。

1. 内容を足す（「本件では」の枠、→ の1行、条文の注）。本文（レジュメ・ノート）にある内容だけを足す。
2. 前後の枚と合わせて1枚にする。
3. 枠の数を減らし、1つの枠にまとめる（2行しかない枠を3つ並べない）。

文字を大きくするだけでは直らない（すでに最大の段を使っている）。

## 6. 文字の量の上限（型ごとの目安）

| 部品 | 上限 |
|---|---|
| 見出し | 全角22字、1行（25字分を超えると heading-long） |
| ◎の要点 | 3〜4行、1行は全角30字まで |
| 枠の中 | 4〜5行 |
| 条文 | 合計4行（長い条文は要る部分だけ「……」で引く） |
| 表 | 6行×4列。1セル2行まで |
| 帯 | 見出し＋3行 |
| 矢印のラベル | 全角8字（2行まで） |
| 1枚の合計 | 190字前後（資料全体の平均は 150〜230 字）。75字未満・330字超で注意、420字で分ける |

## 7. 確認の手順

1. `build_deck.js` が止まらずに終わる（収まらない文字、語の途中の改行、置けないラベル、下書きの印がない）。「確かめる所」の一覧も読む。
2. `deck_lint.py` の error が0（描画後の検査が「済み」になっていること）。
3. PDF にして全枚を画像にし、3×3 の一覧で見る。次に、気になる枚を大きくして見る。
4. 見る所：語の途中の改行、行頭の句読点、枠と文字の間、矢印とラベルの重なり、余白の偏り。
