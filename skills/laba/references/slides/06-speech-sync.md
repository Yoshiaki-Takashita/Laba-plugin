# 発表原稿との対応と時間配分

スライドは、原稿（レジュメ・ノート）を読みながら1枚ずつ送れるように作る。

## 1. 見出しの番号を揃える

- スライドの見出しは、レジュメの通し番号と同じにする：「5. 事実の概要　(2) 時系列③」「8. 上告審【破棄差戻し】　判旨の構造」。
- 右上に、大項目名（章）を小さく置く：「２．事案と各審級の判断」。構成の JSON では `{"type":"section","name":"…"}` で切り替える。
- 1つの項を複数枚に分けるときは、①②、④-1／④-2 を付ける。番号を新しく振らない。
- レジュメを直して番号が変わったら、スライドも直す。`deck_lint.py` は、番号が戻る・飛ぶ箇所を知らせる（heading-order）。判例研究では、`scripts/hanrei/sync_check.py レジュメ.json スライド.json` が、番号と題、小見出し、当事者の記号、時系列の段の数、スライドにだけある日付・金額を照らす。下書きは `scripts/hanrei/resume_to_deck.py` で起こせる（レジュメの番号が見出しに写る）。

## 2. 1枚に、レジュメのどこが対応するか

| レジュメ | スライド |
|---|---|
| 前提知識の1節 | 1〜3枚（仕組みの図／条文／本件では） |
| 当事者の表・相関図 | 当事者1枚、相関図は時系列に吸収 |
| 時系列の1段 | 1枚 |
| 1審級 | 1〜2枚 |
| 判旨 | 構造の表1枚（全文は読み上げ、スライドには載せない） |
| 三審の比較 | 1枚 |
| 意義 | 1枚 |
| 解説の要点1つ | 1枚（2つまで同じ枚に） |
| 学説の1軸 | 1枚 |
| 考察 (1) | 2枚 |
| 考察 (2)〜(4) | 1枚 |

判例研究（発表 20〜30 分）で 45〜50 枚が目安。時系列の段が多い事案では増える。

## 3. 発表原稿をノート欄に入れる

構成の JSON の `notes` に、その枚で話すことを書く（時系列は `steps[].notes`）。

- 話し言葉で書く（です・ます）。レジュメの段落を読むなら、その段落の頭の数語と「（レジュメ○頁）」だけでもよい。
- 1枚の原稿は 75〜450字（15〜90秒）。
- 原稿があれば、`build_deck.js --outline 進行表.md` が、枚ごとの原稿の字数と秒数の見積りを表にする。

## 4. 時間配分

見積りの式：秒 ＝ 原稿の字数 ÷ 300 × 60（1分に300字）。15秒未満は15秒、90秒超は90秒として数える。

| 発表時間 | 枚数の目安 | 配分 |
|---|---|---|
| 10分 | 12〜15枚 | 事案4、判旨3、意義2、考察3 |
| 20分 | 30〜35枚 | 前提知識6、事案と審級14、意義と解説6、学説3、考察5 |
| 30分 | 45〜50枚 | 前提知識10、事案と審級20、意義と解説8、学説4、考察6 |

- 時系列の枚は短い（10〜20秒）。条文・判旨の構造・学説の枚は長い（60〜90秒）。
- 考察に、全体の2割の時間を残す。前提知識が長くなりすぎないようにする。
- 進行表の合計が発表時間を超えたら、枚を削る前に、原稿を削る。次に、前提知識の枚を減らす。

## 5. 想定問答

本編の後ろに、予備のスライド（qa の型）を置く。3〜5問。見出しに番号を振らず「補足　…」とする。

- 判決の射程（この事実が違ったらどうなるか）。
- 自分の考察への反論。
- 改正法との関係。
- 用語の定義を聞かれたときの1枚。

## 6. 講義ノートから起こしたスライド

見出しは、ノートの節の題に通し番号を振る。発表ではなく自習に使うなら、ノート欄に「ノート○頁」と対応を書いておく（`07-from-note.md`）。
