# レジュメの標準構成

成果物は二つ：判例研究のレジュメ（Word）と、発表スライド（PowerPoint）。レジュメは1種類でよい。全体で A4 18〜20頁が目安（発表 20〜30 分の場合）。分量の指定があれば、比率を保って縮める。

## 1. 表紙のかたまり

- 右上に小さく3行：年度と所属・演習名／「判例研究報告レジュメ」／報告者名と発表日（`config.json` から。空なら仮の文字）。
- 中央に「判例研究」（20pt 太字）、テーマ（16pt 太字）、判決情報3行（裁判所・日付・法廷／登載誌／事件番号・事件名）。
- 「構成」（5章の見出し）と、「※条文番号は特に断りのない限り現行法による」。

## 2. 5章の構成

| 章 | 節 | 書くこと | 目安 |
|---|---|---|---|
| １．前提知識 | 制度ごとに1節（3〜4節） | 本件を読むのに必要な制度だけ。各節は「定義→条文→例1つ→本件ではどこで効くか」 | 約2,700字、3頁弱 |
| ２．事案と各審級の判断 | 事実の概要 | (1) 当事者：表（記号／立場／備考）と相関図　(2) 時系列：段ごとの小見出し＋段落。提訴まで　(3) 本件の争点（条文→問い→本件での答え、の表と、争点が1つに絞られる段落） | 4〜5頁 |
| | 第一審【結論】 | 裁判所・日付／当事者の主張／判断／解説 | 1頁 |
| | 控訴審【結論】 | 同上。前の審級から変わった点を1段落 | 1頁 |
| | 上告審【結論】 | 上告理由／判旨（原文）／判旨の構造の表／控訴審からの変化／その後 | 2〜3頁 |
| | 三審の比較 | 表1つ＋争点の絞り込み | 半頁 |
| ３．本判決の意義と調査官解説 | 趣旨と意義 | 意義を3点。判旨の鍵になる語の読み方。改正がある場合は改正前後の対比 | 1〜2頁 |
| | 調査官解説 | 要点を5つ前後。各要点は見出し＋1〜3段落（読めたときだけ） | 2〜3頁 |
| ４．学説 | 対立軸ごとに1節（2節まで） | 対立の構図→両説を1段落ずつ→本件への当てはめ | 2頁 |
| ５．評価と考察 | 本判決に反対する立場 | 1段落 | — |
| | 考察 (1)〜(4) | (1) 自分の論点（`07-original-point.md`）(2) 相手方の保護 (3) 改正法・今後 (4) 射程。合計8段落前後 | 2〜3頁 |
| 参考判例・文献 | | 読んだものだけ。8pt・行間を詰めて1頁以内。判例・条文・文献の小見出しで分けてよい | 1頁 |

見出しには通し番号を振る（節は章をまたいで 1, 2, 3 … と続ける）。スライドの見出しは、この番号と1対1で対応させる（`../slides/06-speech-sync.md`）。小見出し（(1)(2)(3)）も、スライドで飛ばさない。レジュメに「(3) 本件の争点」「(2) 本判決の射程」があるのに、その枚がないと、聞き手がレジュメの場所を見失う（`scripts/hanrei/sync_check.py` の sub-missing）。

スライドの順は、レジュメの順と同じにする。ただし事実の概要は、**相関図 → (1) 当事者 → (2) 時系列①②… → 時系列のまとめ → (3) 本件の争点** の順にする（レジュメでは当事者表の下に相関図を置くが、スライドでは相関図を先に見せる。`../slides/04-step-reveal.md`）。全体は、表紙 → 目次（5章と節を2列で）→ 前提知識（条文の枠＋要点＋「本件では」）→ 相関図 → 当事者 → 時系列 → まとめの表 → 争点 → 各審級（主張の枠／判断の枠／1行の要点）→ 判旨の構造の表 → 三審の比較 → 意義 → 調査官解説 → 学説（左右の枠）→ 反対する立場 → 考察（事実から問いへ→射程→結論）→ 参考文献。

## 3. 前提知識の書き方

- 最初の1文で、何を念頭に置くかを挙げる（「本件を理解する上で、「A」「B」「C」の三つを念頭に置く必要がある。」）。
- 制度は3〜4つに絞る。条文は3つ、参考判例は2つまで。授業であまり扱わない条文は、条文の本文を引用の段落（左に罫線を引いた段落。ブロック `["Q", "…"]`）で示し、直後に端的な解説を置く。判旨の原文も同じ引用の段落にする。
- 各節の最後は、本件につなぐ（「本件では、…が問題になる。」）。並べるだけにしない。
- 参考判例は「事案：／判断：」の2行と、本件との関係の1段落。
- 削るときは、例の重ね書き、条文の周辺知識、同じ内容の再説明から落とす。要点・条文番号・本件につなぐ文は残す。

## 4. 長い資料の縮め方

- 調査官解説：「本判決の調査官解説における要点を、次の五つに整理する。」と書き、要点を見出しにする。説の対立（A説・B説）は表にせず文章で。選択肢の列挙（①〜④）だけは表にしてよい。専門用語の説明は小さい灰色の字の注にする（ブロック `["G", "…"]`。スライドでは枚の隅の `note`）。
- 各審級：変化は差分の表にせず、「変わったのは①…②…の2点である」の1段落にする。
- 学説：対立軸を二つに絞る。各審級がどの説かを並べる表は作らない。

## 5. 表にするもの・しないもの

表は「並べて見ると分かるもの」だけ：当事者、条文から見た争点、三審の比較、判旨の構造、学説の対比（1つ）、改正前後の対比。説明は文章で書く。Word の表は黒の細い罫線の格子で、見出し行の塗りつぶしや白抜きは使わない（体裁は `08-style.md` の6。講義ノートの横罫だけの表とは違う）。

## 6. ビルダー

`scripts/hanrei/resume_build.py` に、この構成を JSON で渡す（見本は `scripts/hanrei/samples/resume_sample.json`）。章・節の番号、表紙、当事者表、時系列の小見出し、争点の表、引用の段落、参考文献の体裁はビルダーが付ける。既定の体裁は判例研究用（`--style hanrei`）。仮の文字（「（…を書く）」「【要確認】」）が残っていると止まる（下書きなら `--draft`）。
