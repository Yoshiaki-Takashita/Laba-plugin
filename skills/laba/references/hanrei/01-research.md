# 調査：判決の原文を取り、事実と判旨を控える

原則は一つ。**事実と判旨は、判決の原文から取る。** 解説の要約から取った事実は、解説者の関心で削られている。考察の材料（`07-original-point.md`）は、削られた側にある。

## 1. 判決の原文

1. 裁判所の判例検索で、事件名か日付で引く（手順と注意は `../case-verification.md` の2。「」を使える条件は同3）。詳細ページで、判例集の巻号頁・判示事項・裁判要旨・原審（裁判所・事件番号・判決日）・参照法条を控える。URL の形は次のとおり（〔 〕の中を入れ替える。id は検索結果の一覧から取る）。

   | 何 | URL の形 |
   |---|---|
   | 事件名で検索（最高裁） | `https://www.courts.go.jp/hanrei/search2/index.html?courtCaseType=1&filter[jikenName]=〔事件名〕` |
   | 詳細ページ（書誌・判示事項・裁判要旨・原審・参照法条） | `https://www.courts.go.jp/hanrei/〔id〕/detail2/index.html` |
   | 全文（PDF） | `https://www.courts.go.jp/assets/hanrei/hanrei-pdf-〔id〕.pdf` |

   - URL は短く保つ（検索の条件を足しすぎると、取得の道具が拒むことがある）。条件は事件名か日付の1つにする。
   - id は、検索結果か、検索エンジンが返した詳細ページの URL から取る。全文検索の結果や、ほかのサイトの紹介からは id が分からないことが多い。記憶で id を書かない。
   - 開いた詳細ページの事件番号・年月日・法廷が、探している判決と同じかを必ず見る（同じ論点の別の判決が先に出てくることがある）。
   - 日本法コネクタがつながっていれば、そちらを先に使う（`../connector.md`。判旨の「」は `case_quote_check` を `scope: "fulltext"` で）。使えないときに、この URL の形で開く。
2. 全文（PDF）を開き、「原審の適法に確定した事実関係」を、要約ではなく文単位で控える。取得の道具に字数の制限があるときは、範囲を分けて取り、要約で受け取らない。
3. 判旨も文単位で控える。段落ごとに、何を述べているか（一般論／本件への当てはめ／結論）を付ける。
4. 主文（破棄差戻し・破棄自判・上告棄却）を全文で確かめる。検索結果の「結果」欄だけで書かない。
5. 個別意見（補足意見・反対意見）の有無を確かめる。全員一致なら、そう書ける。

## 2. 記号の対応表

判決文は当事者を記号（Ｄ・Ｅ・Ｆ…）で書く。レジュメでは読みやすい記号（X・Y・A・B…）に置き換えるので、対応表を作業ファイルに作る。

| 判決文の記号 | レジュメの記号 | 立場 | 初出の箇所 |
|---|---|---|---|
| （例）Ｄ | X | 原告・被上告人 | 事実 1 |

- 原告側は X、被告側は Y、それ以外は A・B・C…の順。関係者が多いときは、役割が分かる順に振る。
- 「」で原文を引くときは、原文の記号のまま引くか、冒頭の注で「判決文の記号を置き換えた」と断る。
- 日付・金額・数量は、表にして原文の表記（漢数字）とレジュメの表記（算用数字）を並べる。写し間違いは、この表で見つける。

## 3. 下級審・差戻審

- 最高裁の判決文には、第一審・控訴審の判断が要約されている。まずここから取る。
- 下級審の判決そのものは、裁判所の検索に載っていないことが多い。判例集の解説、公開されている講義資料・評釈で補い、出所を台帳に書く（格付けは B になることが多い）。
- 判例集の解説を出版社が公開しているページ（有斐閣Online の判例百選のページなど）は、事実の概要の部分が無料で読めることがある。読めた範囲だけを使い、どこまで読めたかを台帳に書く。
- 大学の機関リポジトリの PDF は、転送が長く、取得の道具では開けないことがある。開けなかったら、開けなかったと台帳に書き、利用者に入手を頼む（読んだことにしない）。
- 差戻し後の結末（差戻審・再上告審）は、解説に書かれていることがある。確かめられたら「その後」として書く。確かめられなければ書かない。

## 4. 文献の実在を確かめる

読めない文献でも、実在と書誌だけは確かめられる。

- 出版社の年間総目次、書籍の紹介ページ、雑誌の目次で、題名・号・頁・章を照合する。たとえば、法律雑誌の出版社が公開している年ごとの総目次（PDF）、連載の一覧のページ、書籍の紹介ページ（ISBN で引ける）。
- 論文データベースの書誌ページ、国立国会図書館の個別の書誌ページ。
- 記憶だけで URL を組み立てない。検索結果に出た URL をたどる。
- 書誌を確かめただけの文献は、格付け C。本文には入れない（`02-citation-grade.md`）。

## 4-2. 条文の出所

- 条文の本文は、e-Gov 法令検索（か、条文を引ける連携先）で確かめた文言を写す。手順は `../statute-verification.md`。記憶や、解説に引かれた条文から写さない。
- 判決の当時の条文と現行法が違うときは、冒頭の注で原則（「条文番号は特に断りのない限り現行法による」）を断り、改正前は「旧○条」と書く。
- スライドの条文の枠にも、同じ文言を写す。長い条文は、要る部分だけを「……」で略して引く（文言は変えない）。

## 5. 利用者が貼った資料

- 貼ってもらった解説は、原文として読めたものになる（格付け A）。頁数は、貼られた資料に頁が書いてあるときだけ使う。
- 解説が引いている別の文献（孫引き）は、解説を経由して知っただけなので B。原著者の名前を出して要約しない。

## 6. 控えの形（作業ファイル）

```
[事実]
F01 （原文）「…」  → レジュメの記号に直した文：…  → 使う節：時系列②
F02 …
[判旨]
H01 一般論 （原文）「…」
H02 当てはめ …
[未確認]
- 第一審の判決日（解説に記載なし）
```

事実には番号を振り、レジュメの各文がどの事実に基づくかを追えるようにする。番号のない事実は、判決にない事実である。
