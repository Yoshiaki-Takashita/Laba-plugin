# 判例研究で起きた失敗の型

実際の作業で起きたものを一般化した。症状・原因・見つけ方・直し方の順。講義ノートの失敗は本体の `../failure-catalog.md`。

| # | 症状 | 原因 | 見つけ方 | 直し方 |
|---|---|---|---|---|
| H1 | 読んでいない論文を、著者名と「」つきで引いた | 二次資料の紹介を、原文を読んだかのように書いた | `ledger.py`（unread-quote、unread-page） | 「」と著者名を外し、「…とする見解がある（〜の整理による）」にする |
| H2 | 指導教員の論文の内容を、推測で本文に書いた | 題名と二次資料から中身を補った | `ledger.py`（advisor-unread） | 本文から外す。書誌だけ参考文献に残し、読めていないと報告する |
| H3 | 判決にない事実・金額が入った | 解説の要約や、記憶で補った | 事実の番号との対応（番号のない文） | 削る。必要なら「〜とみられる」と推論の形にする |
| H4 | 判決文の記号と、レジュメの記号が食い違った | 対応表を作らずに書き進めた | 相関図・当事者表・時系列・スライドの4か所の照合。スライドは `sync_check.py`（party-unknown・party-role） | 対応表を作り、全部を揃える |
| H5 | 日付・金額の写し間違い | 漢数字から算用数字への書き換えで誤った | 日付・金額の表で原文と並べる | 原文と突き合わせて直す |
| H6 | 主文を取り違えた（破棄自判と破棄差戻し） | 検索結果の欄だけで書いた | 全文の主文を読む | 主文を全文で確かめる |
| H7 | 判決が述べていない理由を、判決の理由として書いた | 解説の説明を、判決の理由と混ぜた | 理由の文ごとに出所を確かめる | 主語で書き分ける（「本判決は」「解説によれば」） |
| H8 | 金額を大きな字で強調したスライド | 数字が目立つと分かりやすいと考えた | 目視。利用者の指摘 | 金額ではなく、当事者の法的地位の表にする |
| H9 | 「前の審級から何が変わったか」の差分表を審級ごとに作った | 表にすると整って見える | 表の数（審級の節に表が2つ以上） | 「変わったのは①…②…の2点」の1段落にする |
| H10 | 各審級の位置づけ表（どの説か）を作った | 学説の節と審級の節をつなごうとした | 目視 | 削る。当てはめは学説の節の文章で書く |
| H11 | 表の見出し行を塗りつぶし、色の帯や枠で飾った Word | 既定の見た目のまま作った | 目視。`../docx-format.md` の規則 | 黒の細い罫線だけにする。色と枠を外す |
| H12 | 「ポイント」「要確認」の枠が本文に残った | 作業中の目印を消し忘れた | `ledger.py`（marker-left） | 枠を外し、要点は本文に混ぜる。未確認は書かない |
| H13 | 利用者が です・ます に直した段落を、である調に戻した | 文書を作り直した | 版の差分 | 直接編集に切り替える（`09-revision.md`）。その段落を元に戻す |
| H14 | 利用者が付けた太字・下線が消えた | 段落を作り直した | 版の差分 | run を保って文字だけ差し替える |
| H15 | 当事者の表を、頼まれていないのに別の形に変えた | 見やすくしようとした | 版の差分 | 元の表に戻す。変えるときは先に聞く |
| H16 | 前提知識が長すぎて、本題に入るのが遅い | 制度を網羅しようとした | 字数（約2,700字を超える） | 例の重ね書き、周辺知識、再説明を削る。短縮版を並べて渡す |
| H17 | 考察が、解説の「意義」の言い換えだった | 事実を読まずに書いた | 考察 (1) が拾った事実から始まっているか | `07-original-point.md` の手順でやり直す |
| H18 | 学説の節が、説の名前の列挙になった | 読めた資料が少ないのに、数を揃えた | 各説に本件への当てはめがあるか | 対立軸を二つに絞り、当てはめを書く |
| H19 | スライドの関係図を画像で貼り、直せなくなった | レジュメの図を使い回した | `deck_lint.py`（picture） | 図形で描き直す |
| H20 | スライドの矢印のラベルが、矢印や人物と重なった | 手で座標を置いた | `deck_lint.py`（overlap）、全枚の目視 | 自動配置に任せるか、ラベルを2行にする |
| H21 | スライドで語の途中で改行した | 自動の折り返しに任せた | 全枚の目視、`deck_lint.py`（bad-break・render-break） | 切ってよい位置で改行を指定する（ビルダーが行う。`../slides/05-text-fitting.md`） |
| H22 | 部の扉スライド、角丸のカード、丸で囲んだアイコンを使った | 既定の見た目のまま作った | `deck_lint.py`（decoration） | 外す。右上に大項目名を小さく置く |
| H23 | スライドの見出しが、レジュメの番号と合わない | レジュメを直した後、スライドを直さなかった | `sync_check.py`（heading-number・heading-title）、`deck_lint.py`（heading-order）、進行表 | 番号と題を揃える。レジュメを直すたびに掛け直す |
| H24 | 表紙の氏名・日付を、推測で埋めた | 空欄を避けようとした | 目視 | `config.json` にない値は仮の文字にし、報告に書く |
| H25 | 下級審の日付・裁判所名を、確かめずに書いた | 解説の記憶で補った | 台帳に出所があるか | 確かめられた範囲だけ書く |
| H26 | 改正前の条文番号と現行法の条文番号を混ぜた | 判決の当時の条文と、現行法を区別しなかった | 条文の一覧（`../statute-verification.md`） | 冒頭の注で原則を断り、改正前は「旧○条」と書く |
| H27 | 直しのたびに全体を作り直し、前に直した所が元に戻った | 構成の JSON を古いまま使った | 版の記録 | 直しを JSON か文書のどちらか一方に集める。版の記録を付ける |
| H28 | 渡すときに、読めていない文献を報告しなかった | 完成したように見せた | 報告の項目 | B・C の一覧、写した頁、要入手を必ず書く |
| H29 | スライドで、条文番号・判例の表記・語の途中で折れた（「41条1項・2／項」「…3号／551頁」「Y2に／は」） | 行の幅の見積りが、和文と英数字の境の空きを見込んでいなかった。表示側がもう一度折った | `deck_lint.py`（render-break・render-short。PDF にして実際の行を読む） | 文を短くする。ビルダーは境の空きを見込み、語の途中では切らない（切るしかなければ止まる） |
| H30 | レジュメにある小見出しの枚が、スライドにない（「(3) 本件の争点」「考察 (2)」。(1) の次が (3)） | 枚数を減らすときに、小見出しごと落とした | `sync_check.py`（sub-missing・sub-jump） | 枚を足す。省くなら、レジュメの側も合わせる |
| H31 | スライドに、レジュメにない文がある。限定の言い方が言い切りになった（「及ぶとは読めない」→「及ばない」） | 枚を埋めるために足した。短くするときに落とした | `sync_check.py`（content-not-in-resume・hedge-dropped）と、目での照合 | レジュメの言い方に戻す。足したい内容は、先にレジュメに書く |
| H32 | 下書きの印・仮の文字が残ったスライドを渡した（「（書誌は…確認して書く）」「（役割）」） | 下書きの道具の出力を、そのまま作成に掛けた | `build_deck.js`・`deck_lint.py`（placeholder。`--draft` なしで止まる） | 仮の文字を本文で置き換えるか、その行を消す |
| H33 | 1枚の文字が少なく、枠だけが大きい（2行の枠が領域いっぱいに広がる。下半分が空く） | 文字を大きくし、枠を広げて埋めようとした | `deck_lint.py`（sparse・frame-empty）、`build_deck.js` の「確かめる所」、1枚の平均の字数 | 内容を足す（「本件では」、→ の1行）か、前後の枚とまとめる。完成版は1枚平均 189 字 |
| H34 | 相関図を時系列の後に置いた。相関図なしで段を追った | 「先に全体を見せると、段の説明を聞かなくなる」と考えた | 枚の順 | 相関図 → 当事者 → 時系列 → まとめ → 争点の順にする（完成版の順） |
| H35 | 当事者のピクトが全員同じ（人）だった。相関図を画像で貼った | 絵柄を選ばなかった | 全枚の目視 | 人・女性・子・背広の人・会社・銀行・機関・土地・建物を使い分ける。相関図は箱で描く |
| H36 | レジュメの表が横罫だけ、本文が1字下げ、引用の段落がない | 講義ノートの体裁のまま作った | 全頁の目視。`kit_measure.py` の違いの一覧 | `resume_build.py` の既定（`--style hanrei`）で作る |
| H37 | 検査が、完成版として認められた資料を error にした（78件） | 検査の規則を、実測ではなく推測で決めた | 完成版に検査を掛ける | 規則を直す（`../slides/09-quality-rubric.md` の「検査の較正」）。規則を変えたら、完成版に掛け直す |
