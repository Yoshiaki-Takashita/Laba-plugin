# 直しと版の管理

判例研究は、何度も直しが入る。直しのたびに全体を作り直すと、利用者が手を入れた箇所が消え、前の版で直した所がまた元に戻る。

## 1. 原則

- **言われた所だけ直す。** ついでに他の段落を整えない。
- **版番号を上げ、前の版を残す。** 「やっぱり前のでよい」に戻せるようにする。ファイル名は「判例研究_〔テーマ〕_v12.docx」。
- **利用者の手が入った段落は壊さない。** です・ます、太字、下線、言い回し（`08-style.md` 3）。
- **直した所を報告する。** どの節の、どの段落を、どう変えたか。

## 2. 2回目以降は、文書を作り直さない

最初の版は `resume_build.py` で作る。利用者が Word で直した後の版は、作り直さずに直接編集する。

1. docx を展開し、`word/document.xml` を開く（python-docx か lxml）。
2. 直す段落を、本文の文字列で探す。
3. 書式を保つため、同じ種類の段落（同じ見出し・同じ本文の型）を複製（deepcopy）し、文字だけを差し替えて、元の位置に置く。
4. 利用者が付けた書式のある run（太字・下線）は触らない。
5. 保存して、検証（docx の検証スクリプト）→ PDF にして全頁を見る。

表・図の差し替えも同じ。表は行を複製して中身を替える。図は同じ大きさの画像に差し替える。

## 3. 利用者の手が入った箇所の見つけ方

- 前の版（自分が作った版）と、利用者が戻してきた版の、段落ごとの文字列を比べる。
- 違う段落に印を付け、作業ファイルに一覧を書く（「2章 時系列③ 第2段落：です・ますに変更、太字1か所」）。
- 以後の版では、この一覧の段落に触れる直しを頼まれたときだけ、その段落を直す。

## 4. スライドの直し

- スライドは構成の JSON を直して作り直してよい（位置は決まっているので、作り直しても崩れない）。ただし、利用者が PowerPoint で直した版が戻ってきたら、その版を python-pptx で直接編集する。
- レジュメの見出しを変えたら、スライドの見出しも変える（1対1を保つ）。
- 直した後は `deck_lint.py` を通し、全枚を画像にして見る。

## 5. 版の記録

作業ファイルに、版ごとに1行ずつ書く。

```
v11 → v12：４章 学説 第二の対立軸を文章に（表を削除）。考察(2)に1段落追加。利用者の手が入った段落：2章時系列③（変更なし）
```

## 6. 分量を変える直し

「前提知識を短く」のような直しは、別の版として並べて渡す（短縮版と元の版）。どちらを採るかは利用者が決める。採られた分量を、次に同じ種類の仕事をするときの最初の分量にする。
