# 条文の確認

条文を引くとき、要約するときの確認の手順。判例の確認（`case-verification.md`）と対になる。資料の要約が条文の限定を落としていることがあり、それを写すとノートも同じ誤りになる。実例：資料は「控訴審は両請求を併合して審理しなければならない」と書いていたが、条文は「各共同被告に係る控訴事件が同一の控訴裁判所に各別に係属するとき」に限って併合を義務づけていた。

## 目次
1. いつ確かめるか　2. 何で確かめるか　3. 何を見るか　4. 手順　5. 要約の規則　6. 改正があるとき　7. 報告

## 1. いつ確かめるか
- ノートが引く条文は、全部。資料に条文の本文が載っていても、現行の条文と照らす（資料が古い、略している、誤記している、ことがある）。
- とくに、条文を言い換えた文・要約した文・表のセル・論点カードの規範の欄。

## 2. 何で確かめるか
- **コネクタ（laba-jp-connector）がつながっていれば、先にツールで確かめる**（`connector.md`）。ここの手作業は、コネクタが無いとき・`not_covered`・`upstream_error` のときの手順。
- 法律・政令・省令：e-Gov 法令検索（法令の現行の条文が載っている）。
- 最高裁判所規則（民事訴訟規則、刑事訴訟規則など）：裁判所のウェブサイト。
- 条例・施行前の改正：その自治体・官報。確かめられなければ「未確認」。
- 六法のアプリ・解説サイトは補助。最後は一次の条文で見る。

## 3. 何を見るか

| 見る点 | 落としやすい例 |
|---|---|
| 条・項・号・枝番号 | 「424条の2」を「424条2項」と書く。号を落とす |
| 要件の限定の語 | 「同一の」「〜に限り」「〜の時までに」「〜の場合において」「書面で」 |
| 効果 | 「することができる」（権限）と「しなければならない」（義務）。「無効」と「取り消すことができる」。「推定する」と「みなす」 |
| 名宛人・主体 | 誰に向けた規定か（子会社か、親会社の取締役か。裁判所か、当事者か） |
| ただし書・例外 | 本文だけを引いて、ただし書を落とす |
| 準用 | 「準用する」先の条文まで見る |
| 委任 | 「政令で定める」「法務省令で定める」→ 政令・省令の条文と数値 |
| 定義 | かっこ書の定義（「以下「○○」という。」）の範囲 |

## 4. 手順
1. `python3 scripts/statute_check.py NOTE.txt --default-law 〔主な法令名〕 --md work/statute.md` で、ノートが引く条文の一覧を作る。
2. 一覧の1行ずつ、現行の条文を開いて照らす。照らしたら、表の「番号」「限定の語」「効果・名宛人」に印を付け、照合した日を書く。
3. スクリプトが出す「食い違いの候補」（同じ条に、できる／できない など向きの違う語が付いている文の組）を読み、食い違いなら直す。多くは誤検知（原則と例外を書き分けているだけ）である。
4. 法令名の略称（民執、行手など）が、初出で正式名称に開かれているかを見る。
5. 直したら、本文・表・図・論点カードの全部で同じ言い方になっているかを見る。

## 5. 要約の規則
- 条文を要約するとき、要件の限定の語は落とさない。短くしたいなら、効果のほうを短くする。
- 条文の文言をそのまま引くときは「」に入れ、一字一句合わせる。
- 要約に自分の解釈を混ぜない。解釈は「〜と解されている」と分けて書く。
- 「条文上は明らかでないが、〜と解されている」要件は、条文上の要件と分けて書く（`techniques.md` 5）。
- 資料の要約が条文の限定を落としているときは、ノートでは限定を補い、報告に「資料の表現に条文の語を補った」と書く。

## 6. 改正があるとき
- 資料・判例が改正前の条文によっているときは、「旧○条（現○条）」と対応を書く。条番号だけでなく、規律が変わっていないかを確かめる。
- 施行日を確かめる。公布されたが未施行の改正は、その旨を書く。
- 分野ごとの主な改正は `fields/` の各ファイルの④にあるが、そこは手がかりにすぎない。必ず現行の条文で確かめる。

## 7. 報告
- 照合した条文の数と、何で照合したか。
- 資料の表現に条文の語を補った箇所。
- 確かめられなかった条文（規則・条例など）。
