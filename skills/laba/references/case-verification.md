# 判例の確認

判例は、書く前に確かめる。確かめられないものは、確かめられないと分かる書き方をする。判旨を記憶や一般論で書いて、結論を逆にした例があった。

## 目次
1. 何を確かめるか　2. 裁判所の判例検索での手順　3. 「」を使える条件　4. 確認できないとき　5. 資料が判例名を書いていないとき　6. 書誌の書き方　7. 報告に書くこと　8. 理由の出所表

## 1. 何を確かめるか
| 項目 | 確かめ方 |
|---|---|
| 存在と書誌（裁判所・年月日・登載誌・巻号頁） | 裁判所の判例検索の詳細ページ |
| 判示事項・裁判要旨 | 同じページ |
| 主文（棄却か、破棄差戻しか、破棄自判か） | 全文。要旨だけでは分からないことがある |
| 事案（当事者、何を求めたか） | 全文の「原審の確定した事実」 |
| 理由（判例自身が挙げたもの） | 全文。資料がその判例の理由として書いているものが、判決文にあるかを見る。無ければ「資料の説明」として分けて書く。判決が理由を述べていない（原審の判断を正当とするだけ）なら、そう書く |

資料が判例を説明している場合は、資料の説明と上の結果が合うかを見る。食い違うなら、資料の誤記の可能性として報告に回す。

## 2. 裁判所の判例検索での手順
- **コネクタ（laba-jp-connector）がつながっていれば、先にツールで確かめる**（`connector.md`）。ここの手作業は、コネクタが無いとき・`not_covered`・`upstream_error` のときの手順。
1. 年月日で検索する。裁判所の判例検索（courts.go.jp の裁判例検索）で、元号・年・月・日を指定する。事件名で絞れる。
2. 結果の一覧から、該当する事件の詳細ページを開く。判例集の登載箇所、判示事項、裁判要旨、参照法条が載っている。
3. 全文（PDF）を開き、主文と理由を読む。
4. 同じ日に複数の判決があることがある。法廷と事件番号で特定する。

注意：
- 一度に一つずつ問い合わせる。検索の URL は短く保つ。
- サイトが止まっていることがある。その場合は「未確認」として扱い、後で確かめる。確認できたことにしない。
- 検索の結果が0件でも、その判例が存在しないとは限らない（古い判例、下級審は載っていないことが多い）。

## 3. 「」を使える条件
- 「」で引くのは、裁判要旨か全文の原文と、一字一句一致するときだけ。旧仮名遣い・漢数字も原文のまま。
- 資料に載っている判決文の一節を引くときは、資料からの引用であることが分かるようにする。
- 言い換えには「」を付けない。
- 一つの判決の判示が複数あるとき、一部だけを引いて全体の結論と違う印象にしない。

## 4. 確認できないとき
対象：大審院の判例、多くの下級審判決、判例検索に載っていない最高裁判決、サイトの停止中。

- 判旨・事案を、記憶や一般的な紹介で書かない。
- 書くのは、資料に書かれている範囲まで。資料が書誌だけを挙げているなら、書誌と「資料が挙げる判例である」ことだけを書く。
- 本文に「この判例の内容は原典で確認してほしい」と注記し、報告にも列挙する。
- 評釈・解説（大学の紀要、判例評釈）で確かめた場合は、何で確かめたかを報告に書く。確度は裁判所の原文より下がる。
- 点検者が「記憶によれば違う」と指摘した場合も、原典で照合してから直す。照合できなければ、断定を外す。

## 5. 資料が判例名を書いていないとき
資料が「判例は〜とする」とだけ書き、年月日を示していないことがある。

- 内容から判例を特定できるなら、特定して書誌を補う。補ったのは作成者の判断なので、「資料が想定している判例と同じかは、授業・原典で確かめてほしい」と報告に書く。
- 特定に自信がないなら、「判例は」と書くにとどめる。

## 6. 書誌の書き方
- 資料があるなら、資料の表記に合わせる（「最判昭和○・○・○民集○巻○号○頁」の形か、「最判昭和○年○月○日民集○巻○号○頁」の形か）。一つのノートの中で混ぜない。
- 2回目以降は「前掲最判昭和○・○・○」。
- 同じ日に、同じ小法廷が、同じ登載誌の同じ号に載る別の判決を出していることがある。年月日だけで同定せず、事件番号か頁で確かめる。ほかのノートや見本の書誌を流用しない。
- 資料と別の登載誌を確認した場合は、資料の表記を主にして併記する。
- 改正前の条文に基づく判例は、現行の条文との対応を書く（「旧○条、現○条」）。条文そのものの確認は `statute-verification.md`。
- `scripts/cite_check.py` で、表記ゆれ・同じ判例に食い違う書誌・初出が「前掲」になっていないかを見る。この検査は形式しか見ない。書誌が正しいかは、上の確認による。

## 7. 報告に書くこと
- 裁判所のサイトで確認した判例（書誌・要旨・主文のどこまでか）。
- 確認できなかった判例と、その扱い（日付だけ、資料の範囲だけ）。
- 補った判例。
- 資料の書誌・説明と食い違った点。
- 理由の出所表の内訳（判示を確認／判決は理由を述べていない／判決文に当たれない／未確認）と、抜き書きの照合の結果。

## 8. 理由の出所表
判例の理由を書くノートでは、判例ごとに、理由の出所を1件ずつ記録する（`scripts/reason_table.py`。手順と9.5 に届く条件は `metrics/03-reason-fidelity.md`）。

| 状態 | いつ付けるか | ノートでの書き方 |
|---|---|---|
| 判示を確認 | 判決文の全文で、理由の箇所を読んだ。原文の短い抜き書き（125字以内）と、確かめた先（事件番号など）を控えた | 「判決が挙げる理由」の欄、［判示］の札 |
| 判決は理由を述べていない | 全文を読み、理由が書かれていないことを確かめた（「原審の判断は正当として是認できる」だけ、など） | 「判決自体は理由を述べていない」。理由は「資料の説明」として |
| 判決文に当たれない | 公開の判決文が無い（大審院、未登載、有料の判例集だけ） | 理由は「資料の説明」として。［判示］と書かない |
| 判決文未確認 | まだ見ていない | 渡す前に、上の3つのどれかにする |

- 全文は `scripts/case_lookup.py 年月日 --save DIR` で1件ずつ取る。取れた全文は作業用で、ノートにもスキルにも貼らない。
- 抜き書きは、裁判要旨ではなく、判決の理由の本文から取る。原文の表記（旧かな、促音の大書き）のまま写す。
- `reason_table.py check --fulltext DIR` が、抜き書きが全文にあるかを照合する（空白・句読点・促音の表記の違いは無視する）。
- 巻末に、出所表を表として載せる（`reason_table.py block`）。
