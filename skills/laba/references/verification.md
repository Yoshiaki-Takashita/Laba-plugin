# 独立点検

渡す前に、本文を書いていない点検者に点検させる。作成者が自分で照合しただけのものは、独立の点検ではない。実際に、作成者の自己検査は数値（文字数、検査の通過）は正確だったが、意味の誤り（理由のすり替え、論理の要の脱落）と数え方の甘さを見逃した。

## 目次
1. 3種の点検　2. 進め方　3. 指示文のひな形（点検A・B・C）　4. 採点も頼むとき　5. 指摘の扱い　6. 点検者を立てられないとき

## 1. 3種の点検

| 点検 | 見るもの | 渡すもの |
|---|---|---|
| A 法的正確さ | 条文（番号・項号・要件・効果・名宛人）、判例（事案・結論・理由・主文・書誌・「」の一致）、論証の構造（否認と抗弁、訴訟要件）、各ケースの結論、図の矢印とラベル | ノート、資料（あれば） |
| B 足した文の意味照合 | 言い換え・例・ざっくり理解・まとめ・表のセル・図のラベルを、資料の該当段落と突き合わせる。意味のずれ、すり替え、限定語の脱落、確度の変化 | ノート、資料、作成者の照合表（`work/added.md`） |
| C 書き手の判定 | 資料の2頁以上を実際に読み、ノートの対応箇所と読み比べて「同じ書き手に見えるか」を5段階で。浮いている文を引用と書き換え例つきで | ノートの本文、資料、文体の実測値 |

資料が無いときは A だけ。レジュメ型で手本の文体が無いときは C を省き、代わりに「説明が平易で、行間が埋まっているか」を見てもらう。

## 2. 進め方
- 点検者には、作成の経緯や作成者の自己評価を渡さない（引きずられる）。渡すのはノートと資料と、見てほしい点。
- 「修正はしない。指摘だけ」と明示する。
- 指摘の形を決めておく：「該当文の冒頭15字／何が誤りか／正しくはどうか（根拠）」。重大なものを先に。推測による指摘は、推測と明記させる。
- 字数の上限を付ける（500〜700字）。長い報告は使われない。
- 作成者の自己検査の数値は、抜き取りで検証させる（スクリプトを走らせ直す、数え方を確かめる）。

## 3. 指示文のひな形

用途別の詳しいひな形は `reviewer-prompts/` にある（法的正確さ、足した文の意味照合、書き手の判定、採点、分野別の査読、図の照合）。下は、その要点である。

### 点検A（法的正確さ）
```
〔分野〕に詳しい査読者として、講義ノート1本の法的な正確さを点検してほしい。ファイルは修正しないこと。
対象：〔ノートの場所〕　元の資料：〔資料の場所〕
確認してほしい点：
1. 条文番号とその内容の説明（〔主な条文〕）。要件・効果・名宛人・改正の前後。
2. 判例の事案・結論・理由・主文（破棄差戻しかどうか）・書誌。「」の引用が原文と一致するか。対象：〔判例の一覧〕。作成者が原典を確認していない判例：〔一覧〕は特に。
3. 設例の論証の構造（請求原因・否認・抗弁・再抗弁、訴訟要件の位置づけ）と、各ケースの結論・理由。
4. 図の矢印・ラベル・例示が本文と合っているか。
5. 資料からの拾い漏れ、論理の飛躍、言い過ぎ。
出力：〔600〕字以内。重大な誤りを先に、軽微な点を後に。各指摘は「該当文の冒頭15字／誤り／正しくは（根拠）」。推測による指摘はその旨を明記。誤りが無ければ「なし」。
```

### 点検B（足した文の意味照合）
```
講義ノートのうち、資料に足された説明だけを、資料の該当段落と突き合わせてほしい。ファイルは修正しないこと。
対象：〔ノート〕　資料：〔資料〕　作成者の照合表：〔work/added.md〕（鵜呑みにせず、抜き取りで確かめる）
突き合わせるもの：言い換えの文、具体例、「ざっくり理解」、各章の「まとめ」、表のセル、図のラベルと注記。
列挙してほしいもの：
- 意味のずれ（資料と違うことを言っている）
- 理由のすり替え（資料・判例が挙げた理由と別の理由になっている）
- 限定語の脱落（「一般には」「〜に限り」「数人による」など）
- 確度の変化（「余地がある」「要請されよう」が断定になっている、またはその逆）
- 資料にない内容なのに「（補足）」の表示がないもの
- 論理の向きを決める句（「これを認めないと」「〜でない限り」）の脱落
出力：件数と、各件「ノートの文の冒頭15字／資料の対応箇所／ずれの内容／直し方」。〔700〕字以内。
```

### 点検C（書き手の判定）
```
資料（〔場所〕）のうち3頁以上を実際に読み、ノートの本文（〔BODY.txt〕）の対応箇所と読み比べてほしい。ファイルは修正しないこと。
1. 「同じ書き手が書いたように見えるか」を5段階で（5＝区別できない、3＝内容は同じだが別人の文、1＝明らかに別の文体）。
2. 浮いている文・言い回しを、引用で10個まで。それぞれ、資料ならどう書くかの書き換え例を添える（AIらしい癖、翻訳調、説明過剰、資料が使わない語、言い直しの連続）。
3. 文体を合わせた結果、かえって分かりにくくなった箇所。
4. 丸写しに近い箇所：scripts/match_check.py を走らせ、生の値で最長の一致5件を見て、術語・定義・条文の連なりか、地の文の流用かを判定する。
出力：〔500〕字以内。
```

## 4. 採点も頼むとき
`scoring.md` の点検者が付ける項目（網羅率、技法12項目、誤りの重大度別の件数、文体5段階、①③⑤⑫、⑧の確認）を、`reviewer.json` の形で出してもらう。採点の根拠（ノートの短い引用）を付けさせる。総合の判定（資料を下回る／同等／上回る）と、渡す前に必ず直す点（最大5つ）も書かせる。

## 5. 指摘の扱い
- 重大・中程度の指摘は全部直す。軽微な指摘は、直さない理由を書けるなら残してよい。
- 点検者の指摘が記憶に基づくとき（「公式の要旨は〜のはず」）は、原典で照合してから直す。照合して作成者のほうが正しければ、直さない。
- 直したら、機械検査を走らせ直す。直しで新しい誤りが入ることがある（実例：体裁の直しで文の一部が抜けた）。大きく直したら、点検をもう一度頼む。
- 最後の版が点検を受けていないなら、そのことを報告に書く。

## 6. 点検者を立てられないとき
- 自分で一文ずつ資料と照合し、照合表を残す。
- 報告には「独立の点検は未実施。自己照合のみ」と書く。書き手の判定は「未実施」と書き、自己評価の点数を書かない。
- 総合の判定（資料を上回る、など）は出さない。
