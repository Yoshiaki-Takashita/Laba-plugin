# 10　図の採点表

図ができたら、機械の点検（`fig_lint.py`、`trace.py`）を通したうえで、六つの観点を 0〜5 で採点する。**どれか一つでも 3 以下なら直す。** 合計ではなく、いちばん低い観点で判断する（合計が高くても、正確さが 3 の図は出せない）。

採点は、図を作った本人がすると甘くなる。自分で付けた点は「自己採点」と書き、できるだけ別の点検役（`../reviewer-prompts/figure-check.md`）にも付けてもらう。

## 1　六つの観点

| 観点 | 問い |
|---|---|
| メッセージ | この図で分かることを一文で言えるか。図を見てそれが伝わるか |
| 正確さ | 条文・判例・設例・本文と食い違う所がないか。矢印の向き、言い切り、限定語、数字 |
| 可読 | 字が読めるか。重なり・切れ・詰まりがないか。語で書いてあるか |
| 構図 | 型が内容に合っているか。配置が整い、強調が一点に絞られているか |
| 本文との一致 | 図の語が本文にあるか。図を指す文があるか。番号が順か |
| 難所の解消 | この図を見ると、読み手のつまずきが解けるか。結論が分かれる理由が見えるか |

## 2　点の目安

### メッセージ

| 点 | 状態 |
|---|---|
| 5 | 図題を読まなくても、図を見ればメッセージが分かる。強調がメッセージの核を指している |
| 4 | 図題を読めばすぐ分かる。図にメッセージと関係のない要素がない |
| 3 | 図題を読めば分かるが、図のどこを見ればよいかを探す。余分な要素がある |
| 2 | メッセージが二つ混ざっている。または主題（「〜について」）にとどまる |
| 1 | 何を言いたい図か分からない |
| 0 | メッセージがない（箱を並べただけ） |

### 正確さ

| 点 | 状態 |
|---|---|
| 5 | 矢印・言い切り・限定語・条文番号・数字のすべてを、本文と原文（条文・判決）で確かめた。食い違いなし |
| 4 | 本文との食い違いなし。条文・判例は本文の側で確かめてある |
| 3 | 誤りではないが、誤解を招く書き方がある（限定語の省略、例外に触れない言い切り） |
| 2 | 細部に誤りがある（条文の項・号、日付、段の順） |
| 1 | 結論に関わる誤りがある（矢印の向き、勝ち負け、成立不成立） |
| 0 | 複数の誤り、または根拠のない内容 |

正確さが 3 以下の図は、ほかの観点が何点でも出さない。

### 可読

| 点 | 状態 |
|---|---|
| 5 | 150mm 幅で刷って、全部の字が楽に読める。重なり・近接なし。ラベルは語で、長すぎない |
| 4 | 読める。長いラベルが一つ二つあるが、折り返しが意味の切れ目にある |
| 3 | 読めるが詰まっている（線図で空白が五割を切る。表の形の図＝比較・マトリクス・条文の構造・積み上げ・座標・価値配分・審級は、四割を切る）。または折り返しが語の途中にある。線の横の語が三行以上・箱の語が四行以上 |
| 2 | 字と線が近すぎる、記号だけのラベルがある、長文のラベルがある |
| 1 | 字が重なる・切れる所がある |
| 0 | 読めない |

### 構図

| 点 | 状態 |
|---|---|
| 5 | 型が内容の形に合い、目が自然に読む順に進む。そろえ・間隔が整い、強調は一点 |
| 4 | 型は合っている。配置に小さな不揃い（列の下端の差、片寄り）がある |
| 3 | 型は合うが、強調が散っている（三か所以上）。または空白が片寄っている |
| 2 | もっと合う型がある（比較なのに当事者図、流れなのに表のような図） |
| 1 | 型が内容に合っていない。線が交差して追えない |
| 0 | 配置が崩れている |

### 本文との一致

| 点 | 状態 |
|---|---|
| 5 | `trace.py` で「語あり」＋「語あり（語ごと）」が九割五分以上、所見（「なし」・T01〜T07）は直したか理由つきで退けた、読み上げの表が全部済んでいる。図を指す文が直前にあり、本文が図より先に書かれている |
| 4 | 九割以上、「なし」0、T01〜T03 が 0。T04・T05 は人が読んで問題なし |
| 3 | 「一部の語」が目立つ（言い回しが本文と違う）。または図を指す文が離れている |
| 2 | 「なし」がある（断りなく図だけにある語）。または図を指す文がない |
| 1 | 図の数字・条文番号が本文にない（T01） |
| 0 | 本文と別の内容の図 |

### 難所の解消

| 点 | 状態 |
|---|---|
| 5 | 結論が分かれる理由が、図の形そのものから見える。この図がなければ文章を三段落読む必要がある |
| 4 | 理由が図から読み取れる。文章の理解を確かに助ける |
| 3 | 事案や項目の整理にはなるが、「なぜそうなるか」は図から見えない |
| 2 | 難所でない所の図。または当事者を並べただけ |
| 1 | 文章を読めば足りる内容を図にしている |
| 0 | 図があることで、かえって分かりにくい |

## 3　採点の手順

0. 採点は、作成の経過を見ていない点検役がする（`../reviewer-prompts/figure-check.md`）。作った本人の採点は、直す所を探すための下書きで、成績として記録しない。独立の点検では、本人の採点より平均で 0.3 低く、見た目は 5 点満点の 3.5 だった。
1. 機械の点検を回す：`fig_lint.py` の error 0。`trace.py --strict` の所見（T01・T06・T07・「なし」）は、直したか、図を変えずに理由つきで退けた。所見を消すために要件の語を削った図は、正確さを 3 以下にする。
2. PNG を 150mm 幅に相当する大きさで見る（拡大して採点しない）。
3. 図題を隠して図だけを見て、メッセージを一文で言ってみる。言えた文を図題と比べる（メッセージ）。
4. 読み上げの表を作る（`../reviewer-prompts/figure-check.md` 2）。矢印・止め線・枠・枝・小枝・時点・条文番号を一つずつ文にし、本文と突き合わせる。言い切り・限定語・数字を照合する（正確さ・本文との一致）。`trace.py` の「機械で見ない種類」は表の中で必ず見る。
5. 字の重なり・詰まり・折り返しを見る（可読）。
6. 目の動く順、強調の数、空白の片寄りを見る（構図）。
7. 「この図がなかったら、本文だけで同じことが分かるか」を問う（難所の解消）。
8. 六つの点と、いちばん低い観点の理由を一行にまとめる。3 以下があれば、直す所を添える。

採点の前提：

- 「本文との一致」は、本文が図より先に書かれているときだけ意味を持つ。図に合わせて本文を書いたときは、この観点を採点せず「本文を後から書いた」と記録する。
- 強調の数は、箱の数ではなく主張の数で数える。比較図で違いが出る段を全列強調したものは一点。原因の段と帰結の段を合わせて三箱までの道筋も一点。二つの段・二つの道筋を強調していたら「構図」を 3 以下にする。
- 同梱の用例をそのまま採点しても、エンジンの出来は分からない。採点は、用例にない題で、本文を先に書いて作った図で行う。

## 4　記録の形

```
図3（chain-nijujoto）点検役の採点　2 巡目
  メッセージ 5／正確さ 5／可読 5／構図 4／本文との一致 5／難所の解消 4
  いちばん低い観点：構図 4（第二譲受人の箱の右に空白が残る）
  直す所：なし（4 以上）
  機械：fig_lint error 0・warn 0、trace 所見なし（機械で見られる範囲で）・照合できなかった要素 2（読み上げの表で確認）
```

## 5　3 以下が出たときの直し方

| 低い観点 | まず見る所 |
|---|---|
| メッセージ | メッセージを一文で書き直す。図を二つに分ける。関係のない要素を落とす（`00-principles.md` 2節） |
| 正確さ | 本文と原文を読み直す。矢印の `from`／`to`、言い切り、限定語（`06-traceability.md` 3節） |
| 可読 | 語を減らす。`|` で意味の切れ目に改行を入れる。段を減らす・図を分ける（`03-layout.md`） |
| 構図 | 型を選び直す（`../algorithms/figure-type.md`）。強調を一つに絞る。`pos` を組み替える |
| 本文との一致 | ラベルを本文の語に直す。本文に図を指す文を足す。番号を振り直す |
| 難所の解消 | 型を「仕組みが見える型」に替える（比較・流れ・時間軸・積み上げ・複合）。成立しない場合を並べる |

直したら、機械の点検から採点までをもう一度行う。三巡しても 4 に届かないときは、その難所は図に向いていない。表か「ざっくり理解」に切り替える。

## 6　機械の項目との対応

| 観点 | 機械が見ている項目 | 機械では見えないもの |
|---|---|---|
| メッセージ | `cli.js`：`message` がない・図題の形／`fig_lint` W01（強調がない・多すぎる） | メッセージが伝わるか |
| 正確さ | `trace.py` T01・T04・T05・T06（向き・勝ち負け・効果の取り違え）・T07（組合せが本文にない） | T08 に回った関係、機械が取り出さない型（時間軸・数直線など）、内容が法的に正しいか |
| 可読 | `fig_lint` E03・E05・E06・E07・E09・E11・E12、W02・W05・W06・W09・W11・W12・W13／`cli.js`：「語の途中で折れた」「線が箱を貫通する」 | 辞書に無い語の折り返し、記号（破線・点線・箱の形）の意味が読み手に通じるか |
| 構図 | `fig_lint` E04・E08、W03・W04・W07 | 型が内容に合うか |
| 本文との一致 | `trace.py` の語の照合（語あり・なし）・T02・T03 | 意味が合っているか |
| 難所の解消 | なし | すべて |

機械が通っても、採点は省かない。機械が見ているのは、六つの観点の一部だけである。`trace.py` の追跡率 100% や「所見なし」は、語が本文にあり機械の見る範囲で所見がないという意味で、正確さの保証ではない（`06-traceability.md` 2節）。
