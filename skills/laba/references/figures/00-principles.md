# 00　図の原則

図は、文章では伝わりにくい「関係」「順序」「違い」を一目で分からせるために置く。飾りのためには置かない。ここでは、どの型の図にも共通する原則を並べる。個々の型は `02-types/`、機械の点検は `scripts/fig_lint.py`、採点は `10-quality-rubric.md` を見る。

## 1　図を置くかどうかを先に決める

図にする前に、次の三つを順に確かめる。一つでも「いいえ」なら、図にしないで文章か表にする。

| 問い | 「はい」の例 | 「いいえ」の例 |
|---|---|---|
| 読み手はここでつまずくか（難所か） | 証明責任が被告ごとに逆向きになる。基準時が要件ごとに違う | 定義を一つ述べるだけ |
| つまずきの原因は、関係・順序・違いのどれかか | 三者の間で請求が行き来する。四つの時点がある。二つの型で帰結が逆になる | 用語が難しいだけ（言い換えで足りる） |
| 図のメッセージを一文で言えるか | 「登記を先に備えた方が優先する」 | 「二重譲渡について」（主題であって主張ではない） |

難所でない所に図を置くと、読み手は大事な図とそうでない図を見分けられなくなる。一つの章で図は多くても三つか四つまでとし、難所に集める。

## 2　一つの図に一つのメッセージ

- メッセージは、主語と述語のある一文で書く。「AのときはXだが、BのときはYになる」「Pは、QとRがそろって初めて成立する」。
- その一文を、仕様（JSON）の `message` に書く。図題（`caption`）の「この図で分かること：」に続く文も同じ内容にする。
- 一文に「また」「さらに」が入るなら、図を二つに分ける。分けた二つを見比べさせたいなら、複合図（`panel`）にして同じ枠で上下に並べる。
- 図に入れる語は、そのメッセージに必要なものだけにする。関係する事情を全部入れると、何の図か分からなくなる。入れなかった事情は本文に書く。

## 3　図は難所を解く仕組みを見せる

当事者の名前を箱に入れて線で結んだだけの図は、事案の紹介であって、難所を解いていない。図には、結論が分かれる**理由**が見える形を選ぶ。

| 難所 | 弱い図 | 難所を解く図 |
|---|---|---|
| 二人の被告に両方負ける危険 | 原告と被告二人を線で結ぶ | 被告ごとに「誰が証明責任を負うか→真偽不明のとき→帰結」を縦に追い、二つの型を左右に並べる |
| 法定地上権の成否 | 成立する場合の時間軸だけ | 成立する場合としない場合を同じ時間軸で上下に並べ、基準時の状態の違いを強調する |
| 共同正犯と幇助の区別 | 三つの類型の一覧 | 問いを順に当てはめて類型に行き着く流れ |
| 却下と棄却の違い | 用語を二つ並べる | 訴訟要件の関門をすべて通った先に本案審理があり、途中で外れると却下に落ちる流れ |

図の型は、内容の形で決まる。決め方は `../algorithms/figure-type.md` の表による。

## 4　強調は一点

- 色は三つだけ。黒（#1A1A1A）は図の本体、灰（#8C9493）は文脈・補助線、えんじ（#943522）は強調。
- 強調するのは、争点・分かれ目・変わった所のどれか一つ。二つの型を比べる図なら、違いが出る段だけ。時間軸なら、基準時だけ。
- 「一点」は、一つの主張に当たる範囲のこと。箱の数ではない。比較図で違いが出る段を強調するなら、その段の列は全部強調してよい（一段＝一点。三列まで）。原因の段と帰結の段をつなぐ道筋を強調するなら、箱は三つまで。同じ図で二つの段・二つの道筋を強調しない。
- 強調が三か所を超えたら、どれも強調でなくなる。機械は、強調が要素の三割を超えると警告する（W01）。
- 文字は必ず黒。強調したい語は、枠か線をえんじにし、文字の色は変えない。
- 図題に「強調は…」と意味を書く。色の意味を読み手に当てさせない。

## 5　語で書く

- ラベルは語にする。「A」「X」「①」だけの箱を作らない。記号を使うときは「債務者 A」「① 売買」のように語を添える。機械は、記号だけのラベルが三つ以上あると誤り（E09）とする。
- 一つのラベルは二行・十六字までを目安にする。それより長い説明は、図題か本文か図の下の注に回す。箱の中の語が四行以上、線の横の語が三行以上になったら、機械が警告する（W11・W12）。
- 折り返しは、条文番号（「民法424条の2」「203条1項」）、判例の表記、熟語、短い括弧の途中に入れない。エンジンがこの規則で折る（`03-layout.md` 11節）。入らないときの順は、語を減らす→箱を広げる→見出しの字を下げる→図を分ける。
- 勝ち負け・成立不成立・できるできないは、言い切りの形で書く。「原告が負ける」「成立しない」。本文の言い切りと同じ向きであることを必ず確かめる（過去の失敗：図では「勝つ」、本文では「負ける」）。
- 限定語を落とさない。本文が「数人による登記請求」なら、図も「数人による」を付ける。
- 図に補った説明（本文にない事情）には「（補足）」と付ける。

## 6　線と矢印は意味を持つ

- 矢印は、向きのある関係（請求・移転・時間の進み・判断の進み）だけに使う。向きのない関係（対抗しあう・身分関係）は矢じりのない線か、両矢印にする。
- 矢印の元と先は、必ずその関係の当事者の箱に付ける。箱を一つ間違えると意味が逆になる。機械は、矢印の先や元が何にも届いていないと誤り（E10）とするが、「違う箱に届いている」ことは機械では分からないので、人が一本ずつ読む。
- 流れ図では矢印を省かない。箱を並べただけでは順序が読めない。
- 線の太さは二種類（細 0.9、太 2.5。約 1：2.8）。太い線は強調か主役だけ。
- 線の種類は三つまで。実線（確かな関係・条文や判例にある関係）、破線（争いのある関係・仮定・対抗関係）、点線（補助）。
- 届かないこと・及ばないことは、矢印を途中で止めて、短い止め線を付ける。
- 線は、つないでいない箱の中を通さない。別の関係の線と同じ筋に重ねない。どちらも、図の意味を読み違えさせる（機関設計の図で、斜めの線が真下の箱を貫通し、別の線に重なって、監査の向きが逆に読めた）。エンジンは貫通と重なりのない経路を選び、選べないときは警告する。機械は E11・E12 で止める。
- 「ない」ことは、ある形で描かない。成立しない・消滅した・及ばない状態の帯や括りを、太い実線で描かない（破線か灰の細線にする）。
- 権利の行使と手続上の行為（訴訟告知・通知）を、同じ線で描かない。手続上の行為は点線の矢印にし、凡例で断る。
- 人でないもの（物・書類、権利、手続、会議体の機関）は、箱の形で人と分ける。色は増やさない（`01-grammar.md` 11節）。

## 7　余白を残し、片寄らせない

- 図の中の空白は六割前後を目安にする。機械は、五割を切ると「詰めすぎ」、九割を超えると「要素が少なすぎる」と警告する（W05）。比較図やマトリクスのように字の多い型は五割を少し切ることがあるが、四割を切ったら語を減らすか図を分ける。
- 左右・上下で要素の量が大きく違う図は組み直す（W03）。片側に大きな空白の列ができる配置は、過去に何度も減点された。
- 並んだ列の下端はそろえる（W04）。
- 文字と線、文字と文字を重ねない（E06・E07）。文字は図の端から離す（E05）。

## 8　本文と一緒に読めるようにする

- 図は、それを指す文（「図3で確かめる」）のすぐ後に置く。図より後ろにしか説明がない配置にしない。
- 図の番号は、本文に出てくる順に付ける。
- 図の幅は版面いっぱい（150mm）を基準にする。図の中の字は約 8.6pt と 9.8pt の二種類で、本文（10.5pt 前後）より少し小さい程度になる。縮めて貼ると本文より大幅に小さくなるので、縮めない。
- 図に書いた語は、本文のどこかで説明されていること。`scripts/figgen/trace.py` で照合する（`06-traceability.md`）。

## 9　使わないもの

角丸、影、グラデーション、塗りつぶしの色面、丸で囲んだアイコン、吹き出し、ピル型のラベル、立体表現、凡例の箱（線の意味は線の横か図題に書く）、三色以外の色、二種類を超える文字サイズ。これらは情報を増やさず、紙面をうるさくする。機械はこのうち色・影・グラデーション・角丸・文字サイズを誤りとして止める（E01・E03・E08）。

## 10　作る順序

1. 難所を一つ選ぶ（`../algorithms/figure-type.md` の手順1）。
2. メッセージを一文で書く。
3. 型を決める（同じ表）。
4. 仕様（JSON）を書く。語は本文から取る。
5. `node scripts/figgen/cli.js spec.json out.svg --png` で作る。
6. `python3 scripts/fig_lint.py out.svg --spec spec.json` で機械の点検（誤り 0 にする）。
7. `python3 scripts/figgen/trace.py spec.json --body 本文.md --fig N` で本文と照合。
8. PNG を目で見る。矢印を一本ずつ、本文の文と突き合わせる。
9. `10-quality-rubric.md` で六つの観点を採点する。どれかが 3 以下なら直す。
10. 別の点検役に `../reviewer-prompts/figure-check.md` で見てもらう。

## 11　過去の失敗から決めたこと

| 失敗 | 決めたこと | どこで防ぐか |
|---|---|---|
| 矢印が違う箱から出ていて意味が逆になった | 矢印は一本ずつ本文と突き合わせる | 点検役・`../checklists/04-figures.md` |
| 限定語（「数人による」）が図で落ちた | ラベルは本文の語をそのまま使う | `trace.py` T05・点検役 |
| 図では勝ち、本文では負けだった | 言い切りの向きを照合する | `trace.py` T04・点検役 |
| 文字と線が重なった・端で切れた | 機械で止める | `fig_lint.py` E05〜E07 |
| 右側に四割の空白の列ができた | 列の幅を内容に合わせ、中央に寄せる | `fig_lint.py` W03、エンジンの配置 |
| 図が広すぎて字が本文より小さくなった | 幅 150mm で作り、縮めない | `fig_build.js --width-mm` |
| 図の番号が本文の順と違った | 番号は本文の順 | `trace.py` T03 |
| 当事者を並べただけで難所を解いていなかった | 仕組みが見える型を選ぶ | `10-quality-rubric.md`「難所の解消」 |
| 注に主語がなく、何についての留保か分からなかった | 注は主語のある完全な文 | `05-caption.md` |
| 本文にない説明を図に入れたのに印がなかった | 「（補足）」を付ける | `05-caption.md`・`06-traceability.md` |
| 図が、それを指す文から遠かった | 指す文のすぐ後に置く | `trace.py` T02・`07-composition.md` |
| 斜めの線が、つないでいない箱を貫通し、別の線に重なって、関係が逆に読めた（機関設計の五者の図） | 経路は「貫通しない・重ならない」ものを候補から選ぶ。選べなければ警告して配置を変えさせる | エンジンの経路・`fig_lint.py` E11・E12・回帰試験 |
| 語が全部本文にあり追跡率は 100% なのに、勝ち負けが入れ替わっていた・対抗の矢印が逆だった・効果を別の類型に書いていた | 語ではなく、組合せ（誰について・誰から誰へ・どうなる）を照合する | `trace.py` T06・T07、点検役の読み上げ |
| 条文番号や熟語の途中で折れた（「（381条／1項）」「公認会／計士」「事情をさ／らに」） | 折ってはいけない所を辞書と規則で決める | エンジンの折り返し・`fig_lint.py` W13・回帰試験 |
| 「成立しない」を太い実線の帯で描いた（形が意味と逆） | 「ない」状態は破線か灰の細線 | エンジンの warn・点検役 |
| 流れ図の出口の箱だけが大きく、右の列の上が空いた | 出口の箱は中身の高さ。枝の下に、落ちる例を一行で置く | エンジンの配置・`fig_lint.py` W03 |
| 用例の条文の文言が、改正前のままだった（民訴法285条の控訴期間の起算点。現行は「電子判決書」の送達） | 用例・型解説の条文は、法令の現行の原文で照合する | 回帰試験（古い文言の検索）・`README` の照合の記録 |
| 用例に、書き込み用の文言（「理由の要点を一行で…」）が残っていた | 用例は、そのまま読める完成した図にする | 回帰試験 |
| 作った本人の採点が、別の人の採点より高かった | 採点は、作成の経過を見ていない点検役の点を採る。本文は図より先に書く | `10-quality-rubric.md` 3節・`../reviewer-prompts/figure-check.md` |
