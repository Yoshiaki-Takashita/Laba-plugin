# 02　図の型（25）

型は、内容の形で決まる。難所の性質から型を選ぶ手順は `../../algorithms/figure-type.md`。ここには型ごとに「いつ使うか・使わないとき・要素・作り方・よくある失敗・最小の仕様・仕様を書くときに迷う所・仕様の例・分野別の用例」がある。メッセージの形から型を選ぶ早見は `scripts/figgen/README.md` 3 節。

## 迷ったとき

- 当事者を並べたくなったら、まず「この図で結論の理由が見えるか」を問う。見えないなら、比較図・流れ図・積み上げ図・時間軸のどれかにする。
- 二つの型で迷ったら、メッセージの一文の形で決める。「AのときはX、BのときはY」→比較図。「PはQ・R・Sがそろって成立する」→要件効果の木。「まずP、次にQ、外れたらZ」→流れ図。「Pの時点でQであればR」→時間軸。
- どの型にも入らないなら、図にしない。表か「ざっくり理解」で手当てする。
- 期間の長さ・重なりそのものが主題なら、時間軸より先に数直線を当てる。条件→義務の条文が並ぶ規則の束（機関設計の要否など）は決定木。
- 人でないもの（物・書類・権利・手続・会議体の機関）、範囲（判決の効力が及ぶ者）、基準時からの補助線、凡例、注記の吹き出しは、型ではなく部品として足す（`../01-grammar.md` 11節、用例 `parties-hanketsuko-hani`・`parties-daihyososho`）。
