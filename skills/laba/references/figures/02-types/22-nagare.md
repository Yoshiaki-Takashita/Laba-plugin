# 22　流れ図

判断や手続が段階を踏み、途中で外れると別の結論に落ちる様子を、上から下への箱と矢印で描く。

- レンダラ：`flow`（`scripts/figgen/lib/renderers/flow.js`）
- 用例：`scripts/figgen/specs/flow-torikeshisosho.json`

## いつ使うか

- 関門を順に通る判断（訴訟要件、犯罪の成立要件、審査の段階）
- 外れたときの結論が同じ（却下、不成立）で、最後まで通ったときだけ別の結論になるとき
- 一本道の手続を横に並べるとき（`direction:"right"`）

## 使わないとき

- 枝ごとに結論が違い、深く分かれるとき（決定木）
- 主体が何人も関わるとき（スイムレーン）
- 枝分かれのない一本道で、段が三つ以下（番号付きの文で足りる）

## 要素

- 太字の一行目＝段の名前。二行目＝問いの中身と条文
- 下向きの矢印＝通ったとき。横に「満たす」
- 右向きの線＝外れたとき。上に「当たらない」「欠ける」、下にその段で落ちる例を一行（`exit.eg`）。出口が同じなら一本の縦線に集めて箱を一つにする
- 出口・終点の箱＝結論。下辺が太い。出口の箱は中身の高さで、二行目に帰結を一行（`exit.sub`）
- えんじ＝最後まで通った先（本案審理、犯罪の成立）

## 段の中の小枝（例外）

ただし書・適用除外・例外の手続を、注ではなく図の中に出すときは、段に `branch` を付ける。段の箱の下の部分に、点線の区切りの下で「枝の語 →［小さな箱］」を置く。二つまで（三つ目以降は warn を出して描かない。段を分けるか注に回す）。右向きの流れ図（`direction:"right"`）でも小枝と段ごとの通過の語（`steps[].pass`）は描かれる（第5回で直した。箱が狭いので「枝の語 ↓［小さな箱］」を縦に積む）。小枝の語が長いときは下向きにする。

```json
{"text": "会社に提訴請求をしたか", "sub": "847条1項", "pass": "した", "exit": {"label": "していない", "text": "訴えを提起できない"},
 "branch": [{"label": "回復できない損害のおそれ", "text": "直ちに訴えを提起できる", "sub": "847条5項"}]}
```

`trace.py` は、小枝を「〔段〕に〔枝の語〕なら〔小さな箱〕」として本文と照らし、二行目の条文番号がその語と同じ文にあるかも見る。ただし、**小枝がどの段に付いているか（小枝の帰属）は機械では見ない**。点検役が読み上げの表で「〔段〕のうち〔小枝の語〕なら〔小枝の箱〕」と読み、本文がその例外をその段で述べているかを確かめる（`../../reviewer-prompts/figure-check.md`）。

## 作り方

1. 段を判断の順に並べ、`steps` に書く。外れたときの出口を `exit` に
2. `pass` に通ったときの語、`end` に終点
3. 出口の箱が全部同じなら、エンジンが一つにまとめる。右の列が空くので、`exit.eg` に落ちる例を入れる
4. 段ごとに出口が違うなら、段の右に箱が並ぶ
5. 注に、流れに入らない留保を書く

## よくある失敗

| 失敗 | 直し方 |
|---|---|
| 箱を並べただけで矢印を省いた | 矢印を省かない。順序が読めなくなる |
| 却下（訴訟要件を欠く）と棄却（本案で負ける）を同じ出口にした | 出口を分ける。意味が違う |
| 段の順が判断の順と違う | 資料・判例の検討の順に合わせる |
| 並べた順を、法律が定めた審査の順のように書いた | 順が法定でないなら、図題に「並べた順は説明の順」と断る |
| 出口の箱だけが大きく、右の列の上が空いた | 出口の箱は中身の高さ（エンジンの既定）。枝の下に例を置く |
| 出口ごとに同じ箱を四つ並べた | 一本の線に集める（エンジンの既定） |

## 最小の仕様

`flow` で図になる最小の形。ここから項目を足す（全部の項目は `scripts/figgen/README.md` 5 節）。

```json
{"type":"flow","message":"…。","caption":"図N　…",
 "steps":[{"text":"訴訟要件を満たすか","exit":{"label":"満たさない","text":"訴えの却下"}}],
 "pass":"満たす","end":{"text":"本案の審理","accent":true}}
```

## 仕様を書くときに迷う所

| 迷う所 | 答え |
|---|---|
| 出口の語はどこに書くか | `exit.label`＝枝の上、`exit.text`＝出口の箱、`exit.sub`＝箱の二行目（帰結）、`exit.eg`＝枝の下の一行（例） |
| 段ごとに違う「通ったとき」の語 | `steps[].pass`（全部同じなら上位の `pass`） |
| 出口を段ごとに置きたい | 出口の語が違えば自動で段ごと。同じ語でも分けるなら `mergeExits:false` |
| 段の中で小さく枝分かれする | 流れ図では持てない。決定木にするか、図を分ける |

## 仕様の例

そのまま `node cli.js` に渡せば生成できる（図題の「図N」は、ノートでの番号に置き換える）。

```json
{
  "type": "flow",
  "message": "取消訴訟は、訴訟要件を一つでも欠けば却下され、すべて満たして初めて本案の審理に入る。",
  "caption": "図N　この図で分かること：取消訴訟の訴訟要件は、一つでも欠ければ訴えが却下され、すべて満たして初めて本案審理に進む。上から下へ読む（並べた順は説明の順で、審査の順が法律で決まっているわけではない）。強調は本案審理。",
  "steps": [
    {"text": "処分性", "sub": "処分その他公権力の行使に当たる行為か（行訴法3条2項）", "exit": {"label": "当たらない", "text": "訴えの却下", "sub": "本案の判断に入らない", "eg": "例：行政指導、通達"}},
    {"text": "原告適格", "sub": "取消しを求めるにつき法律上の利益を有する者か（9条1項）", "exit": {"label": "有しない", "text": "訴えの却下", "eg": "例：法律上保護された利益がない"}},
    {"text": "訴えの利益", "sub": "処分の効果がなくなった後も、回復すべき法律上の利益が残っているか（9条1項かっこ書）", "exit": {"label": "消滅した", "text": "訴えの却下", "eg": "例：期間の経過、工事の完了"}},
    {"text": "被告適格・管轄・出訴期間など", "sub": "11条、12条、14条ほか", "exit": {"label": "欠ける", "text": "訴えの却下", "eg": "例：出訴期間を過ぎた"}}
  ],
  "pass": "満たす",
  "end": {"text": "本案審理", "sub": "処分は違法か。違法なら請求認容（事情判決を除く）", "accent": true},
  "notes": ["枝の下の例は、要件を欠く典型を一つずつ挙げたもので、個別の事案での判断は判例による（補足）。"]
}
```

```
node scripts/figgen/cli.js check scripts/figgen/specs/flow-torikeshisosho.json      # 仕様の検証
node scripts/figgen/cli.js scripts/figgen/specs/flow-torikeshisosho.json out.svg --png
python3 scripts/fig_lint.py out.svg --spec scripts/figgen/specs/flow-torikeshisosho.json
python3 scripts/figgen/trace.py scripts/figgen/specs/flow-torikeshisosho.json --body 本文.md --fig N --strict
```

## 分野別の用例

- 行政法：取消訴訟の訴訟要件、申請に対する処分の審査
- 刑法：構成要件該当性→違法性→責任、共犯の類型の判定
- 憲法：保障範囲→制約→正当化
- 民訴：訴訟要件の審理、上訴の適法要件
- 民法：契約の成立→有効→効果帰属→効力発生
- 会社法：決議の瑕疵の判定
