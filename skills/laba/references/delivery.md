# 渡し方

## 目次
1. 渡すもの　2. 報告の型　3. 資料の誤記の扱い　4. 版管理　5. 途中経過の伝え方　6. 言ってはいけないこと

## 1. 渡すもの
- ノート（.docx）。利用者が別の形式を求めたら、それに従う。GNOTO のノート（.gnoto）を求められたら、内容を確定してから `${CLAUDE_PLUGIN_ROOT}/skills/gnoto-lite/SKILL.md` に従って書く（このプラグインに gnoto-lite が入っているときだけ。単体の laba では Word で渡し、GNOTO 化は別に頼むよう伝える）。
- 利用者が求めたときだけ：採点表、作業ファイル（一覧、照合表）。ふだんは報告に要点だけ書く。
- 資料の書き起こしテキストは渡さない（作業用）。

## 2. 報告の型
短く書く。読み手は、ノートを開く前に「何ができたか、どこを信用してよいか、どこを自分で確かめるべきか」を知りたい。

1. 一文で：何のノートが何頁でできたか。点検を受けたか。
2. 中身：構成（章立てを1〜2行）、図（何を示す図が何枚）、表。
3. 各ケース・各設問の結論（ある場合）。1行ずつ。ノートとしての判断で書いた結論は、そう書く。
4. 判例の確認状況：確認できたもの／できなかったもの（その扱い）／補ったもの。条文の確認状況：照合した数と方法、資料の表現に条文の語を補った箇所。
5. 資料の誤記と思われる箇所。
6. 授業・原典で確かめてほしい点（資料が結論を示していない所、作成者の解釈を入れた所）。
7. 採点を回した場合：総合点、判定、誤りの件数、未採点の項目、最後の版が点検を受けたか。

書き方：
- 結論から。作業の経過は書かない。
- 作業中の呼び名（ラウンド番号、ファイルの略称、スクリプト名）を使わない。利用者が知らない言葉は、言い換える（「一致の検査」→「資料と同じ文が続く箇所を数えた結果」）。
- 数字には、何の数字かを添える。
- 確かめていないことを、確かめたように書かない。

## 3. 資料の誤記の扱い
- 本文では、正しいと考える形で書く。紛らわしい所だけ、本文で一言触れる。
- 黙って直さない。報告に「資料の○頁の『A』は『B』の誤りと思われる」と列挙する。
- 誤記か、作成者の読み違いか、判断がつかないものは「〜かもしれない。確かめてほしい」と書く。
- 資料どうし・資料の中で食い違う所（ある頁では○○、別の頁では△△）も報告する。

## 4. 版管理
- 修正は、言われた箇所だけ直す。関係のない所を書き換えない。
- 版番号を上げ（_v2、_v3）、前の版を残す。「やはり前のがよい」に戻れるようにする。
- 何を変えたかを3行以内で書く。
- 体・構成を大きく変える版では、前の版で良かった文が消えていないかを確かめる。

## 5. 途中経過の伝え方
長い作業（採点を回す、複数の回をまとめる）では、節目ごとに短く伝える。
- 何が終わり、何が分かったか（数値があれば表で）。
- 次に何をするか。
- 利用者に決めてほしいことがあれば、最後に、選びやすい形で。

## 6. 言ってはいけないこと
- 点検を受けていない版を「点検済み」と言う。
- 自分で付けた点・自分で数えた値を、独立の評価のように言う。
- 「完璧」「誤りはない」。言えるのは「点検者が見つけた誤りは直した」「この範囲では見つからなかった」まで。
- 資料なしで作ったノートを、網羅していると言う。
