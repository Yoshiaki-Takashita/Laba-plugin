# 合議（意見分離アルゴリズム）

法の解釈には、条文と判例を正確に読んだうえでも結論が分かれる点がある。最高裁の小法廷は、考え方の違う5人が同じ記録を読み、多数意見・補足意見・意見・反対意見に分かれることで、判断の根拠と限界を外から見える形にしている。この文書は、それを担当（`agents/justice-*.md` の5人）で行う手順である。

目的は「多数決で正解を決めること」ではない。**結論がどの前提で分かれるか（分かれ目）を取り出し、どちらの立場でも答案を書ける材料を残すこと**である。

## 目次
1. 二つの領域（ここが土台）　2. いつ開くか　3. 5人の立場　4. 争点票　5. 第1回（独立）　6. 分かれ目の抽出　7. 第2回（応答）　8. 評決と意見の種類　9. 法的点検による線引き　10. ノート・レジュメへの載せ方　11. してはいけないこと　12. 担当を立てられないとき　13. ファイル

## 1. 二つの領域

| 領域 | 中身 | 合議での扱い |
|---|---|---|
| 確定領域 | 条文の文言・番号・施行の時点。判例の主文・結論・判決文に書かれた理由・書誌。資料に書かれた事実。`work/verified/` で found のもの | **全員が同じものを前提にする。意見は分かれない。** これに反する記述は「反対意見」ではなく誤りであり、法的点検が削る |
| 開かれた領域 | 条文の文言が複数の読みを許す点。判例が判断していない点、射程の内か外か。規範への当てはめ（評価）。判例の当否 | 意見が分かれてよい。分かれたら、そのまま記録する |

判例の当否を論じること（「この判例の結論には反対である」）は開かれた領域である。判例の内容を違えて書くこと（「この判例は〜と判示した」が判決文と合わない）は確定領域の誤りである。この二つを混ぜない。

## 2. いつ開くか

合議は重い（5人×2回）。次のときだけ開く。1つのノートで開く争点は、通常3つまで（利用者が求めたときは別）。

- 設例の結論が、評価（「正当な理由」「相当の期間」「背信的」など）や、判例の射程の読み方で変わるとき。
- 資料・教科書が「争いがある」「見解が分かれる」と書いている論点で、利用者が結論を求めているとき。
- 判例研究の「検討」（判旨に賛成か反対か、射程はどこまでか）。
- 利用者が「どう考えるべきか」「反対の立場からは」と聞いたとき。
- 節の執筆・法的点検が `gogi_requests`・区分 D（見解の相違）として挙げた点。

開かないとき：条文を読めば決まる点。判例がその事案類型について結論を示しており、設例がその範囲に明らかに入る点（判例の立場を書けば足りる。利用者が当否を聞いたときは開く）。速さ優先の依頼。

## 3. 5人の立場

5人は、同じ確定領域を前提に、解釈の方法が違う。どれも法律家の正統な方法であり、どれかが誤りなのではない。詳しい設定は各担当のファイル。

| 担当 | 立場 | 最初に問うこと | 重く見る価値 |
|---|---|---|---|
| `justice-bunri` | 文理・体系 | 条文は何と書いているか。体系のどこに置かれているか | 法的安定性、予測可能性、立法と司法の役割分担 |
| `justice-shushi` | 趣旨・利益衡量 | この規定は何を守るためにあるか。当事者の利益状況はどうか | 具体的妥当性、制度趣旨の実現、弱い立場の保護 |
| `justice-hanrei` | 判例・射程 | 先例は何を、どの事実について判断したか。本件はその内か外か | 先例との整合、同種事案の平等、一歩ずつの法形成 |
| `justice-tetsuzuki` | 手続・要件事実 | 誰が何を主張立証するか。その規範は裁判で使えるか | 手続保障、不意打ちの防止、規範の運用可能性 |
| `justice-seido` | 制度・帰結 | この規範を一般化したら、人々の行動と制度はどう変わるか | 取引の安全、社会的な費用、制度全体の整合 |

5人が全員一致することは普通にある。**分かれることを目標にしない。** 各人が自分の方法で誠実に考えた結果を数える。

## 4. 争点票（親が作る）

`work/gogi/<争点の番号>/issue.json`。合議の質は、この票で決まる。

```
{"id": "g01",
 "question": "問いを1文で（はい・いいえ、または選択肢で答えられる形）",
 "options": {"A": "肯定（〜できる）", "B": "否定（〜できない）", "C": "場合分け（任意）"},
 "facts": ["設例の事実。資料のまま。評価を混ぜない"],
 "fixed": [{"ref": "民法110条", "text": "条文の原文", "from": "verified/…"},
           {"ref": "最判昭和○・○・○民集○巻○号○頁", "holding": "主文の結果", "reasons": "判決が挙げる理由", "decisive_facts": "判断の前提になった事実", "from": "verified/…"}],
 "open": ["開かれた点を1つずつ。例：『正当な理由』に本件の事情が当たるか"],
 "source_view": "資料・教科書がこの点をどう書いているか（あれば。確度の語のまま）",
 "field": "minpo"}
```

- `fixed` には、確認（`verifier`）で found のものだけを入れる。未確認の判例は入れない（入れるなら `status: 未確認` と書き、裁判官はそれを根拠にできない）。
- `question` に結論を誘導する語を入れない（「不当にも」「当然」）。
- 問いが2つあるなら、争点を2つに分ける。

## 5. 第1回（独立）

5人を**同時に**立てる。渡すのは `issue.json` と `LABA` の場所だけ。**ほかの裁判官の意見、親の見立て、資料の結論の予想は渡さない**（先に見た意見に寄るのを防ぐ）。各人は意見書を返事として返し、親が `work/gogi/<id>/r1/<担当>.json` にそのまま保存する。

意見書の形（全員同じ）：

```
{"justice": "bunri", "issue": "g01", "round": 1,
 "vote": "A",
 "conclusion": "結論を1文で",
 "rule": "この争点に当てる規範（自分の言葉で。条文・判例の引用は fixed の ref で示す）",
 "reasons": ["理由を3〜5つ。自分の方法の順に"],
 "application": "事実への当てはめ。どの事実をどう評価したか",
 "relies_on": ["fixed の ref。ここに無いものを根拠にしない"],
 "precedent": "判例との関係：射程内で従う／射程外／判例の結論に反対（理由）／判例なし",
 "crux": "この前提が違えば結論を変える、という点を1つ",
 "weakest": "自分の意見のいちばん弱い所",
 "confidence": "高|中|低"}
```

## 6. 分かれ目の抽出（親）

`python3 LABA/scripts/gogi_tally.py work/gogi/<id> --round 1` で、票の分布と、形の誤り（`relies_on` に `fixed` 以外がある、`vote` が選択肢に無い、など）を見る。次に親が、各人の `crux` と `reasons` を並べ、**結論を分けている前提**を1〜3個に絞って `work/gogi/<id>/crux.md` に書く。

分かれ目の種類（どれに当たるかを書く）：
1. 条文の読み（文言の範囲、文理か趣旨か）
2. 判例の射程（本件は内か外か。決め手の事実はどれか）
3. 事実の評価（同じ規範で、当てはめが違う）
4. 利益の重みづけ（どちらの当事者の利益・どの価値を重く見るか）
5. 司法の役割（解釈で対応するか、立法に委ねるか）
6. 主張立証（誰が何を立証すべきか、立証できない場合の負担）

全員一致なら、第2回は開かず、「全員一致。ただし理由は次のとおり分かれる／同じである」を書いて10に進む。

## 7. 第2回（応答）

票が分かれたときだけ。5人を同時に立て、今度は `r1/` の全員の意見書と `crux.md` を渡す。各人は：

- 反対の立場の、いちばん強い理由に答える（弱い理由だけを選んで叩かない）。
- 票を変えてよい。変えるなら、どの理由で変えたかを書く。**人数に合わせて変えない**（「多数だから」は理由にならない）。
- 自分の意見の種類を選ぶ（8）。

出力は第1回の形に、`"round": 2`、`"changed": true|false`、`"change_reason"`、`"reply"`（反対の立場への応答）、`"type"`（8の種類）を足す。`work/gogi/<id>/r2/<担当>.json` に保存。第3回は開かない（収束を目的にしない）。

## 8. 評決と意見の種類

`gogi_tally.py work/gogi/<id> --round 2 --emit` が、評決（例 3対2）と、ノートに載せるブロックの下書きを出す。

| 種類 | 意味 |
|---|---|
| 多数意見 | 過半数（3人以上）の結論。理由は、多数の中で共通する部分を親がまとめる（個々の裁判官の言葉を勝手に強めない） |
| 補足意見 | 多数の結論と理由に賛成し、言い足す（射程の限定、残された問題） |
| 意見 | 結論は多数と同じ、理由が違う |
| 反対意見 | 結論が違う |

過半数が無い（2対2対1など）ときは、「多数意見は形成されなかった」と書き、立場ごとに並べる。無理に束ねない。

## 9. 法的点検による線引き

評決の前に、`legal-reviewer` に全意見書と `issue.json` を渡し、次だけを見させる（結論の当否は見させない）。

- 条文・判例（確定領域）に反する記述はないか → あれば、その理由を削るよう指摘。削った結果、意見が成り立たなくなるなら、その票は「撤回」として数えない。
- `fixed` に無い判例・学説を事実として書いていないか。
- 判例の内容を、自分の結論に合わせて言い換えていないか（理由のすり替え）。

線引きの問い：**「この記述は、条文か判決文を開けば正誤が決まるか」**。決まるなら確定領域。決まらないなら開かれた領域で、点検者は触らない。

## 10. ノート・レジュメへの載せ方

本文の該当箇所（設例の検討、論点の解説、判例研究の「検討」）のあとに、「合議」の小見出しで置く。順序は固定。

1. **判例の立場**（確認済みのもの。あれば）：判例は〜とする（書誌）。これは事実として書く。
2. **評決**：例「LABA の合議では 3対2 で肯定」。全員一致ならそう書く。
3. **多数意見の要旨**（規範と決め手の理由）、**反対意見の要旨**、あれば補足意見・意見。各2〜4文。誰の意見かは立場の名前（文理・体系の立場、など）で書く。
4. **分かれ目**：「〜と読むなら肯定、〜と読むなら否定」の形で1〜3個。ここがいちばん大事。
5. **答案での使い方**：判例の立場で書くならこう、反対の立場ならこの理由を使う。試験で安全なのはどちらか（判例があるなら判例）。

表示の決まり：
- 見出しの下に必ず「（LABA の5つの立場による検討。裁判所・学者の見解ではない）」と書く。
- 合議の結論を、判例・通説であるかのように書かない。「判例は」「通説は」と書けるのは、確認済みの資料があるときだけ。
- 立場の名前を、実在の裁判官・学者・学説の名前（○○説）に置き換えない。資料が学説名を挙げているときは、資料の記述として別に書く。
- 巻末の論点カードには「分かれ目」の欄だけを写す。短答式の命題は、合議の結論から作らない（条文・判例から作る）。

判例研究では、「検討」の節の骨格に使える：多数意見＝報告者の採る立場の候補、反対意見＝想定される批判。報告者（利用者）の結論は利用者が決める。合議は材料であって、報告者の意見の代わりではない。

## 11. してはいけないこと

- **事実を多数決で決める**（条文の文言、判例の結論、施行日）。確かめれば決まるものは、確認の担当が確かめる。
- 分かれることを指示する（「2人は反対に回れ」）。逆に、まとめることを指示する。
- 第1回で、ほかの意見や親の見立てを見せる。
- 5人の意見を、実在の最高裁判事・学者の見解として示す。
- 合議の結論で、確認済みの判例の記述を書き換える。
- 反対意見を「誤り」として削る（確定領域に反しないかぎり）。

## 12. 担当を立てられないとき（claude.ai のチャット）

1人で5つの立場を順に書くことになる。独立性は弱い（先に書いた意見に引かれる）。次のようにして補い、ノートには「合議（1人で5つの立場を順に検討。独立の担当によるものではない）」と書く。

- 先に `issue.json` に当たる内容（問い・選択肢・確定領域・開かれた点）を書き出す。
- 5つの立場を、結論を書く前に「最初に問うこと」への答えから書く。順番は、自分の最初の直感と**反対になりそうな立場から**書く。
- 全部書いてから、分かれ目を抽出する。評決は載せてよいが、「3対2」の数字より分かれ目を主に書く。
- 第2回は省いてよい。

## 13. ファイル

```
work/gogi/g01/issue.json      争点票（親）
work/gogi/g01/r1/<担当>.json  第1回の意見書（親が返事を保存）
work/gogi/g01/crux.md         分かれ目（親）
work/gogi/g01/screen.md       法的点検の線引き（親が返事を保存）
work/gogi/g01/r2/<担当>.json  第2回
work/gogi/g01/result.json     評決（gogi_tally.py）
work/gogi/g01/blocks.json     ノートに載せるブロックの下書き（gogi_tally.py --emit。親が文を整える）
```

報告には「合議：実施（争点数、各評決）」と書く。開かなかった争点候補があれば、理由を一言書く。
