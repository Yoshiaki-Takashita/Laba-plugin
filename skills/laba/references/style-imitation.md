# 言葉遣いを資料に合わせる

本文は、資料の書き手が書いたように読める文体にする。内容は自分の言葉で書き、言葉遣いだけを合わせる。資料が教科書型のときに使う。レジュメ型（手本になる文章が無い）のときは、末尾の既定値で書く。

## 目次
1. 測る　2. 許容幅　3. 言い回しの型を拾う　4. 書くときの規則　5. 語の置き換えで済ませない　6. 術語は崩さない　7. 丸写しの線引き　8. 二層の体の分け方　9. レジュメ型の既定値　10. 仕上げ

## 1. 測る
`scripts/style_profile.py SOURCE.txt --out profile.json` で次を測る。

| 項目 | 見るもの |
|---|---|
| 文の長さ | 平均・中央値・分布（〜40字／41〜60／61〜80／81〜100／100字超） |
| 段落 | 1段落あたりの文数・字数 |
| 文末 | である／からである／という理由である／ことになる／とされる／と解される／ない／がある／受動／よう（推量）／です・ます／体言止め |
| 文頭の接続語 | また・したがって・もっとも・しかし・そこで・なお・ただし・これに対して・他方・すなわち・たとえば・つまり など、それぞれの頻度 |
| 読点 | 「，」か「、」か |
| 漢字率・カタカナ率、括弧の数 | |
| 使われていない表現 | です・ます、体言止め、箇条書き、文頭の「つまり」、読者への呼びかけ |

数値だけを保存し、資料の文は保存しない。

## 2. 許容幅
`scripts/style_check.py BODY.txt --profile profile.json` が次の幅で見る。

- 平均文長：資料の±15%。中央値：±20%。
- 文長の分布：各区分で資料の±10〜12ポイント。短い文だけ、長い文だけの段落にしない。
- 段落あたりの文数：資料の±40%。
- である調の資料：です・ます率 1%以下、句点のない文 2%以下、である文末は資料の値−10ポイント以上。
- 接続語で始まる文：資料の±10ポイント。
- 読点：資料が「，」なら「，」だけ。
- 漢字率：±5ポイント。
- 資料にほとんど出ない語がノートに3回以上、または資料の3倍を超える頻度で出たら WARN。

数値を合わせることが目的ではない。数値は「浮いていないか」を見る道具で、最後は点検者に読ませる（10節）。

## 3. 言い回しの型を拾う
資料を読み、次の場面の決まった言い回しを作業ファイルに控える（短い型だけ。文は写さない）。

| 場面 | 型の例（資料によって違う。資料のものを使う） |
|---|---|
| 判例を引く | 「判例は，…とする（最判…）。」「…という理由である。」「前掲最判…」 |
| 判例の立場を評する | 「判例はかかる立場を採用しなかった」「特段の理由を付すことなく」 |
| 学説を引く | 「…という見解がある。」「もっとも，この見解に対しては，…という批判がある。」「…が多数説である。」 |
| 例を出す | 「たとえば，XがYに対して…という場合，」 |
| 当てはめる | 「…場合がこれに当たる。」「前者の例であり，…後者の例とされる。」 |
| 理由を述べる | 「…からである。」「…ということである。」 |
| 控えめに自説を出す | 「…と解する余地がある。」「…と解するのが相当である。」 |
| 指示語 | 「かかる」「当該」「前者／後者」「前述のとおり」 |
| 条文の括弧 | 「（41条1項）」を文末の句点の前に置く |

## 4. 書くときの規則
- 資料と同じ体で書く（である調なら、である調）。
- 教科書型の本文には、箇条書きと太字のラベル（「何か」「なぜか」）を使わない。構造を見せる役目は、表と図と見出しに任せる。文中の①②の列挙は使ってよい。
- 段落は、理由（からである）、例（…がこれに当たる）、帰結（ことになる）のどれかで閉じる。
- 対比は1文に畳んでよい（「前者においては…のに対し，後者においては…」）。「一つは…。もう一つは…。」と数を予告して並べる型は、1節に1回まで。
- ノート自身・表・図への言及を、本文の主語にしない。「表4のとおりである。」ではなく、文末の括弧「（表4）」にする。
- 資料の書き手の見解を紹介するときも、資料の体のまま書く。

## 5. 語の置き換えで済ませない
です・ますで書いた下書きを、語を置き換えてである調にすると、浮いた文になる。実際に起きた例：

- 「つまり」を「すなわち」に替えただけ → 「すなわち，…ということである。」が何度も出る。資料では文頭の「すなわち」はまれだった。
- 判例の理由文（「…という理由である。」）の直後に、言い直しの文を足す → 資料は理由で段落を閉じている。
- 「そのため」「まとめて審理」のように、資料に出ない平易な語が残る。

直し方：置き換えた文ごとに、資料の該当頁を開き、同じ働きの文（言い換え、例示、理由づけ）を資料がどう書いているかを見て、その型で書き直す。言い換えの標識（すなわち／ということである／ことを意味する）は1文に1つ、1段落に1つまで。文頭の「すなわち」は、資料の頻度の3倍まで。具体化が要るなら、理由の文の前に「たとえば，…という場合，」で入れる。

## 6. 術語は崩さない
資料の術語と条文の用語は、一致率を下げるためでも言い換えない（「併合審理」を「まとめて審理」にしない）。平易な言い換えは「ざっくり理解」の段だけで使う。

術語の表記は、資料に合わせる。同じ概念に複数の表記があるとき（例：主観的予備的併合／主体的予備的併合、取消訴訟／取消しの訴え）、どちらが正しいかを決めず、資料の表記を使う。資料の表記が少数派だと分かっているときは、初出で「（○○とも表記される）」と添える。資料が無いときは、条文の用語を優先する。

## 7. 丸写しの線引き
- 写してよいもの：術語、条文の文言、判例の書誌、定義文（短いもの）、判旨の「」引用。
- 写さないもの：地の文。資料の難しい文は、そのまま写さずに噛み砕く。
- 測り方：`scripts/match_check.py SOURCE.txt BODY.txt`。生の値（raw）と、書誌・定義・術語を除いた値（filtered）の両方が出る。報告には両方を書く。除いた値だけを書くと、実態より良く見える。
- 目安：除いた値で、20字以上の一致が1万字あたり10か所程度まで、最長30字程度まで、12字一致率10%以下。生の値で最長の一致を5つ見て、定義・条文・書誌以外の文の流用が無いことを確かめる。
- 文体を合わせる作業の途中で、一致は増える（実例では一度3倍になった）。合わせ終えたら必ず測り直す。

## 8. 二層の体の分け方
- 本文：資料の体。
- ざっくり理解：です・ますの平易な説明。段の中はすべて、です・ます。太字の見出しと左の字下げで本文と分ける（色・枠・網掛けは使わない）。
- 表のセル・図のラベル：簡潔な体言止めでよい。
- `style_check.py` は本文だけに掛ける（`build_docx.py --body-out` が本文だけを書き出す）。

利用者が「全部である調で」「全部です・ますで」と言ったら、それに従う。

## 9. レジュメ型の既定値（手本になる文体が無いとき）
- です・ます調。1文は平均40〜50字。100字を超える文は作らない。
- 各項目は「何か（条文と具体例）→なぜか（理由に番号）→ただし（限界・例外）」。
- 太字の小見出し、短い箇条書き（1項目1〜2文）、番号付きの手順を使ってよい。
- 専門用語は初出で一言説明する。
- 読点は「、」。
- `style_check.py` を `--profile` なしで走らせると、この既定値で見る。

## 10. 仕上げ
1. `style_check.py` の WARN を 0 にする。
2. `match_check.py` を走らせ直す。
3. 資料の2頁以上を読んだ別の点検者に、「同じ書き手に見えるか」を5段階で判定させ、浮いている文を引用と書き換え例つきで挙げさせる（`verification.md`）。自分の評価は成果として書かない。
