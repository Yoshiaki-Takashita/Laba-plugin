# 判例をどこに、どう書くか

## 1. 本文か、表か

| № | 条件 | 書く場所 |
|---|---|---|
| 1 | その小節の判例が1〜2件 | 本文で4段（事案の型→結論→理由→射程）。表は作らない |
| 2 | その小節の判例が3件以上で、同じ観点（事案の型・結論・理由）で並べられる | 表。本文は導入の1文と、表では書けない関係（判例どうしの緊張、背景の考え方）だけ |
| 3 | 判例が3件以上だが、判例の変遷（前の判例→後の判例）が主題 | 本文（年代順）。必要なら時間軸の図 |
| 4 | 1件の判例を詳しく検討する（判例評釈型、参考判例） | 見出し（C）＋「事案：／判断：」＋解説の段落 |
| 5 | 資料が判例名を挙げるだけ（内容の説明なし） | 本文の括弧に書誌だけ。内容を補うなら、確認のうえ（補足） |

## 2. 理由の出所の書き方
判例の「理由」には、出所が3つある。区別して書く。

| 出所 | 何か | 書き方 |
|---|---|---|
| 判示 | 判決文に書いてある理由（裁判所の公開する全文で確かめたもの） | 表：「判決が挙げる理由」の列、またはセルの冒頭に［判示］。本文：「…という理由である。」 |
| 資料 | 資料（教科書・レジュメ）が、その判例の理由・背景として説明しているもの | 表：「資料の説明」の列、またはセルの冒頭に［資料］。本文：「…と説明されている」「…という考えが背景にあるものと解される」 |
| 補足 | 作成者が足した説明 | （補足）を付ける |

決定表：

| № | 条件 | 判決の理由の欄 | 資料の説明の欄 |
|---|---|---|---|
| 1 | 判決文を確かめ、理由が書いてある | その理由（判決の語句に沿って） | 資料が別の説明をしていれば、それ |
| 2 | 判決文を確かめ、理由が書いていない（「原審の判断は正当」だけ、など） | 「判決は理由を述べていない」 | 資料の説明 |
| 3 | 判決文を確かめていない（大審院、下級審、サイト停止、時間の制約） | 「判決文は確認していない」 | 資料の説明 |
| 4 | 資料が「特段の理由を付さずに」と書いている | 「判決は理由を述べていない」（確かめたなら）／「資料によれば、理由は付されていない」 | — の代わりに「資料に説明なし」 |

- 空欄・「—」にしない。
- 列名を「判例が挙げる理由」と一つにまとめない（資料の説明まで判例のものに見える）。
- 資料が「主たる理由」「補強的な理由」と順序を付けているとき、その順序づけが判決文にあるかを確かめる。無ければ、順序づけは資料の説明の欄に書く。
- `scripts/reason_source_check.py` が、列名・空欄・理由を述べていない判決に付いた理由文を見る。

## 3. 疑似コード
```
def place_case(section):
    n = len(section.cases)
    if section.is_single_case_study: return "見出し＋事案／判断"
    if n <= 2: return "本文4段"
    if section.theme_is_development: return "本文（年代順）"
    return "表＋導入1文"

def reason_cells(case):
    if not case.fulltext_checked: return ("判決文は確認していない", case.source_explanation)
    if case.court_gives_reason:   return (case.court_reason, case.source_explanation_if_different)
    return ("判決は理由を述べていない", case.source_explanation)
```
