# 図の型の選択

## 入力

一覧化の段階で書き出した「文章だけでは分かりにくい点」（難所）。それぞれについて、何が分かりにくいのか（性質）を一言で書き、メッセージを一文で書く。メッセージが書けない難所には、図を当てない。

## 手順

1. 難所ごとに、下の決定表を上から順に当てる。最初に当たった行の型を使う。
2. 「図にしない場合」に当たるなら、表・文・「ざっくり理解」で手当てする（`table-or-prose.md`、`zakkuri-placement.md`）。
3. 型が決まったら、`../figures/02-types/` の該当ファイルを読み、用例の仕様を写す。
4. 章全体で、枚数と配分（後述）を確かめる。

A を先に当てるのは、難所を解く図が A に多いからである。当事者を並べたくなったら、まず A のどれかで同じ難所を解けないかを考える。

## 表の形を後回しにする（単調さを避ける）

比較図（`compare`）・判例マトリクス（`matrix`）・座標図の各欄に文を詰めた図は、罫線の表と見分けがつかなくなりやすい。章の図が表の形ばかりになると、読み手は「どこから読むか」を図から受け取れない。次の順で、表の形より先に、関係・流れ・包含・時間の型を当てる。

| 難所の中に、これがあるなら | 表の形（比較図・マトリクス）より先に当てる型 | 例 |
|---|---|---|
| 誰が誰に、何を主張・請求できるか（相手が場面ごとに変わる） | 当事者関係図・動きの図（主張できる相手に矢印、できない相手に止め線） | 留置権は物権なので第三者にも主張できるが、同時履行の抗弁権は契約の効力なので、契約の相手方（と債権の譲受人などの承継人）に対して主張する → 当事者関係図 |
| 答えを順に出していく（「まず…、次に…」） | 流れ図・決定木 | 三類型の要件を並べた比較図 → 類型に行き着く問いの順の流れ図 |
| 広い概念と狭い概念、原則と例外 | 包含図・条文の構造図・流れ図の段の中の小枝（`branch`） | 既判力の客観的範囲（主文）と例外（相殺の判断） → 条文の構造図か小枝 |
| 時点・基準時・期間 | 時間軸・数直線 | 既判力の基準時の前後で、主張できる事由が分かれる → 時間軸 |
| 二つの観点の組合せ | 座標図（欄の文は一行。規律は欄の下の二行目に） | — |

それでも比較図にするとき（場面ごとの帰結を同じ段で見比べることが難所そのもののとき）は、次の三つで階層を付ける。色は増やさない。

- **形**：列の見出しの下に太い線（見出しの帯。既定）。結論の段は下辺を太く（`under`）。例外は箱の下の点線の区切りの下に（セルの `except`）。
- **太さ**：違いが出る段だけを強調（`accent`）。ほかの段は細い枠のまま。強調は図に一か所（三列でも一つの段）。
- **間隔**：段の間の矢印（推論の順）と、矢印のない狭い間隔（観点の並び）を使い分ける（`arrows:false`、`rows[].arrow:false`）。

章の図が三つ以上あるとき、表の形（比較図・マトリクス・座標図）は半分まで。それを超えたら、一枚を上の表の型に描き直す。

```
def figure_type(h):                       # h = 難所
    if not h.message_in_one_sentence: return None
    # A 理由を見せる
    if h.same_frame_one_fact_differs:                return "複合図"
    if h.burden_of_proof_differs_by_party:           return "主張立証責任の分配の図"
    if h.similar_cases_diverge and h.who_against_whom: return "動きの図"        # 表の形より先に：相手が変わるなら関係の型
    if h.similar_cases_diverge and h.ordered_questions: return "流れ図"
    if h.similar_cases_diverge:                      return "比較図" if h.n_cases <= 3 else "表"
    if h.staged_gates_with_common_exit:              return "流れ図" if h.n_steps > 3 or h.has_exit else "文"
    if h.questions_branch_to_3plus_results:          return "決定木" if h.depth <= 4 else "分ける"
    if h.claim_defense_reply:                        return "積み上げ図" if h.n_defense_lines <= 2 else "表"
    if h.timing_decides:                             return "時間軸" if h.n_events >= 3 else "文"
    if h.reaches_some_not_others:                    return "動きの図" if h.n_items >= 2 else "文"
    if h.two_axes:                                   return "座標図" if h.n_axes == 2 else "表"
    # B 構造
    if h.requirements_support_effect:                return "要件効果の木" if h.n_req >= 3 else "文"
    if h.proviso_or_items_in_one_article:            return "条文の構造図"
    if h.lengths_or_ranges:                          return "数直線"
    if h.shared_value:                               return "価値配分の図"
    if h.procedure and h.n_actors >= 2:              return "手続のスイムレーン"
    if h.organs:                                     return "組織図"
    if h.concept_contains_concept:                   return "包含図" if h.depth <= 3 else "表"
    # C 判例・学説
    if h.n_precedents >= 5 and h.varies_by_party_and_claim:
                                                     return "判例マトリクス" if h.n_precedents <= 12 else "表"
    if h.one_case_through_instances:                 return "審級の流れ"
    if h.precedent_shift and h.shift_is_verified:    return "判例の変遷の図"
    if h.doctrines_diverge and h.content_in_source:  return "学説の対立地図" if h.n_doctrines <= 3 else "表"
    # D 事案
    if h.two_transferees_from_one:                   return "対抗関係の図"
    if h.rights_pass_along:                          return "権利移転の連鎖"
    if h.relations_accumulate and h.for_slides:      return "時系列の積み上げ図"

    if h.n_parties >= 3 and h.n_relations >= 2:      return "当事者関係図"
    return None
```

## メッセージの形から選ぶ

型に迷ったら、メッセージの一文の形で決める。

| メッセージの形 | 型 |
|---|---|
| 「A のときは X、B のときは Y」 | 比較図。枠ごと比べるなら複合図 |
| 「P は、Q・R・S がそろって成立する」 | 要件効果の木 |
| 「まず P、次に Q を問い、外れると Z になる」 | 流れ図 |
| 「P か否か、Q か否かで、四つに分かれる」 | 決定木・座標図 |
| 「P の時点で Q であれば R」 | 時間軸 |
| 「X が P を、Y が Q を、X が R を主張立証する」 | 積み上げ図 |
| 「P は及ぶが、Q は及ばない」 | 動きの図 |
| 「P は原則 X、ただし Q のときは Y」 | 条文の構造図 |
| 「P と Q のどちらか早い方」 | 数直線 |
| 「X が先に備えた方が優先する」 | 対抗関係の図 |
| 「〜について」「〜の関係」 | まだメッセージになっていない。書き直す |

## 枚数と配分

- 一つの章（講義一回分）で三つか四つ。資料二十頁なら四つから六つ、十頁以下なら二つから四つ。
- A の型（理由を見せる）を、章に一つ以上。
- D の型（事案を見せる）は、一つのノートに二枚まで。
- 同じ型は二枚まで。三枚目が要るなら、複合図にまとめられないかを考える。
- 図が三つ以上なら、型は二種類以上。
- 難所三つに図を当てたら、残りは表か「ざっくり理解」で手当てする。

## 図にする前の確認

1. その図の「分かること」を一文で言えるか。言えないなら描かない。
2. 図の要素（箱・矢印・ラベル）の全部に、本文の根拠があるか（`../figures/06-traceability.md`）。根拠は、点検役の読み上げの表（`../reviewer-prompts/figure-check.md`）で確かめる。`trace.py` の所見なしは根拠にならない。
2'. 型を選ぶときに、その型で機械が見ない誤りを知っておく（要件と効果＝流れ図・木、範囲の枠の中と外＝当事者関係図、小枝の帰属＝流れ図、兄弟の枝＝木、帯の前後＝時間軸、すり替え＝包含図）。その型を選んだら、読み上げの表でその行を必ず立てる。
2''. 右向きの流れ図（`direction:"right"`）でも、段の中の小枝（`branch`）と段ごとの通過の語（`steps[].pass`）は描かれる（第5回で直した）。ただし箱が狭いので、小枝の語は短く（一つの段に二つまで。三つ目は warn を出して描かない）。小枝が長いときは下向きにする。
3. 条文番号・期間・判例の書誌を、原文で確かめたか。
4. 本文に留保（余地がある、不明確）があるなら、注に一文で入るか。
5. その分野でよく図にする論点か（`../figures/08-field-gallery.md`）。

## 選び間違いの例

- 類型を並べただけの図（軸がない）→ 表で足りる。軸があるなら座標図にし、各欄に規律を一行入れる。
- 当事者関係図に「両立しない」とだけ書く → 何が分かれ目かが見えない。主張立証責任の分配の図にして、相手ごとの証明責任を並べる。
- 判例を枠に入れて矢印でつなぐ → 矢印の意味（変更、区別、射程）が曖昧になる。マトリクスか、確かめたうえで判例の変遷の図にする。
- 成立する場合の時間軸だけ → 何が決め手かが見えない。成立しない場合を並べて複合図にする。
- 三つの類型の一覧表のような比較図 → 類型に行き着く手順が見えない。問いを順に当てる流れ図にする。
- 訴訟要件を請求原因の積み上げに入れる → 訴訟要件は流れ図、請求原因は積み上げ図。
- 要件の木に矢じりを付ける → 「支える」関係は矢じりなし。進行は流れ図。

ほかの失敗は `../figures/09-anti-patterns.md`。
