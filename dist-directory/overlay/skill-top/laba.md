## 公式版（道具なし）での進め方

この手順書は、フル版ではスクリプト（`${CLAUDE_PLUGIN_ROOT}/skills/laba/scripts/`）を走らせる前提で書いてある。**最初に** `${CLAUDE_PLUGIN_ROOT}/skills/laba/scripts/pipeline.py` があるかを確かめる。あれば（フル版）この節は飛ばす。**無ければ（公式版）**、本文の「走らせる」「`python3 …`」「`node …`」「`scripts/…`」の行は実行せず、次の手作業の道に読み替える。規則（網羅・足した説明は「（補足）」・確かめていない判例は「未確認」・自己採点を成果にしない）は変わらない。

1. **読む・一覧にする（①②③）**：資料を全頁読み、見出し・判例・条文・相互参照・問い・難所の一覧を、作業用の表として自分で作る（`references/workflow.md` ①②、`checklists/01-intake.md`・`02-inventory.md`）。文体は `references/style-imitation.md` 1〜3 の項目（文末の体・一文の長さ・読点・言い回しの型）を、資料から数例ずつ拾って控える。数値は概数であり、機械で測っていないと報告に書く。
2. **本文・図・設例・巻末（④〜⑧）**：`references/` の規則どおりに書く。図は `skills/laba-figures/SKILL.md` の手作業の道、判例研究は `skills/laba-hanrei/SKILL.md`、スライドは `skills/laba-slides/SKILL.md` の手作業の道に従う。条文・判例の確認は、コネクタがあればそれ、なければ e-Gov と裁判所サイトの頁を読む（`statute-verification.md`・`case-verification.md`）。判例検索の道具（`case_lookup.py`）は無いので、裁判所サイトの検索頁と詳細頁を直接読み、判決全文は PDF を開けるときだけ読む。読めなかった判例は「未確認」とし、判旨を書かない。
3. **Word にする（⑨）**：環境に python-docx があれば、その場で短いコードを書いて .docx を作る。体裁は `references/docx-format.md` の 1〜3（A4・余白・游明朝 10.5pt・見出し・表は横罫 3 本・図は幅 150mm 以内・フッターに頁番号・黒だけ・囲みや網掛けなし）と、ブロックの種別（5）をそのまま使う。コードは作業用で、渡さなくてよい。python-docx が無く、入れられないときは、Word が作れないと伝え、同じ体裁で書いた Markdown を渡す。
4. **数える・検査する（⑨）**：機械の検査（22本）は走らない。数える必要があるもの（字数、資料との同文の続き、判例・条文の出現数、図表の数）は、その場で標準ライブラリだけの短い Python を書いて数える。数えられない環境では、数値を書かず「未測定」と書く。段階ごとの確認表 `references/checklists/` の 03〜07 と `references/failure-catalog.md` を、本文を 1 節ずつ見ながら実際にたどる。
5. **独立点検・採点（⑩⑪）**：担当（`agents/`）を立てられる環境（Cowork・Claude Code）では、本文を書いていない点検者に `references/reviewer-prompts/` の指示文で見させる。立てられないときは、自分が書いた者でない目で同じ指示文の項目を順に確かめ、「独立点検ではなく自己点検」と書く。点は、独立採点・機械測定・自己採点を分けて報告し、機械測定は「未測定（公式版）」と書く。**スコアボードの数値は、フル版で測った値で、公式版の成果物には当てはまらない。**
6. **渡す（⑫）**：`references/delivery.md` の型で。走らせなかった検査（機械の検査全部）とその理由（道具が入っていない版）を、報告に必ず書く。分からないことは「不明」と書く。

担当（`agents/`）の指示にある「スクリプトを走らせる」も、同じく手作業の道に読み替える（走らせられなかったと報告する）。
