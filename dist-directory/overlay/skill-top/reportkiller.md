## 公式版（道具なし）での進め方

**最初に** `${CLAUDE_PLUGIN_ROOT}/skills/reportkiller/scripts/prose_check.js` があるかを確かめる。あれば（フル版）この節は飛ばす。**無ければ（公式版）**、下の「2. 機械の点検」の `node …`・`python3 …` と、建築の図の `scripts/archstudio/` は使えない。次のとおりにする。規則（読んでいないものは書かない・引用台帳・レベル・文体と図の規則）は変わらない。

1. **台帳**：1 文献 1 行の表を自分で作る（`references/citation-ledger.md` の形式。V0〜V3）。`ledger_check.js` の代わりに、仕上げの前に本文と台帳を見比べて確かめる：V0 を本文で使っていないか／ID の重複がないか／本文の ID がすべて台帳にあるか／「」の引用と頁が V3 の文献だけか／同じ ID に別の頁が付いていないか。
2. **文体・構成の点検**（`prose_check.js`・`report_check.js` の代わり）：`references/verification.md` の 1〜6（引用の再照合・数値の再計算・別の目による査読・文体・使ってはいけない使い方・最終チェック）と、言語に合う規則（`prose-ja.md`・`prose-ja-law.md`・`prose-en.md`）、段の数値（`levels.md`）を、本文を段落ごとに見ながら実際にたどる。数える必要があるもの（字数、文の長さの分布、数え上げの語の回数）は、環境に Python があれば短いコードで数える。数えられないときは数値を書かず「未測定」と書く。本文を見ていない別の担当（`agents/` を立てられる環境）に査読させるか、立てられないときは「自己査読」と書く。
3. **Word**：環境に python-docx があれば、その場でコードを書いて .docx を作る。体裁は `references/word-format.md`（A4・黒一色・囲みなし・フッターに頁番号・表は横罫 3 本）。python-docx が無く、入れられないときは、Word が作れないと伝え、同じ体裁の Markdown を渡す。
4. **図**（`fig_check.py` の代わり）：`references/figures.md` に従い、SVG を直接書く（色は #943522 を 1 つだけ足す、角丸・影・グラデーションなし、ラベルは図だけで意味が取れる語、矢印は省かない、図題は完全な文）。完成後、同じ文書の 10（自己点検）の項目を 1 つずつ当てる。PNG は SVG を PNG にできる道具が環境にあるときだけ。
5. **建築の作品研究・建築図**：図の作成・点検の道具（`archstudio`）は無い。作品研究・ポートフォリオの中身の規則（`arch-portfolio.md`・`arch-masters.md`・`arch-masters-data/`・`arch-creative.md`）はそのまま使う。図は `references/arch-figures.md` の「守ること」に従って、Claude が配置図・平面のダイアグラムなどの SVG を手で書く。**寸法・縮尺の精密さはフル版に劣る**ので、図の中と報告に「資料／推定／創作」の 3 層の見分けを必ず付け、縮尺つきの正確な図面とは呼ばない。
6. 報告には、走らせなかった検査（機械の点検の全部。道具が入っていない版）と、分からないこと（不明）を書く。
